## 2. 你在华为具体做什么？

> 我在华为做的是面向数据通信产品黑盒测试的 AI 测试 Agent。它根据测试用例、接口定义和业务规则生成测试脚本，再结合执行结果处理失败用例。我参与的重点包括脚本生成、业务动作封装，以及 Skill 和多阶段 Workflow 的优化，主要解决复杂任务中上下文难组织、接口参数复杂、失败后难定位的问题。

**追问“你本人做了哪些工作”时展开：**

- 从已有测试脚本中整理接口调用和参数使用方式，把重复的底层调用封装成业务动作，方便生成和维护脚本。
- 优化 Agent 的指令和上下文，把复杂测试任务拆成几步，让每一步拿到对应资料、产出明确结果。
- 利用历史执行失败信息，帮助 Agent 调整脚本并围绕失败点复测。

### 面试官让你举个例子

> 一个比较典型的问题是，底层接口参数多，如果让模型每次从头理解并填写，容易出现参数遗漏或搭配错误。我做的一个方向是从历史脚本中提炼稳定的业务动作，把固定参数放进封装内部，外面只保留必要输入。这样 Agent 生成脚本时更接近描述“做什么业务动作”，也更方便后续维护。

这里用“参数复杂 → 业务封装 → 简化生成与维护”讲清一个问题就够了。

## 3. 有没有业务上落地的成果？

> 我的工作直接服务测试自动化，具体产出是测试脚本生成、业务动作封装，以及失败用例定点复测这些能力。比如把重复且参数复杂的接口调用整理为可复用动作，脚本就更容易生成和维护；执行失败后，再利用失败信息调整和复测。它的业务价值主要是减少重复编写和排查脚本的工作，让测试人员更集中地处理复杂场景。

如果追问“怎么衡量价值”，接着说：

> 我会看脚本执行成功率、需要人工修改的比例、单个用例的处理时间，以及失败定位和复测需要的时间。除了看生成速度，还要看脚本能不能执行、结果能不能满足测试目标。

## 4. 实习中最大的技术难点是什么？

> 我感受比较深的是，模型生成一段看起来合理的脚本，并不代表它理解了接口约束和业务顺序。我的处理思路是把问题拆开：通过业务动作封装减少参数复杂度，通过 Workflow 明确步骤，再把执行错误反馈给 Agent，帮助它定位和调整。相比一次塞入大量上下文，这样更容易发现问题出在哪个环节。

**可继续解释：** 参数问题用输入校验和动作封装解决；步骤问题用任务拆分解决；执行失败用错误分类和定点复测解决。不同问题用不同办法，避免只修改提示词。

## 5. 实习期间是怎么使用 AI 的？

> 我在华为的工作本身就是开发 AI 测试 Agent，把模型用在理解测试任务、生成脚本和根据执行反馈调整脚本这些环节。我的体会是，要先把任务目标、工具说明和输入资料组织好，再通过实际执行判断结果。涉及接口参数和业务规则时，程序校验与工具返回的信息很重要。

如果问的是“你怎样用 AI 辅助自己写代码”：

> 我会让 AI 帮忙理解已有代码、起草重复逻辑和分析报错，再自己检查关键逻辑，并通过运行结果验证。用 AI 提效的前提，是我能解释它生成的代码，也知道应该怎样判断它是否正确。

### 如果追问 TTS 的一个技术点

> 长文本分段生成后，每段音频的响度可能不一致。我参与的处理方法是用 RMS 衡量片段能量，根据参考或历史音频确定目标响度，再对后续片段做归一化，同时对静音做保护。音调方面可以提取基频，比较片段间的统计特征；语速可以结合字级时间戳分析。

## 7. 介绍一个最能体现 AI 应用开发能力的项目

> 我会介绍 Agentic RAG，它是一个论文知识库问答系统。用户导入论文后，系统会解析、分块和建立索引；提问时通过 BM25 和向量检索召回内容，再重排并生成带原文引用的回答。我主要关注检索链路、证据组织和效果评测，希望用户拿到答案后还能回到论文核对。这个经验也可以迁移到银行的内部制度和业务知识问答。

**30 秒内的结构：用户问题 → 检索和生成 → 自己做的重点 → 为什么有用。**

## 8. Deep Research 是做什么的？

> Deep Research 是一个多 Agent 深度研究系统。它先明确研究范围，再把问题拆成任务，由研究、复核和报告等角色协作完成。我重点做了任务状态管理、结果检查和中断恢复，让长任务执行过程中可以知道做到哪一步、哪些结果还需要补充，以及中断后怎么继续。

被问“为什么需要多 Agent”时：

> 多 Agent 适合子问题相对独立、可以并行研究，或者需要不同角色分工的任务。我让研究和复核分开，便于从不同角度检查结果；统筹角色通过任务看板管理进度，避免各个 Agent 各做各的。简单任务直接用单 Agent 或 Workflow 更合适。

## 9. Forge 是做什么的？

> Forge 是一个终端 Coding Agent，可以读取和修改代码、搜索文件、执行命令，并保存会话。我关注的是 Agent 连续工作时的工程问题，比如会话状态、上下文管理、任务跟进和子 Agent 协作。模型与工具之间的循环用 LangChain 实现，项目再围绕它补充工具、会话和交互能力。

三个项目的区别：**RAG 解决“怎么找到并引用知识”，Deep Research 解决“复杂研究怎么分工”，Forge 解决“编码任务怎么连续执行”。**
