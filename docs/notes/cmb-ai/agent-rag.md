# Agent、RAG 与数据集

这一章优先练第 1～7 题。第 8～12 题作为追问展开。

<a id="agent"></a>

## 1. Agent 和普通大模型问答有什么区别？

> 普通问答主要是根据输入生成回答；Agent 还会围绕目标决定下一步、调用工具，再根据结果继续行动。比如测试 Agent 会读测试用例、生成脚本、调用执行工具，再根据报错调整。工程上需要把模型、工具、状态和停止条件接起来，形成“判断、执行、反馈”的循环。

**一次工具调用怎么走：**

1. 开发者提供工具名称、用途和参数结构。
2. 模型返回工具名和结构化参数。
3. 程序校验参数与权限，执行对应函数。
4. 工具结果回到模型，模型继续调用工具或给出最终回答。

模型提出调用，应用程序实际执行。

<a id="methods"></a>

## 2. 你提到 Agent 技术，有哪些具体实现方法？

> 常见的实现方式有固定 Workflow、ReAct 式工具循环、先规划再执行，以及多 Agent 分工。流程明确时，用 Workflow 管理步骤；需要根据中间结果决定下一步时，用工具循环；任务较长时可以先拆计划；子任务比较独立时再考虑多 Agent。我在华为的测试任务中更重视工作流拆分，在 Deep Research 中则使用多角色协作。

| 方法 | 怎样执行 | 适合什么任务 |
| --- | --- | --- |
| 固定 Workflow | 代码规定步骤和分支，模型负责其中的理解与生成 | 测试、材料处理、流程明确的业务任务 |
| ReAct / 工具循环 | 模型根据已有信息选择工具，观察结果后继续 | 检索探索、报错排查、工具选择依赖上下文的任务 |
| Plan-and-Execute | 先列子任务，再逐项执行，必要时调整计划 | 长报告、多步骤研究 |
| 多 Agent | 不同角色或子任务分别执行，再汇总结果 | 可并行研究、研究与复核分工 |

它们可以组合。外层 Workflow 控制任务阶段，某个阶段内部运行 Agent，是很常见的方式。

### LangChain、LangGraph 分别做什么？

> LangChain 提供模型、工具、消息和 Agent 等组件；LangGraph 更适合管理带状态的流程，通过节点、分支和循环组织执行。我用它把路由、查询规划、检索和答案聚合接起来，也用它支持研究任务中的状态保存与恢复。

## 3. Workflow、Agent、Skill 有什么区别？

> Workflow 管理流程怎么走，Agent 根据当前情况决定下一步，Skill 则把一类任务的方法、约定和参考材料整理成可复用能力。比如测试场景中，Workflow 规定先理解用例、再生成和执行；Agent 选择所需工具；Skill 提供这一类测试的规则和示例。

如果问“Skill 和提示词的区别”：

> 提示词通常是一段直接给模型的指令；Skill 可以把任务步骤、示例、参考文档和脚本放在一起，按任务需要加载，更方便复用和维护。具体组织方式取决于应用使用的框架。

## 4. 怎么让 Agent 稳定一点？

> 我会从任务、工具和执行三方面处理。任务要拆清楚，每一步有明确输入和输出；工具要说明用途并校验参数；执行要设置超时、重试和调用次数限制，保存状态，并把错误信息反馈回来。像转账、数据修改这类动作，还需要在执行入口控制权限和确认。

结合自己的经历补一句：

> 华为的测试 Agent 主要通过业务动作封装、分阶段 Workflow 和失败反馈减少执行问题；Deep Research 则通过任务看板和 checkpoint 管理长任务。

**如果追问失败重试：** 网络超时可以有限重试，参数错误应先修正参数，权限不足要停止。带外部写入的操作重试前要检查是否已经完成，避免重复执行。

<a id="rag"></a>

## 5. 你的 RAG 项目怎么做？

> 我的项目是论文知识库问答。离线阶段把 PDF 解析成文本和结构，分块后建立向量和关键词索引；在线阶段先理解问题，再用 BM25 和 FAISS 混合召回，经过 FlashRank 重排和上下文整理，交给模型生成答案。答案会带论文位置和原文引用，方便用户回查。

记住两条流程：

```text
导入：PDF → 解析与分块 → embedding / BM25 → 索引
问答：问题 → 路由与改写 → 混合召回 → 去重与重排 → 整理上下文 → 带引用回答
```

### 为什么同时用 BM25 和向量检索？

> BM25 擅长匹配术语、缩写和具体名称；向量检索擅长处理语义相近但表达不同的问题。论文里既有专业词，也有自然语言解释，两种方式结合能互相补充，再由重排模型判断哪些候选更适合回答当前问题。

### 重排和召回有什么区别？

> 召回先从大量文档里找出一批候选，重点是尽量找到相关内容；重排再对问题和候选逐一做更细的相关性判断，重点是把最有用的证据放到前面。重排通常更慢，所以放在候选集上做。

### 为什么要分块？怎么分？

> 整篇论文直接送给模型，成本高，也容易混入无关信息。分块让检索能定位到具体内容。我会尽量保留标题、章节和段落结构，较长内容再按长度拆分，并保留必要重叠和页码等信息。块太小容易丢条件，太大又容易引入噪声，需要结合检索和回答结果调整。

## 6. 数据集怎么做？

### 从你的 RAG 项目回答

> 我的 RAG 项目使用 KITE AI Papers 的固定 15 个问题和 134 篇论文做对比评测。问题和语料固定后，用四条检索 Pipeline 运行并记录答案、证据、评分、耗时和上下文 token，再逐题比较差异。这样修改检索方案时，就能看出哪些问题变好、哪些问题退步。

### 如果追问：让你从头做银行知识问答评测集呢？

> 我会先从业务人员常见问题中抽样，覆盖概念解释、办理条件、材料清单、多条件判断和无法回答的问题。每题整理参考答案、对应制度条款和关键条件，由熟悉业务的人审核，再把开发集和独立测试集分开。制度更新后也要更新题目和答案版本。

具体做法记五步：

1. **确定业务范围。** 比如先做某类内部制度或某条业务线，定义谁来用、什么算答对。
2. **收集真实问题。** 覆盖常见问法、同义改写、跨文档问题和边界问题，控制重复题。
3. **补齐标准。** 记录答案要点、原文依据、适用条件和文档版本。
4. **组织审核和划分。** 业务人员检查答案；按文档、主题或时间隔离近似样本，减少数据泄漏。
5. **持续补充难例。** 把漏检、引用错误、过期答案和应拒答却回答的情况加入回归集。

### 如果问的是训练数据，而非评测数据

> 我在衔远参与过营销场景的训练数据构造和模型调优。训练集的准备重点是任务定义、样本来源、清洗去重、格式统一和质量检查；SFT 数据可以组织成指令、输入与目标回答，多轮任务保留对话结构。评测数据要独立保留，便于判断模型对新问题的效果。

通用流程：**任务定义 → 合规取数 → 清洗去重与脱敏 → 标注 → 抽样质检 → 数据划分 → 训练与评测。** 模型可以辅助生成样本，审核要重点看事实、任务相关性和重复性。

## 7. 怎么评估 RAG？你的实验有什么结果？

> 我把检索和回答分开看。检索侧看相关证据是否被找回、排序是否靠前；回答侧看内容是否正确完整、引用是否支持结论，同时记录耗时和 token。我的固定题集实验中，加入重排的 B1 平均评分约为 6.0，高于基础方案 B0 的约 4.27。后续两个方案平均分略高，但部分题目退步更多，所以最终保留 B1 作为默认方案。

| 指标 | 一句话解释 |
| --- | --- |
| Recall@K | 前 K 个结果找回了多少应找回的证据 |
| MRR | 第一个相关结果出现得有多靠前 |
| nDCG | 多个结果的相关程度和排序是否合理 |
| 回答正确性、完整性 | 回答有没有说对、关键条件有没有漏 |
| 引用支持度 | 引用原文是否真的支持回答中的结论 |
| 延迟与 token | 用户要等多久、每次请求消耗多少资源 |

**追问“为什么不直接选平均分最高的”：**

> 我会一起看逐题表现。有的方案平均分提高，是少数题进步较多，但原来能回答好的问题退步了。默认方案需要兼顾整体收益、退步情况和成本，所以我设置了候选标准，再决定是否替换。

## 8. Agentic RAG 比普通 RAG 多了什么？

> 普通 RAG 往往按固定步骤检索一次再回答。Agentic RAG 会根据问题和已有证据决定是否拆分问题、改写查询或继续检索。在我的项目中，外层用 LangGraph 管理路由和查询规划；检索 Agent 接入工具来获得证据。多工具探索可以组合语料浏览、精确搜索、语义搜索和原文读取，默认流程使用混合检索。

如果问“为什么不让模型一直查到满意为止”：

> 需要设定停止条件，例如证据覆盖了问题、剩余预算不足，或者继续检索已经没有新信息。否则容易重复检索、延迟增加，甚至让无关内容挤占上下文。

## 9. 怎么减少幻觉？

> 我会先提高检索和资料质量，让模型拿到与问题相关、版本正确的内容；再要求答案围绕证据组织，并给出原文引用。资料不足时说明缺少什么，必要时交给人工。同时用评测集持续检查，区分是没有检索到、证据排得太后，还是模型拿到证据后理解错了。

三种常见错误对应三种处理：

- **没检索到：** 检查解析、分块、关键词和语义召回，必要时改写查询。
- **找到了但没用好：** 检查重排和上下文打包，把关键条件保留下来。
- **引用与答案不一致：** 核对结论与原文，增加回答与引用的评测。

## 10. RAG 和微调怎么选？

> 业务知识经常更新、回答需要来源时，优先考虑 RAG；需要模型适应某种输出格式、表达方式或稳定任务行为时，可以考虑微调。银行制度问答适合用 RAG 接入最新资料；如果还需要统一术语和固定输出结构，再结合提示词或微调。两者可以一起使用。

## 11. 你做的是模型训练还是应用开发？

> 我目前重点做 AI 应用开发，包括知识接入、Agent 工具、工作流、后端接口和评测。早期实习接触过数据构造、模型调优和 vLLM 部署，所以理解模型侧的基本流程；现在更希望把模型能力组织成业务人员能使用的系统。

## 12. 大模型基础快问

| 问题 | 20 秒回答的核心 |
| --- | --- |
| embedding 是什么？ | 把文本转换为向量，让语义相关的内容在向量空间中更接近，用于检索和匹配。 |
| Transformer 为什么用 Attention？ | 让当前位置结合上下文中相关的信息。基本计算是 Q、K 算相关权重，再对 V 加权。 |
| temperature 做什么？ | 调整采样分布，较低通常更集中，较高更多样；它不直接代表答案准确率。 |
| SFT 是什么？ | 用任务输入和目标输出继续训练，让模型学习特定任务的回答行为。 |
| LoRA 是什么？ | 冻结主要模型参数，训练额外的低秩参数，降低需要更新的参数量和训练资源需求。 |
| vLLM 做什么？ | 用于大模型推理服务，通过 KV cache 管理、连续批处理等机制提高服务效率。 |

工具与检索流程可对照 [LangChain 官方 RAG 文档](https://docs.langchain.com/oss/python/langchain/rag)。更深入的问题留到 [RAG 项目讲解](../project-defense/agentic-rag-guide.md)继续复习。
