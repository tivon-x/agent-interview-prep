# 字节跳动数据平台 Agent 开发工程师面试题解析与参考回答

对应题库：`BYTE_AGENT_INTERVIEW_QUESTION_BANK.md`，覆盖 Q001 至 Q360。项目事实以当前简历事实源、项目代码、指南和冻结评测产物为准。标注“设计题口径”或“知识题口径”的内容不能说成个人线上经验。

## 使用说明

- 先闭卷回答，再看“参考回答”。项目题补充代码入口、失败样例和事实边界。
- 30 秒题用“结论，两个依据，一个边界”；90 秒题用“目标，链路，取舍，失败处理，证据”；系统设计题用“澄清约束，画最小链路，说明状态与权限，再谈扩展”。困难题和系统设计题的参考回答是 90 秒主干，`知识点` 中最相关的 2 至 4 项就是追问时的展开方向。
- 简历项目回答只认当前实现和已有产物。冻结实验不代表线上准确率，测试代码不代表生产验证，路径限制不等于操作系统沙箱。

## 30 秒答题模板

先用一句话下结论，再给两个关键机制或取舍，最后补一句适用边界。基础题无需把所有名词都讲完，等面试官追问。

## 90 秒答题模板

先说明问题和目标，再按输入、决策、执行、校验、状态五步讲链路。随后说一个关键取舍和一个失败场景，最后落到自己的实现证据或明确说“这是设计题口径”。

## 系统设计答题模板

先确认用户、租户、读写副作用、规模、延迟、准确性和合规要求。然后画入口、编排、模型、工具、数据、状态、观测七层最小链路，重点讲权限前置、幂等恢复、版本回放和降级，最后给演进顺序。

## A. 自我介绍、动机与经历边界

### Q001 请做 90 秒自我介绍，为什么目标是数据平台 Agent 工程而不是纯模型训练？
- **考察点**：能否把经历收束成岗位需要的工程主线，并守住能力边界。
- **知识点**：Agent 工程；RAG；Workflow；评测；后端可靠性。
- **复习巩固**：闭卷串联华为测试 Agent、Agentic RAG、Deep Research 和 Forge，各用一句“问题、动作、证据”。
- **参考回答（90 秒）**：我的定位是 AI 应用和 Agent 工程，重点是把模型接进可验证、可恢复的后端链路。华为实习让我接触测试 Agent 的 Skill、Workflow、失败反馈和业务动作抽象；Agentic RAG 覆盖检索、证据和冻结评测；Deep Research 处理多 Agent 调度、证据门禁和 checkpoint；Forge 关注 Harness、工具边界和会话持久化。这些经历与数据平台 Agent 的编排、RAG、工具接入和稳定性直接对应。我了解训练基础，但没有把自己定位成预训练或强化学习研究者。

### Q002 为什么想做平台而不只做一个垂类 Agent？平台抽象的最小边界是什么？
- **考察点**：是否理解平台化来自重复问题，而非堆通用组件。
- **知识点**：Runtime；Tool Registry；状态协议；权限；观测。
- **复习巩固**：列出三个跨场景稳定能力和三个必须留在业务侧的规则。
- **参考回答（60 秒）**：平台值得做，是因为状态管理、工具协议、权限、追踪、评测和发布在多个 Agent 中重复出现。最小边界应是稳定的运行时契约、工具注册与鉴权、会话和任务状态、观测审计。指标口径、审批规则和业务失败语义仍留在垂类层。第一版不会强行统一所有 Prompt、规划策略或多 Agent 拓扑。

### Q003 四段实习和三个项目的共同主线是什么？如何避免堆技术名词？
- **考察点**：能否用问题与结果组织经历。
- **知识点**：问题链；个人贡献；证据；边界。
- **复习巩固**：每段经历只留“业务问题、本人动作、验证方式”三句。
- **参考回答（60 秒）**：共同主线是把不稳定的模型能力放进可约束的软件流程。实习侧有测试动作抽象、失败反馈和音频质量检测，项目侧有检索证据、多 Agent 状态、Harness 和评测。我回答时先讲问题，再讲我负责的决策与验收，技术名只用于解释机制，不把工具清单当贡献，也不补未经确认的线上指标。

### Q004 你对数据平台的理解是什么？它和业务后端、AI 平台各自的责任边界？
- **考察点**：岗位业务背景是否清楚。
- **知识点**：采集；开发；治理；元数据；服务；模型基础设施。
- **复习巩固**：画数据从生产、传输、加工、治理到消费的链路。
- **参考回答（知识题口径，60 秒）**：数据平台管理数据全生命周期，包括接入、计算、调度、元数据、质量、血缘、安全和数据服务。业务后端负责具体交易与领域流程，AI 平台负责模型调用、训练或推理基础设施。数据 Agent 位于交界处，用元数据和业务口径理解问题，通过受控工具查询或操作平台，但不能绕开数据权限和治理规则。

### Q005 最近关注的 Agent 或数据平台变化是什么，怎样判断是可落地能力而非热点？
- **考察点**：前沿敏感度与工程判断。
- **知识点**：标准协议；Harness；评测；迁移成本；真实指标。
- **复习巩固**：选 MCP 或长任务 Harness，准备价值、限制、验证三个角度。
- **参考回答（60 秒）**：我更关注工具协议标准化和长任务 Harness。判断能否落地，我会看它是否减少真实集成成本，是否有权限、恢复、观测和评测闭环，升级后能否兼容，以及坏例是否可复现。协议接通只证明互操作，不能自动解决规划质量和安全隔离；这类边界比发布热度更重要。

### Q006 哪些内容由 AI 辅助，哪些决策与验收由你负责？请举一个可核验例子。
- **考察点**：诚信和真实掌控力。
- **知识点**：需求拆解；方案选择；代码审查；测试验收；归属。
- **复习巩固**：准备一个能现场定位代码、测试和产物的例子。
- **参考回答（60 秒）**：AI 会辅助检索代码、提出实现和生成部分草稿，我负责问题拆解、方案取舍、审查、测试与失败修正。比如 Agentic RAG 的 Pipeline 是否晋级，不由生成代码或平均分决定，而由固定语料、可复核报告、逐题 win/loss 和 gate 共同判断。最终 B2、B3 没过门槛，默认仍是 B1。我的贡献应表述为组织和验收这条证据链，不把 AI 产出全部算作手写。

### Q007 面试官认为项目过于复杂、像拼装，你如何用一条真实状态流证明理解深度？
- **考察点**：是否理解组件间状态和失败语义。
- **知识点**：canonical state；事件；幂等；门禁；恢复。
- **复习巩固**：闭卷画 Deep Research assignment 从 pending 到 completed 的全部校验。
- **参考回答（90 秒）**：我会选一条状态流而不是报框架名。Deep Research 中，模型只给 Task 和 Assignment ID，服务端从 canonical Task Board 补全目标、attempt 和路径；同批 tool call 先 reservation，再执行；结果 patch 要匹配 assignment、attempt 和 fingerprint，旧结果被拒绝；产物通过结构与引用校验后才能完成；checkpoint 恢复时 running 回到 pending，但 attempt 不回退。这条链能说明我理解为什么需要每个组件，也能指出它仍是单进程控制器，不是分布式 exactly-once。

### Q008 和产品、数据开发、算法同学对“效果好”的定义不同，怎么对齐？
- **考察点**：跨角色协作和指标拆解。
- **知识点**：业务目标；质量指标；SLO；成本；验收集。
- **复习巩固**：为数据问答列业务、数据、模型、服务四层指标。
- **参考回答（45 秒）**：先把“效果好”拆成可分别验收的指标：业务看任务是否解决，数据开发看口径和数据新鲜度，算法看检索与答案质量，后端看延迟、错误率和成本。再用同一批代表性任务做基线，明确主指标、护栏指标和上线门槛。争议保留到逐题坏例和用户影响，不用一个总分掩盖取舍。

### Q009 企业客户要求一周上线但权限和审计未就绪，如何沟通范围？
- **考察点**：能否守住 To B 安全底线并推进交付。
- **知识点**：最小权限；只读；审批；审计；分阶段交付。
- **复习巩固**：准备一个只读试点方案和阻断条件。
- **参考回答（60 秒）**：我会把一周目标收缩为隔离环境、固定数据集、只读工具和白名单用户，所有调用保留最小审计记录，高风险导出和写操作关闭。权限和审计不是后补功能，因为一旦越权，模型效果再好也不能上线。可以同时给出第二阶段的身份映射、字段权限、审批与回滚计划，让客户看到可交付范围和缺口。

### Q010 你最不愿在简历上夸大的一个能力是什么，为什么？
- **考察点**：事实边界意识。
- **知识点**：冻结评测；生产验证；个人归属；可复核证据。
- **复习巩固**：准备三组“能说、不能说”。
- **参考回答（45 秒）**：我最不愿夸大生产化能力。我的项目能证明架构、测试和冻结评测，但不能证明真实多租户规模、线上 SLA 或业务收益。比如 KITE 只覆盖固定 15 题和 134 份 PDF；Deep Research 的门禁保证结构与引用约束，不保证网页事实绝对正确。明确边界不会削弱项目，反而便于讨论还需补什么。

### Q011 面对未接触的大数据组件，如何在两天内形成可讨论的设计判断？
- **考察点**：快速学习方法是否可靠。
- **知识点**：官方文档；最小实验；关键语义；失败模式；对比。
- **复习巩固**：选 Kafka 或 Flink，按输入、状态、恢复、扩缩容整理一页纸。
- **参考回答（45 秒）**：先从岗位场景提取必须回答的语义，如顺序、重复、状态、恢复和延迟；再读官方概念与故障语义，跑一个最小实验验证关键假设，最后和已知系统对比并列出未知项。两天目标是形成有证据的设计判断，不是假装掌握全部调优细节。

### Q012 你更偏应用、算法还是平台工程？用一个反例说明边界。
- **考察点**：定位是否清晰且不自我包装。
- **知识点**：应用后端；算法理解；平台契约；训练边界。
- **复习巩固**：准备一个擅长项和一个明确不擅长项。
- **参考回答（45 秒）**：我偏 Agent 应用和平台工程，能把检索、模型、工具、状态与评测连成服务，也能理解算法指标并做实验。反例是我没有基础模型预训练或 Agent RL 的真实交付，遇到模型本体优化会和算法同学协作。我能负责输入输出契约、数据与评测闭环，而不会把算法了解说成训练经验。

### Q013 模型效果、延迟、成本、安全都差一点，第一周怎么排优先级？
- **考察点**：风险和收益排序能力。
- **知识点**：安全底线；正确性；SLO；成本；可逆性。
- **复习巩固**：用影响乘概率和可逆性给四项排序。
- **参考回答（90 秒）**：先封住越权、数据泄露和不可逆副作用，再处理会给错误业务结论的质量问题。随后用 SLO 看延迟是否阻断核心任务，最后优化成本，除非成本已导致不可服务。第一周先加阻断和观测，建立最小基线，再逐项实验。排序会根据业务风险调整，但安全和伪成功不能拿平均效果交换。

### Q014 解释 Agent 给非技术同学听，如何避免把它说成全自动替人决策？
- **考察点**：表达和风险沟通。
- **知识点**：目标；工具；规则；确认；责任主体。
- **复习巩固**：用数据问答场景做 30 秒无术语解释。
- **参考回答（30 秒）**：Agent 可以理解目标、选择被允许的工具并按步骤完成任务，但它的判断会受数据、模型和规则限制。查数和生成草稿可以自动做，涉及敏感数据、写操作或高成本动作要经过程序校验或人工确认。最终责任仍由业务系统和人员承担。

### Q015 讲一次方案被证据否定后如何调整，什么证据改变了你的判断？
- **考察点**：是否真正用评测驱动决策。
- **知识点**：假设；对照；逐题回退；门禁；停止规则。
- **复习巩固**：复述 Agentic RAG B2/B3 未晋级的数字边界。
- **参考回答（60 秒）**：Agentic RAG 曾比较更复杂的 B2、B3。它们平均分高于 B1，但增量分别只有 0.4 和 0.3333，且逐题 losses 分别为 3 和 4，没有满足平均提升至少 0.5、losses 不超过 2 等 gate。因此没有因“更复杂、均分更高”就切换默认流程，B1 继续作为默认。这个结论只属于冻结数据与评测协议。

## B. 华为测试 Agent 与 Workflow

### Q016 AW、BAW 分别是什么，为什么要把底层 AW 封装成业务动作？
- **考察点**：是否理解实习中的核心抽象。
- **知识点**：底层动作；业务语义；固定参数；有限值域；稳定接口。
- **复习巩固**：准备一个脱敏的 AW 到 BAW 参数映射例子。
- **参考回答（45 秒）**：AW 是较底层的可执行动作，参数多且贴近接口；BAW 把固定参数下沉，并按有限值域或业务场景形成语义清楚的业务动作。这样测试生成面对的是稳定意图，底层接口变化集中在封装层。我的经历可讲抽取、封装和脚本转换，不能补未确认的规模或收益百分比。

### Q017 如何从既有编排脚本抽取 AW、入参类型、实际取值和调用模式？脏数据怎么办？
- **考察点**：数据抽取与质量处理能力。
- **知识点**：解析；标准化；类型推断；频次统计；异常样本。
- **复习巩固**：画解析、校验、聚合、人工确认流水线。
- **参考回答（60 秒）**：先用脚本语法和元数据解析调用，不靠纯文本猜测；对动作名、参数位置、类型和值域标准化，再按调用上下文和频次聚合。缺字段、类型冲突和极少见值单独进入异常集，不直接参与自动封装；高风险或低置信结果交人工确认，并保留来源脚本以便回溯。

### Q018 一个 AW 对应多个业务场景时，何时拆多个 BAW，何时保留参数化 BAW？
- **考察点**：抽象粒度取舍。
- **知识点**：语义稳定性；参数正交性；组合爆炸；可发现性。
- **复习巩固**：为一个有限枚举和一个连续参数分别做选择。
- **参考回答（45 秒）**：如果不同取值代表不同业务意图、前置条件或风险，就拆成多个 BAW；如果只是同一动作的正交配置，保留参数化接口。还要控制动作数量，避免枚举组合爆炸。判断标准是调用者能否仅凭名称和 schema 选对动作，而不是追求参数越少越好。

### Q019 BAW 生成后怎样避免业务动作名称相近但实际调用不同，引入错误复用？
- **考察点**：生成资产的唯一性和语义校验。
- **知识点**：规范化签名；冲突检测；黄金样例；人工审核；版本。
- **复习巩固**：写出动作签名包含的字段。
- **参考回答（设计题口径，90 秒）**：为 BAW 建规范化签名，包含底层 AW、固定参数、暴露参数、前置条件和副作用；名称只是展示字段。生成后做同名异签和异名同签检查，用代表性脚本回放比较调用结果。冲突项阻断发布并人工确认，资产带版本，调用脚本绑定明确版本。

### Q020 把 AW 脚本批量转成 BAW 脚本，如何设计可回滚、可审阅的转换？
- **考察点**：批量变更安全性。
- **知识点**：dry-run；结构化 diff；映射清单；原子发布；回滚。
- **复习巩固**：设计一次转换产物目录和审批步骤。
- **参考回答（设计题口径，60 秒）**：转换先生成新脚本和映射报告，不覆盖原文件；报告展示每个 AW 到 BAW 的参数变化、未匹配项和风险。通过语法检查、静态校验和抽样执行后按批次发布，保留旧版本与转换 manifest。出现回退时按 manifest 恢复，不做不可追踪的原地替换。

### Q021 失败信息怎样进入下一轮脚本生成或调整？哪些失败不能交给模型猜？
- **考察点**：失败反馈能否结构化和受控。
- **知识点**：错误分类；最小上下文；确定性修复；权限；人工确认。
- **复习巩固**：将失败分环境、接口、脚本、数据和模型五类。
- **参考回答（60 秒）**：先把错误码、失败步骤、关键日志和前置状态结构化，再决定是否反馈给模型。语法或已知参数错误可按规则修复，环境抖动先重试或报环境问题；权限、接口契约变化、不可逆副作用和原因不明的失败不能让模型猜。下一轮只带相关证据，并限制可修改范围。

### Q022 测试 Agent 的 Workflow 如何区分规划、生成、执行、校验和人工审批？
- **考察点**：是否会把模型判断放进确定性状态机。
- **知识点**：阶段状态；artifact；门禁；副作用；审批。
- **复习巩固**：闭卷画状态转换和每步输入输出。

### Q023 同一用例重复失败，如何区分环境抖动、脚本错误、接口变更和模型理解错误？

### Q024 如何诚实说明你优化了 Prompt、上下文和任务拆分，但没有统一提升百分比？

### Q025 测试工具 schema 应如何描述输入、前置条件、幂等性和风险？

## C. Agentic RAG 项目连续追问

### Q031 请从导入 PDF 到答案和证据展示，讲完整链路。
- **考察点**：能否讲清自己的端到端项目。
- **知识点**：解析；切分；索引；路由；混合召回；重排；packing；引用。
- **复习巩固**：沿 `api`、`indexing`、`agent` 三层闭卷画链路。
- **参考回答（90 秒）**：PDF 导入后解析正文和页码、章节等元数据，切分后写 Node Store，并构建 FAISS 与 BM25 索引。请求先判断 direct、retrieve 或 out-of-scope，需要检索时可改写并拆为最多三个子查询。默认 B1 做 dense 与 sparse 召回、去重、FlashRank 重排和 token budget packing，回答产出答案、证据、置信度和局限。展示引用使用可追溯的 `quote_text` 及 paper、section、page，`retrieval_text` 只服务召回。SSE 推送进度、证据和最终答案，不说成已验证逐 token 流。

### Q032 当前默认为什么是 FAISS 加 BM25、flat 索引、FlashRank 和 fixed answer？
- **考察点**：能否用证据解释默认配置。
- **知识点**：语义召回；关键词召回；平面索引；重排；冻结决策。
- **复习巩固**：定位 `core/settings.py` 和冻结 KITE 决策。
- **参考回答（60 秒）**：FAISS 与 BM25 互补语义和精确词匹配，FlashRank 在混合候选上做更精细排序。flat 链路更简单且当前基线更稳定，hierarchical 已支持但不是默认。fixed answer 保持可控，因为 Adaptive 复验未证明净收益。B2、B3 虽均分略高也未过晋级 gate，所以默认仍是 B1。这里的“默认”是项目配置，不是商业生产部署证明。

### Q033 dense 和 sparse 各自容易漏什么，混合召回为何仍需要重排？
- **考察点**：检索原理是否扎实。
- **知识点**：语义近邻；精确实体；词汇错配；融合；cross-encoder。
- **复习巩固**：为专有名词和同义改写各造一个反例。
- **参考回答（45 秒）**：dense 擅长同义和语义相近，但可能错过精确编号、缩写和罕见实体；sparse 能抓关键词，却会漏掉没有词面重合的表达。融合扩大候选覆盖，不代表顺序正确，因为两个通道的分数不可直接比较，且缺少 query 与文段的细粒度交互。重排在较小候选集上重新判断相关性。

### Q034 B0、B1、B2、B3 的差异是什么？不要把四条 Pipeline 说成四种索引层级。
- **考察点**：冻结实验能否准确复述。
- **知识点**：Hybrid；rerank；metadata prefix；RRF；neighbor expansion。
- **复习巩固**：闭卷写四条 Pipeline 的单行差异。
- **参考回答（90 秒）**：B0 是混合召回但不重排；B1 是当前默认的平面混合召回加重排；B2 加入 mixed tokenizer、metadata prefix、RRF 后重排；B3 在 B2 上增加邻近段扩展。它们是检索 Pipeline 的消融比较，不是四种索引层级，hierarchical 是另一项索引模式能力。

### Q035 KITE gate 的晋级条件有哪些，B2/B3 为什么没有替换 B1？
- **考察点**：是否理解平均分之外的发布门禁。
- **知识点**：有效性；均分增量；wins/losses；p95；token；证据契约。
- **复习巩固**：记住 0.5、wins 至少 4、losses 至多 2、1.5 倍三个阈值。
- **参考回答（90 秒）**：候选和 B1 都要 15 题记录有效，候选均分至少高 0.5，逐题 wins 不少于 4、losses 不多于 2，p95 与平均 context token 都不超过 B1 的 1.5 倍，还要通过证据契约和人工检查。B2 相对 B1 只提高 0.4，5 wins 但 3 losses；B3 提高约 0.3333，5 wins 但 4 losses，所以都未晋级。自动报告也明确不做生产切换。

### Q036 15 题、134 PDF 的冻结评测能证明什么，不能证明什么？
- **考察点**：实验外推边界。
- **知识点**：固定语料；固定协议；可复现；样本量；分布外。
- **复习巩固**：把“内部有效”和“外部有效”分两列。
- **参考回答（45 秒）**：它能证明在固定 134 份 PDF、15 个问题、模型、judge、代码提交和配置下，四条 Pipeline 的可复核相对表现。它不能证明真实业务准确率、跨领域泛化、线上 SLA 或成本，也不能把 valid_count 解释为全部答对。当前代码和冻结评测提交不同，不能说结果已在当前 HEAD 重跑。

### Q037 chunk 切分如何影响 recall、引用完整性和上下文成本？
- **考察点**：是否理解切分的多目标取舍。
- **知识点**：粒度；边界；overlap；噪声；引用定位。
- **复习巩固**：用定义跨段和长表格举两个失败例。
- **参考回答（45 秒）**：chunk 太小会把条件与结论拆开，召回到半句话且引用不完整；太大则混入噪声，提高 embedding、重排和上下文成本。overlap 能缓解边界问题但会制造重复。应结合文档结构、问题类型和 token 预算选择，并用 recall、引用支持度和成本共同评测。

### Q038 怎么为论文库选择 chunk 大小和 overlap？给出反例。
- **考察点**：能否从数据和任务选择参数。
- **知识点**：结构切分；token 分布；查询类型；实验；反例。
- **复习巩固**：抽取若干论文段落，画长度分布并设计小型对照。
- **参考回答（设计题口径，60 秒）**：先按标题、段落、列表和表格边界切，再用 token 上限兜底；对定义、方法步骤和跨句限定保留适量 overlap。用真实问题比较 Recall@K、context recall、引用完整性和 token。反例是把所有内容固定按 500 token 切，可能把表头与数据、实验条件与结果分开，单靠更大 overlap 还会放大重复。

### Q039 RRF 融合的直觉与风险是什么，何时不用它？
- **考察点**：融合算法理解。
- **知识点**：rank fusion；尺度无关；k 常数；通道质量；重复。
- **复习巩固**：手算两个排序列表的 RRF 分数。
- **参考回答（45 秒）**：RRF 按各通道排名的倒数累加，不依赖原始分数尺度，适合融合 BM25 与向量结果。风险是弱通道也会贡献分数，k 和权重会影响头部，重复与通道相关性可能制造虚假共识。若只有一个可靠通道、已有可校准统一分数，或离线实验显示融合增加坏例，就不必用。

### Q040 检索到多个互相矛盾的段落，回答层如何展示不确定性？
- **考察点**：证据冲突处理。
- **知识点**：来源版本；时间；权威性；分歧呈现；拒答。
- **复习巩固**：构造同一指标不同版本的冲突样例。
- **参考回答（设计题口径，90 秒）**：先比较文档版本、时间、适用范围和来源权威性，不能让模型暗中选一个。若能根据用户场景消解，就说明所用版本和限定条件；无法消解时并列两种说法及各自证据，降低置信度并请求补充上下文。对高风险问题可直接拒绝给单一结论。

### Q041 token budget packing 为什么是独立环节？如何避免只留下高分碎片而丢失限定条件？
- **考察点**：上下文选择是否独立于排序。
- **知识点**：预算；多样性；邻接；文档配额；必要条件。
- **复习巩固**：对同一候选列表手工做一次 packing。
- **参考回答（60 秒）**：排序回答“谁更相关”，packing 还要处理总 token、来源多样性、重复和段落完整性，因此应独立。可为文档和子问题设配额，去重后保留必要邻接段、标题与限定条件，并避免高分结果全来自同一来源。最终记录被选证据和截断原因，便于定位“召回到了但没送进模型”。

### Q042 LangGraph 的路由、子查询分发和聚合做了什么？最多三个子查询的取舍？
- **考察点**：能否讲清图编排的实际作用。
- **知识点**：direct/retrieve/out-of-scope；rewrite；Send；fan-out/fan-in；预算。
- **复习巩固**：定位 `agent/graph.py` 与 `agent/edges.py`，画节点和状态字段。
- **参考回答（60 秒）**：图先判断知识库范围，再走直接回答、检索或越界回答。检索路径会规划和改写问题，通过 `Send` 分发子查询，最后聚合检索结果与回答。最多三个子查询是质量与成本的硬预算，可覆盖常见多跳拆分，又避免无界 fan-out、重复召回和上下文爆炸。它不负责运行时选择 B0 到 B3。

### Q043 某类问题 recall 很好但答案错，如何判断是 rerank、packing、生成还是 citation 映射问题？
- **考察点**：分层归因能力。
- **知识点**：候选集；重排位次；送模上下文；回答；引用映射。
- **复习巩固**：选一个坏例保存四层中间产物。
- **参考回答（90 秒）**：先确认 gold 是否在原始候选中；在但被重排压低，是 rerank 问题。重排靠前却未进入最终上下文，看 packing 与预算。上下文含完整证据但答案错，定位生成或 Prompt；答案正确但引用指错，查 evidence ID、quote_text 与展示映射。每层固定输入重放，避免同时改多个组件后无法归因。

### Q044 GroundedAnswer 中的答案、证据、置信度、局限各自作用？
- **考察点**：结构化回答契约意识。
- **知识点**：answer；evidence；confidence；limitations；展示。
- **复习巩固**：用一个库外问题写完整结构。
- **参考回答（45 秒）**：答案给用户结论；证据绑定可追溯原文；置信度表达系统对证据充分性的判断；局限说明语料缺口、冲突或适用范围。四者分开后，前端能呈现引用，评测能分别检查事实和证据。置信度不是校准后的概率时不能包装成准确率。

### Q045 为什么 `retrieval_text` 不应直接展示为用户引用？
- **考察点**：检索表示与证据表示的边界。
- **知识点**：metadata prefix；source-faithful；quote_text；可追溯。
- **复习巩固**：定位 `retrieval_pipeline.py` 中两字段构造。
- **参考回答（45 秒）**：`retrieval_text` 可以拼接标题、元数据前缀或其他增强信息，用于召回和重排，并不一定是源文档连续原文。展示引用应使用 source-faithful 的 `quote_text`，同时绑定 paper、section、page 和版本。否则用户看到的“原文”可能含系统添加内容，引用审计也会失真。

### Q046 SSE 发了哪些进度与最终事件？为何不能把它说成逐 token 流式生成？
- **考察点**：能否准确描述已有实现。
- **知识点**：HTTP SSE；进度；证据；final；token stream 边界。
- **复习巩固**：定位 `api/routers/chat.py` 的事件类型。
- **参考回答（45 秒）**：当前 API 通过 SSE 发送处理进度、证据和最终答案等事件，让前端看到阶段变化。已有证据不足以说明生成模型的每个 token 都实时穿透到浏览器，所以我只说事件流式返回。SSE 解决传输和用户反馈，不自动等于任务取消、恢复或模型 token streaming。

### Q047 新增或删除论文后，索引、引用定位和历史会话如何保持版本一致？
- **考察点**：知识库更新的一致性设计。
- **知识点**：snapshot；manifest；双写切换；tombstone；会话绑定。
- **复习巩固**：画 index version 从构建到切换的流程。
- **参考回答（设计题口径，90 秒）**：每次变更生成新的 corpus 与 index manifest，记录 parser、chunk、embedding 和文档版本。新索引完整构建并校验后原子切换，删除用 tombstone 确保所有通道都不可召回。回答和历史会话绑定当时的 index version、chunk ID 和来源版本，旧引用仍可追溯；若原文被合规删除，则显示已撤销而不是静默指向新内容。

### Q048 hierarchical 已支持但不是默认，什么时候值得启用？
- **考察点**：是否根据问题结构选择索引。
- **知识点**：文档树；粗到细；长文；多跳；基线。
- **复习巩固**：比较 flat 与 hierarchical 在长章节问题上的候选链。
- **参考回答（60 秒）**：当文档层级稳定、问题需要先定位文档或章节再找细节，且平面检索常丢全局语境时，hierarchical 值得实验。代价是构建、调参和调试更复杂，父子召回也可能传播错误。当前项目已支持该模式，但离线基线没有证明优于 flat rerank，所以不能说它已是默认最优。

### Q049 Adaptive 路径为什么只保留显式实验配置，不直接变为默认？
- **考察点**：是否尊重实验停止规则。
- **知识点**：显式配置；复验；净收益；复杂度；默认稳定性。
- **复习巩固**：阅读 `v2_upgrade_plan.md` 中 M4.1、M4.2 状态。
- **参考回答（45 秒）**：Adaptive 增加动态判断和多轮成本，必须用稳定收益换取复杂度。项目两次复验都没有证明净收益，因此 fixed 保持默认，Adaptive 只作为显式实验入口，后续持久 run、checkpoint 和产品入口也没有继续扩建。已实现不等于应上线。

### Q050 如何构造难例，专测术语冲突、跨段条件和错误引用？
- **考察点**：针对性评测集设计。
- **知识点**：最小对比；对抗样例；gold evidence；不可回答；版本。
- **复习巩固**：每类手写三题并标 gold chunk 与干扰 chunk。
- **参考回答（设计题口径，90 秒）**：术语冲突题放入同名不同义文档；跨段题把条件、方法和结论分散在相邻或远距离段落；引用题设置答案相似但不支持该陈述的干扰片段。每题标答案、必要证据、禁止证据和不可回答条件，并保存文档版本。评测同时看召回、回答和引用支持，不只看文本相似度。

### Q051 用户问的内容不在论文库，路由应怎样处理而不是编答案？
- **考察点**：越界识别和诚实降级。
- **知识点**：scope；无证据；澄清；外部工具；拒答。
- **复习巩固**：准备三类越界输入及用户提示。
- **参考回答（30 秒）**：路由应识别 out-of-scope，明确说明当前论文库没有足够证据，并给出可行动选项，如换关键词、上传相关文档或在获得授权后调用外部搜索。不能把模型常识伪装成库内结论，引用为空时也不能生成虚假证据。

### Q052 检索质量不变时，优先从哪里降 p95 和 context token？如何验证没有偷质量？
- **考察点**：性能优化与质量护栏。
- **知识点**：分段 trace；候选数；缓存；并行；packing；回归。
- **复习巩固**：给链路各阶段列耗时和 token 指标。
- **参考回答（90 秒）**：先用 trace 分解解析、embedding、dense/sparse、rerank、模型调用的 p95，优化真正慢的阶段。常见动作是并行独立召回、减少无效候选、缓存稳定 embedding 与检索结果、去重并改进 packing，而不是直接砍上下文。验证时冻结同一评测集和版本，要求 Recall、答案分、引用与逐题 losses 不退化，再看 p95 和 token 是否下降。

## D. Deep Research 项目连续追问

### Q053 讲清 Orchestrator、Scoping、Research、Verification/Reviewer、Report 的职责。
- **考察点**：是否理解多 Agent 分工与控制边界。
- **知识点**：编排；范围；研究；验证；报告；Readiness。
- **复习巩固**：沿 `src/agent.py` 画角色输入输出，说明 Readiness 是确定性评估器。
- **参考回答（90 秒）**：Orchestrator 推进全局状态并委派任务；Scoping 把开放问题转成可审批范围；Research 收集结构化 finding 与来源；Verification/Reviewer 检查缺口、相互支持和反驳；Report 只消费通过门禁的材料生成报告。Readiness 不是第五个专业 Agent，而是判断证据是否足够停止研究的确定性评估器，语义辅助失败也不能解除硬阻塞。

### Q054 Task Board 为什么是 canonical state，为什么不能让 UI JSON 反向更新它？
- **考察点**：是否区分运行时真相与展示投影。
- **知识点**：typed state；reducer；projection；lost update；审计。
- **复习巩固**：定位 Task Board patch 与 Web projection 路径。
- **参考回答（60 秒）**：typed Task Board 参与调度、reducer 和 checkpoint，包含状态转换所需的不变量，因此是唯一真相。UI JSON 为展示和审计派生，可能延迟、裁剪或来自旧版本。若允许其反向更新，会让旧投影或模型输出覆盖新 attempt，产生 lost update。UI 只能提交受校验的命令，不能提交整份状态。

### Q055 同一模型响应包含多个 task call 时，reservation 如何防止并发重复领取？
- **考察点**：并发调度细节是否掌握。
- **知识点**：批量预留；tool_call_id；pending；running；attempt。
- **复习巩固**：定位 `WorkflowGuardMiddleware.after_model()` 和 reservation 校验。
- **参考回答（90 秒）**：ToolNode 并发前，middleware 先批量校验并预留合法 Assignment，把状态从 pending 改为 running、attempt 加一，并绑定 `reserve:<tool_call_id>`。真正执行时必须证明该 reservation。相同 ID、旧 attempt、已取消或越权任务会在 Worker 启动前拒绝，避免同批并发重复领取。

### Q056 attempt、tool_call_id、patch fingerprint 分别防什么乱序问题？
- **考察点**：是否理解多层去重标识。
- **知识点**：执行代次；调用身份；补丁去重；stale result。
- **复习巩固**：构造旧 Worker 晚到和重复消息两个时序图。
- **参考回答（90 秒）**：attempt 区分同一 Assignment 的不同执行代次，旧代次结果不能覆盖新代次；tool_call_id 绑定一次具体调度与 reservation；patch fingerprint 防同一状态补丁被重复应用。三者分别覆盖代次、调用和消息三个层面，缺一时都可能出现迟到结果或重复提交污染状态。

### Q057 为什么 Worker 的自然语言“已完成”不能直接将 assignment 标记 completed？
- **考察点**：模型声明与系统事实是否分离。
- **知识点**：artifact contract；schema；来源完整性；服务端状态机。
- **复习巩固**：列出 finding、source index、event JSONL 的完成条件。
- **参考回答（45 秒）**：自然语言只是模型意见，不能证明产物存在、归属正确或引用完整。服务端要检查 finding 标记、固定路径、source index、source_id 和 event JSONL schema，再由受控 patch 转换状态。否则一句“完成”就能绕过证据和权限门禁。

### Q058 artifact validator 应检查哪些内容？为什么结构合法不等于网页事实真实？
- **考察点**：验证层次是否清楚。
- **知识点**：路径归属；schema；引用闭合；正文 hash；事实真实性。
- **复习巩固**：阅读 `task_board.py` 的验证条件，区分 syntactic 与 semantic truth。
- **参考回答（60 秒）**：validator 检查产物路径属于当前 assignment、JSON 可解析、必填字段与状态合法、source index 完整、source_id 可解析、事件逐行符合 schema。它能证明结构和引用契约成立，不能证明网页没过期、抽取无误或陈述真实。事实层还需来源质量、冲突处理、Claim Verification 和人工判断。

### Q059 两个 Research Worker 同角色，如何阻止互读 sibling 产物又允许已授权父级资料？
- **考察点**：上下文隔离与最小授权。
- **知识点**：AssignmentReadScope；allowlist；parent；sibling；虚拟文件。
- **复习巩固**：定位 read scope 构造和 denied inputs。
- **参考回答（90 秒）**：服务端根据 assignment 合同生成精确 allowlist，只允许共享资料、本 assignment 路径和明确授权的 parent 产物，sibling 与 aggregate 输入默认拒绝。模型不能自行扩大路径范围。当前边界约束 StateBackend 的虚拟文件访问，不是 OS 沙箱；真正不可信执行仍需进程或容器隔离。

### Q060 AssignmentReadScope 是什么安全边界，不是什么安全边界？
- **考察点**：能否准确陈述安全能力。
- **知识点**：逻辑能力；虚拟文件；路径权限；OS 权限；网络隔离。
- **复习巩固**：准备“防什么、不防什么、生产要补什么”三句。
- **参考回答（45 秒）**：它是应用层读取能力边界，限制 Worker 在 StateBackend 中能看到哪些共享、本任务和父级产物，防止 sibling 信息串扰。它不限制进程可访问的真实文件、网络或系统调用，也不构成容器沙箱。生产执行不可信工具还需 OS 级隔离和凭据收敛。

### Q061 Verification、Readiness、Claim Verification 的输入、输出和错误类型有何不同？
- **考察点**：三类门禁是否分得清。
- **知识点**：任务结果；全局充分性；陈述证据；blocker；warning。
- **复习巩固**：画三张输入输出卡片。
- **参考回答（60 秒）**：Verification 检查任务结果与 gaps，输出需补证或可接受结论；Readiness 汇总范围覆盖、来源和高风险缺口，决定是否能停止研究；Claim Verification 检查报告中的具体陈述、source ID 与提取正文是否对应。三者解决任务质量、全局充分性和最终陈述三个层面，不能用一个 judge 分数替代。

### Q062 为什么 Readiness input snapshot 失效后，旧的 READY 不能继续用于 report gate？
- **考察点**：派生结论的版本一致性。
- **知识点**：input hash；stale decision；TOCTOU；门禁。
- **复习巩固**：构造 READY 后 finding 变化的时序。
- **参考回答（90 秒）**：READY 是针对特定 findings、sources、verification 和 claims 快照的派生结论。输入变更后，旧结论不再证明当前材料充分，继续使用会产生检查时与使用时不一致。Report gate 因此重算 hash，失配就要求重新评估，而不是相信状态字段仍写着 READY。

### Q063 claim inventory 如何避免报告生成阶段临时加入无来源陈述？
- **考察点**：生成前证据契约设计。
- **知识点**：claim ID；重要性；source binding；allowlist；report gate。
- **复习巩固**：为三条报告陈述制作 claim inventory。
- **参考回答（60 秒）**：研究结束前先形成 claim inventory，为重要陈述记录 claim ID、内容、重要性和支持 source。Claim Verification 验证后，报告只能使用已登记且通过的 claim；新增陈述必须回到 inventory 和验证流程。这样报告生成不是临时自由发挥，仍要承认它不能证明来源本身绝对真实。

### Q064 如何处理来源引用存在但正文抽取失败、内容过期或相互冲突？
- **考察点**：复杂证据失败处理。
- **知识点**：usable source；时间戳；冲突；降级；披露。
- **复习巩固**：分别写三类来源的状态和报告策略。
- **参考回答（设计题口径，90 秒）**：抽取失败的来源标为不可用，不因 URL 存在就通过；过期来源保留抓取时间和适用期，优先补新来源；冲突来源按时间、权威性和定义范围分析，无法消解就并列披露。高重要性 claim 若缺可用证据，应阻断或降级报告，不让模型自行补齐。

### Q065 checkpoint 和长期 memory 的差别，为什么半成品不应写入 memory？
- **考察点**：运行恢复与知识沉淀边界。
- **知识点**：执行状态；恢复；稳定事实；污染；生命周期。
- **复习巩固**：把 task state 字段分到 checkpoint、memory 或都不存。
- **参考回答（45 秒）**：checkpoint 保存某次运行的图状态、任务进度和预算，用于故障恢复；长期 memory 保存跨任务仍稳定且经过确认的信息。半成品可能错误、过期或包含未验证猜测，写入 memory 会污染后续任务。只有完成并通过验证的可复用信息才考虑沉淀，还需支持来源、过期和删除。

### Q066 AsyncSqliteSaver 恢复时如何处理 running assignment、attempt 和预算？
- **考察点**：当前项目恢复语义是否掌握。
- **知识点**：SQLite checkpoint；recovery patch；pending；attempt；budget snapshot。
- **复习巩固**：定位 `checkpointing.py`、`cli.py` 和恢复测试。
- **参考回答（60 秒）**：当前用 `AsyncSqliteSaver` 保存 Agent Team checkpoint。恢复时，运行中断的 Assignment 通过 recovery patch 回到 pending，但 attempt 不回退，防旧结果重新成为有效；elapsed 和已用预算从快照恢复。进程内 semaphore 与 controller 不序列化，新进程按持久快照重建控制。它仍不保证外部副作用 exactly-once。

### Q067 外部搜索已发出但进程在结果写入前崩溃，如何实现 at-least-once 并控制重复副作用？
- **考察点**：外部调用恢复设计。
- **知识点**：调用记录；幂等键；查询操作；去重；状态不确定。
- **复习巩固**：画 intent、request、result 三阶段记录。
- **参考回答（设计题口径，90 秒）**：调用前持久化 tool_call_id、attempt、请求摘要和状态，恢复时先查是否已有结果或供应商请求 ID。搜索是读操作，可按退避重试并按规范化来源去重；有副作用的工具必须使用业务幂等键或查询确认，无法确认时转人工，不能盲重放。系统最多承诺任务协议的 at-least-once，外部系统的实际效果取决于其幂等能力。

### Q068 为什么不序列化 semaphore/controller？重启后如何重新建立运行时控制？
- **考察点**：持久状态与进程资源边界。
- **知识点**：运行时对象；不可移植；预算快照；重建；租约。
- **复习巩固**：列出可序列化事实和不可序列化句柄。
- **参考回答（45 秒）**：semaphore、锁和 controller 绑定当前事件循环与进程，序列化后不能在新进程恢复真实占用关系。checkpoint 只保存计数、elapsed 和限制等安全事实，新进程创建控制器并采用快照。多实例场景还要换成外部队列、租约或分布式配额，不能沿用内存 semaphore。

### Q069 exploring、finalizing、exhausted 三种预算模式如何防止尾部无报告？
- **考察点**：长任务预算收尾策略。
- **知识点**：宽泛研究；定向补证；资源预留；终止；incomplete。
- **复习巩固**：为三种模式列允许和禁止动作。
- **参考回答（60 秒）**：exploring 允许常规研究；进入 finalizing 后冻结宽泛探索，只保留定向补证、Verification、Claim 和 Report 的资源；exhausted 则停止新研究。这样在预算完全耗尽前为收尾预留模型和时间。若仍无法生成合格报告，状态应是 incomplete，不能因预算结束伪装为完成。

### Q070 预算不足时，怎样决定继续补证、停止或降级回答？谁有权改变门禁？
- **考察点**：成本与质量门禁治理。
- **知识点**：claim importance；gap risk；预算；降级；policy ownership。
- **复习巩固**：对高风险与低风险 gap 各做一次决策。
- **参考回答（设计题口径，90 秒）**：按 claim 重要性、缺口风险和补证预期收益排序，高风险核心 claim 缺证就继续定向补证或停止，次要缺口可在报告中披露后降级交付。模型只能在既定预算内选择动作，无权修改安全和证据门禁；门禁由产品与工程 policy 控制，临时放宽需版本化审批和审计。

### Q071 SSE replay 和 heartbeat 解决什么，为什么浏览器事件只是 projection？
- **考察点**：流式传输与任务状态能否分离。
- **知识点**：event ID；重连；心跳；canonical state；projection。
- **复习巩固**：查看 `event_streaming.py` 与 Web API 映射。
- **参考回答（45 秒）**：heartbeat 保持连接并帮助发现断线，replay 用 event ID 补发窗口内事件，让前端恢复进度。浏览器收到的事件经过裁剪且可能延迟，只是 canonical Board 和产物的投影，不能反向决定任务状态。连接断开也不等于后端任务取消。

### Q072 评测 manifest 需要冻结哪些信息，为什么仅保存最终分数不够？
- **考察点**：评测可复现性。
- **知识点**：代码；数据；Prompt；provider；预算；评测器；逐例结果。
- **复习巩固**：阅读 `evals/experiments.py` 的 manifest 与 summary。
- **参考回答（60 秒）**：manifest 应保存代码提交与 dirty 状态、数据和 case hash、Prompt、模型与 provider、工具、预算、评测器和环境信息。最终分数无法解释版本差异、失败类别或逐题回退，也不能续跑和审计。逐例输入、输出、证据、错误和耗时同样要保留。

### Q073 Tavily 403/usage limit 的历史证据如何解读，如何改进失败分类？
- **考察点**：能否正确解释失败运行。
- **知识点**：environment failure；product failure；历史产物；分类器；不回写。
- **复习巩固**：阅读 Phase 19 evidence plan 和旧 cases 记录。
- **参考回答（90 秒）**：历史 open-ended smoke 因 Tavily 403 和套餐额度失败，没有报告、judge 或 GAIA 结果，不能把 runner 退出当 case 通过。旧记录曾标 product_failure，当前分类器已能识别 environment_failure，但历史产物没有回写。正确做法是保留原始证据、修分类逻辑并重跑，而不是改旧结果粉饰质量。

### Q074 何时多 Agent 真有收益，何时单 Agent 加工具更稳？
- **考察点**：架构取舍是否克制。
- **知识点**：任务并行；上下文隔离；角色专长；协调成本；评测。
- **复习巩固**：为研究、查数、审批三个场景做选择。
- **参考回答（60 秒）**：任务可独立并行、上下文需要隔离、角色有明确输入输出且聚合可验证时，多 Agent 才可能有收益。步骤短、共享状态强、工具少或协调成本高时，单 Agent 加确定性 Workflow 更稳。选择要用完成率、延迟、成本和坏例比较，不因框架支持就默认多 Agent。

## E. Forge、Harness 与 Agent Runtime

### Q075 Forge 的三包边界是什么，为什么不让 UI 或 provider SDK 反向依赖底层？
- **考察点**：当前项目架构边界是否掌握。
- **知识点**：core；coding；TUI；依赖方向；适配层。
- **复习巩固**：打开项目指南和架构测试，画包依赖。
- **参考回答（60 秒）**：Forge 把通用运行时、coding 能力和终端 UI 分层，provider 细节通过适配进入，UI 只消费事件和投影。核心层不依赖具体 TUI 或 SDK，工具与会话也不把展示类型向下传。这样升级 LangChain 或 provider 时主要改适配边界，避免状态和工具契约被 UI 绑死。

### Q076 为什么选官方 `create_agent()` 和 `astream_events(v3)`，而不维护另一套 while model-tool loop？
- **考察点**：复用框架与自研边界。
- **知识点**：官方执行语义；中间件；事件流；升级成本；Harness。
- **复习巩固**：定位 Harness 创建 Agent 和事件适配代码。
- **参考回答（60 秒）**：模型与工具循环已有成熟执行语义，Forge 复用 `create_agent()`，把价值放在工具、状态、取消、会话和产品行为上；`astream_events(v3)` 提供统一运行事件，再映射成自身投影。自建第二套 loop 会重复处理 ToolMessage 配对、并行、异常和升级兼容。Forge 仍用 Harness 补框架没负责的产品契约。

### Q077 LangChain 执行事实、Forge projection、TUI 展示状态如何区分？
- **考察点**：事件分层和单一真相意识。
- **知识点**：runtime events；projection；render state；replay；一致性。
- **复习巩固**：跟一次 tool call 从事件到 TUI 的映射。
- **参考回答（90 秒）**：LangChain 事件描述模型、工具和图的实际执行；Forge 将其归一成稳定的产品事件与会话记录；TUI 再把这些投影成可增量渲染的状态。展示丢帧不能改执行事实，恢复时应从持久会话或 Harness 重建投影，而不是把屏幕状态当真相。

### Q078 `StructuredTool`、`ToolDefinition`、`ToolRuntime` 分别是什么，怎样避免双 schema 漂移？
- **考察点**：工具抽象是否准确。
- **知识点**：框架工具；领域定义；执行上下文；单一 schema；适配。
- **复习巩固**：定位 tool registry 与适配测试。
- **参考回答（60 秒）**：`ToolDefinition` 表达 Forge 的工具元数据和输入契约，`ToolRuntime` 提供工作区、取消或会话等执行上下文，`StructuredTool` 是交给 LangChain 的适配对象。schema 应从同一领域定义生成或在一个边界转换，不能分别维护两份。契约测试验证名称、字段、默认值和错误语义一致。

### Q079 为什么工具 artifact 不直接拼入模型可见文本？
- **考察点**：数据通道和上下文治理。
- **知识点**：模型文本；artifact；大对象；敏感信息；UI 展示。
- **复习巩固**：列三类适合 artifact、不适合模型上下文的内容。
- **参考回答（45 秒）**：artifact 可能体积大、含二进制或敏感元数据，直接拼入文本会浪费 token、引入注入并破坏结构。模型只接收经过裁剪和标注的摘要或引用，完整 artifact 留给 UI、下载或后续受控工具。两条通道都保留关联 ID 便于审计。

### Q080 设计一个最小 Harness，哪些状态必须是 canonical，哪些只是 UI 投影？
- **考察点**：Agent 产品运行时设计。
- **知识点**：message/tool 配对；run state；budget；approval；projection。
- **复习巩固**：画最小事件模型和状态不变量。
- **参考回答（设计题口径，90 秒）**：canonical 状态至少包含消息与 tool call/result 配对、运行状态、版本、预算、取消和审批决定，以及外部副作用引用。UI 的流式文本片段、加载动画、折叠状态和局部进度只是投影。Harness 负责把模型与工具事件持久化、校验终止、处理取消和恢复，再向 UI 发稳定事件。第一版不自研模型 loop，先复用框架执行语义。

### Q081 JSONL session 为什么适合 replay、branch、export？它的空间和查询缺点？
- **考察点**：日志型存储取舍。
- **知识点**：append-only；顺序；事件；分支父指针；压缩；索引。
- **复习巩固**：手工写五条会话事件并重放。
- **参考回答（45 秒）**：JSONL 追加简单、每条事件独立，保留顺序和父关系后容易重放、复制分支和导出。缺点是重复状态占空间，随机查询、聚合和并发写较弱，文件损坏与压缩也要处理。适合本地单用户会话，团队平台需数据库、索引和事务。

### Q082 compaction 在何时触发，为什么 auth/quota/cancel 不能误判成 context overflow？
- **考察点**：错误分类和压缩触发条件。
- **知识点**：context window；阈值；provider error；保留近期；不可重试。
- **复习巩固**：查看 context overflow 分类与 compaction 测试。
- **参考回答（60 秒）**：压缩应在估算上下文接近窗口或 provider 明确返回上下文超限时触发，摘要旧消息并保留近期上下文、目标和工具配对。认证、额度和取消需要各自处理，误判成 overflow 会白白再次调用模型、掩盖真实错误，甚至在取消后继续工作。因此错误分类要依据 provider 结构化信息而非任意失败文本。

### Q083 取消发生在 shell tool 运行时，如何清理子进程、补齐 ToolMessage 并保证 session 可 replay？
- **考察点**：取消链路是否闭合。
- **知识点**：取消传播；进程组；finally；synthetic result；持久化。
- **复习巩固**：定位 shell 取消和 ToolMessage 配对测试。
- **参考回答（90 秒）**：取消从 session 传播到 Harness 与 tool，shell 应终止进程组并等待回收，finally 释放文件与锁。若模型已发出 tool call，session 必须持久化一个明确的取消或失败 ToolMessage，保证消息协议完整；随后写终态和已知输出。重放时看到的是一次已结束的取消，不会误以为工具仍运行。跨进程恢复仍需外部任务协议，不能只靠当前子进程句柄。

### Q084 Todo、HITL、Goal 为什么不要塞进同一个大状态对象？
- **考察点**：状态职责拆分。
- **知识点**：生命周期；权限；事件；独立演进；不变量。
- **复习巩固**：列三者的创建者、更新者和终止条件。
- **参考回答（45 秒）**：Todo 是模型工作清单，HITL 是图暂停与人类决定，Goal 是产品级长目标和自动继续状态。它们生命周期、写权限和恢复语义不同，塞进一个对象会让任一更新触发无关冲突，并难以审计。保持独立，再通过事件和关联 ID 协作更清楚。

### Q085 Goal 自动继续为什么有次数和无进展阈值，恢复时为何归一为 paused？
- **考察点**：长循环终止与恢复安全。
- **知识点**：bounded loop；progress；stuck；paused；显式恢复。
- **复习巩固**：阅读 GoalController 和 session 恢复测试。
- **参考回答（90 秒）**：自动继续若没有次数和无进展限制，模型可能在相同错误上无限消耗。系统比较持久化动作与进展，达到阈值就停并要求用户介入。进程恢复时无法证明中断前调用是否仍有效，也不应后台自行续跑，所以活动 Goal 归一为 paused，等待显式恢复。

### Q086 supervisor-as-tool 如何做 subagent，为什么 child 不继承 checkpointer 和 task？
- **考察点**：子 Agent 隔离和委派契约。
- **知识点**：tool delegation；能力裁剪；独立上下文；checkpointer；task identity。
- **复习巩固**：定位 subagent profile 和 supervisor tool 测试。
- **参考回答（60 秒）**：父 Agent 通过受控工具提交任务，supervisor 根据 profile 创建能力受限的 child，并把结果作为工具返回。child 不继承父 checkpointer 和运行 task，避免两条图共享内部执行状态、错误恢复彼此污染，也避免子任务直接获得父级全部能力。需要持久化时应设计明确的子任务协议，而非隐式继承。

### Q087 capability intersection 和真正安全隔离有什么差异？
- **考察点**：逻辑授权与执行隔离边界。
- **知识点**：allowlist；交集；OS sandbox；凭据；网络。
- **复习巩固**：为文件读、shell 和网络分别判断两层保护。
- **参考回答（90 秒）**：capability intersection 只让 child 获得父权限与 profile 权限的交集，减少可调用工具，是应用层最小授权。它不能阻止一个已获 shell 工具的进程访问 OS 允许的文件或网络。真正隔离还需要容器、系统调用、网络、文件和凭据边界。

### Q088 workspace path 的 lexical/resolved 检查分别防哪类路径逃逸？
- **考察点**：路径安全细节。
- **知识点**：`..`；绝对路径；symlink；resolve；TOCTOU。
- **复习巩固**：构造 `../` 和工作区内 symlink 指向外部两个样例。
- **参考回答（45 秒）**：lexical 检查拒绝明显的绝对路径和 `..` 越界，resolved 检查解析符号链接后的真实路径仍在工作区内，并关注最终写入目标的 symlink。两者结合覆盖文本路径与真实指向差异，但仍有竞态和 shell 绕过，所以不能称为完整沙箱。

### Q089 为什么“shell 不是 sandbox”，若面向不可信代码需补什么？
- **考察点**：系统安全边界是否清醒。
- **知识点**：进程权限；容器；seccomp；网络；资源；临时凭据。
- **复习巩固**：列文件、进程、网络、资源和秘密五类隔离。
- **参考回答（90 秒）**：shell 继承宿主进程的 OS 权限，应用层路径检查挡不住任意命令读取其他路径、发网络请求或启动进程。运行不可信代码需独立容器或微虚机、只读或临时文件系统、网络默认拒绝、系统调用限制、CPU/内存/时间配额和短期凭据，并在外层审计与销毁环境。Forge 当前能力不能包装成这些生产隔离。

### Q090 FileOperationQueue 为什么不只是每个工具一个 `asyncio.Lock`？跨进程怎么办？
- **考察点**：共享资源并发控制。
- **知识点**：跨工具冲突；路径粒度；顺序；事件循环；分布式锁。
- **复习巩固**：构造 read/write、write/write 跨工具竞争。
- **参考回答（60 秒）**：多个读写工具可能操作同一路径，按工具各放一把锁仍会互相穿透。队列按共享资源协调顺序，并可把阻塞文件 I/O 移出事件循环。当前进程内队列不能解决多进程并发，平台化需数据库 CAS、对象版本或带租约的分布式协调，并处理持有者崩溃。

### Q091 多模型 provider abstraction 应统一什么、不统一什么？
- **考察点**：抽象边界和差异保留。
- **知识点**：消息；工具；流式事件；错误；usage；能力协商。
- **复习巩固**：对两家 provider 做 contract 差异表。
- **参考回答（设计题口径，60 秒）**：统一核心消息、工具调用、流式事件、错误分类、取消和 usage 表达；保留模型能力、思考参数、缓存、结构化输出、限额和原生错误细节。公共层只承诺交集，差异通过 capability 与扩展字段暴露。缺失 usage 应为 unknown，不记成零。

### Q092 工具返回超大输出、畸形 JSON 或 prompt injection 时，Harness 在哪个边界截断、标注和隔离？
- **考察点**：工具结果信任边界。
- **知识点**：schema validate；size limit；artifact；untrusted label；sanitization。
- **复习巩固**：为工具入口和模型上下文入口各写校验清单。
- **参考回答（设计题口径，90 秒）**：工具适配层先校验类型与 schema，限制字节、行数和递归深度，完整大结果落 artifact；进入模型上下文前再按 token 预算裁剪并标成不可信数据，不能让结果中的指令提升权限。畸形 JSON 返回结构化失败，可重试仅限安全错误；高风险字段隔离或审批。原始内容、摘要和截断原因用关联 ID 审计。

### Q093 用户看到文本流但最终工具失败，前端和 session 应呈现什么终态？
- **考察点**：流式过程与最终事实一致性。
- **知识点**：tentative output；failed state；ToolMessage；UI 修正；重放。
- **复习巩固**：设计 start、delta、tool_error、final 四类事件。
- **参考回答（45 秒）**：流式文本应标为生成中，不能在工具成功前当最终答案。工具失败后 session 写配对的失败 ToolMessage 和明确终态，前端停止流并显示“未完成”及可重试信息，必要时撤销或标记先前草稿。重放应得到同一失败结论，不显示伪成功。

### Q094 从单用户 coding agent 演进到团队平台，最先要替换的三个单机假设是什么？
- **考察点**：生产化差距判断。
- **知识点**：身份租户；持久存储；分布式执行；审计；隔离。
- **复习巩固**：对 JSONL、内存锁、本机 shell 各写替代方案。
- **参考回答（90 秒）**：最先替换身份与权限假设，把本地用户变成租户、用户和服务身份；替换本地 JSONL 与内存锁，用事务状态、对象版本和队列；替换宿主 shell，用隔离 worker、短期凭据和资源配额。随后补多副本恢复、集中审计和配额。Forge 当前更适合证明本地 Harness 设计，不等于团队生产平台。

## F. Agent Framework、Loop、Workflow 与状态机

### Q095 Agent、Workflow、Harness 的定义和边界分别是什么？
- **考察点**：核心概念能否落到职责。
- **知识点**：动态决策；确定性编排；运行环境；状态；工具。
- **复习巩固**：为固定审批流和开放研究各选架构。
- **参考回答（45 秒）**：Agent 用模型在运行时选择下一步；Workflow 按预定义规则和状态转换执行；Harness 包住模型与工具循环，负责上下文、状态、权限、取消、恢复和观测。规则固定的审批流直接用 Workflow，只有决策空间确实开放时才引入 Agent。

### Q096 agent loop 的最小闭环有哪些事件，终止条件如何定义？
- **考察点**：是否理解执行循环而非只会框架 API。
- **知识点**：input；model；tool call；tool result；state；stop。
- **复习巩固**：手画一轮含工具失败的事件序列。
- **参考回答（60 秒）**：最小闭环是接收输入与状态、构建上下文、模型决策、校验并执行工具、写入结果，再判断是否继续。终止包括模型给出合格 final、达到目标门禁、用户取消、预算耗尽、不可恢复失败和无进展阈值。每次 tool call 必须有结果事件，终态要持久化。

### Q097 Planner、Executor、Verifier 三角色何时有价值，何时会只增加 latency？
- **考察点**：多阶段设计取舍。
- **知识点**：复杂任务；独立验证；上下文；协调成本；基线。
- **复习巩固**：选简单问答和长研究做对比。
- **参考回答（60 秒）**：任务可拆、执行步骤昂贵且验证标准独立时，三角色能减少盲目执行。短任务、工具少、验证只是重复读答案时，会增加模型调用和上下文损失。先以单 Agent 或 Workflow 做基线，只有完成率或风险明显改善才拆角色。

### Q098 把“查数并生成报告”建成状态机，列出状态、转换、可恢复点和不可逆操作。
- **考察点**：系统设计能否具体到状态。
- **知识点**：clarify；plan；authorize；execute；verify；report；checkpoint。
- **复习巩固**：闭卷画状态图并标出写操作。
- **参考回答（设计题口径，90 秒）**：状态可设 received、clarifying、planned、authorized、querying、verifying、reporting、completed/failed/cancelled。澄清、计划、查询结果和报告草稿后均可 checkpoint；每次转换带版本和 attempt。只读 SQL 可安全有限重试，导出、发布和外部通知属于不可逆或高风险操作，执行前审批并用幂等键，执行后不能简单回滚整条流程。

### Q099 为什么模型自然语言不能直接成为工作流状态转换的唯一依据？
- **考察点**：软判断与硬状态的边界。
- **知识点**：非确定性；schema；服务端校验；权限；重放。
- **复习巩固**：把“已完成”改成可机检条件。
- **参考回答（30 秒）**：自然语言可能含糊、被注入或与真实副作用不一致。模型只能提出结构化意图，服务端依据当前版本、权限、产物和门禁执行转换。这样状态可重放、可审计，也能拒绝非法和迟到转换。

### Q100 一个带副作用 tool 的幂等键如何构造？请求重放与业务重复如何区分？
- **考察点**：副作用去重设计。
- **知识点**：tenant；operation；business key；payload hash；attempt；result store。
- **复习巩固**：为“发布任务”设计键和冲突响应。
- **参考回答（60 秒）**：键通常包含租户、业务操作类型、稳定业务对象和请求语义 hash，由调用方生成并在服务端唯一约束。同一键同一 payload 返回已有结果，是请求重放；同一键不同 payload 要冲突拒绝；业务上允许再次执行时使用新的业务版本或显式 operation ID，不能靠重试次数混淆。

### Q101 节点超时后重试，如何避免上次已成功但响应丢失造成重复扣费或重复发消息？
- **考察点**：不确定执行结果处理。
- **知识点**：幂等键；查询确认；outbox；unknown state；人工接管。
- **复习巩固**：画“请求成功、响应丢失”的时序。
- **参考回答（设计题口径，90 秒）**：调用前持久化 operation ID 与 intent，外部服务支持幂等键就复用同一键；超时后先按 operation ID 查询结果，再决定补发。自有系统用事务 outbox 把状态与消息意图原子记录。若外部既不幂等也不可查询，状态标 unknown 并人工处理，不能自动重试高风险动作。

### Q102 长任务如何拆成任务、持久化进度、通知用户和支持取消？
- **考察点**：长任务后端设计。
- **知识点**：job；step；checkpoint；queue；SSE；cancel token。
- **复习巩固**：画 API、任务表、队列、worker、事件流。
- **参考回答（设计题口径，90 秒）**：入口创建 job_id 和版本化任务记录，按可重试且可验收的 step 拆分，队列交给 worker。每步提交 checkpoint、attempt、进度和产物引用；SSE 只推送事件，断线可按 event ID replay。取消写持久化意图并传播到运行中工具，worker 在安全点收口，已发生副作用单独记录和补偿。

### Q103 并行子任务的 join 条件如何选，部分失败时是否应提前返回？
- **考察点**：fan-out/fan-in 语义。
- **知识点**：all；quorum；first-success；deadline；必要任务。
- **复习巩固**：为多源检索和报表分区计算各定 join。
- **参考回答（60 秒）**：join 取决于业务完备性：所有分区都必需用 all；多来源冗余可用 quorum 或 first-success；有截止时间则到 deadline 汇总。部分失败是否提前返回要看失败任务是否关键，返回时必须标覆盖范围和缺口。取消剩余任务也要安全清理。

### Q104 多租户下如何做任务队列的公平性、优先级、限流和背压？
- **考察点**：调度平台思维。
- **知识点**：tenant queue；weighted fair；quota；admission；backpressure。
- **复习巩固**：为免费和高优租户设计权重与硬上限。
- **参考回答（设计题口径，90 秒）**：先做租户级并发、QPS、token 与工具配额，再用加权公平队列调度，优先级只在租户额度内生效。入口做准入控制，队列长度和预计等待超阈值就降级或拒绝；worker 与模型网关反馈容量形成背压。预留系统和紧急通道，但不能让单大客户长期饿死其他租户。

### Q105 ReAct、plan-and-execute、deterministic workflow 的取舍是什么？
- **考察点**：常见编排模式理解。
- **知识点**：逐步决策；先规划；固定路径；可控性；成本。
- **复习巩固**：分别给一个适用场景和失败模式。
- **参考回答（45 秒）**：ReAct 适合信息逐步显现但容易循环；plan-and-execute 适合可拆长任务，但计划可能过期；确定性 Workflow 最稳、易审计，适合规则和审批明确的流程。实际可混用：Workflow 管外层状态，局部开放节点用 Agent。

### Q106 多 Agent 的共享状态、消息协议和冲突解决怎样设计？
- **考察点**：多 Agent 一致性设计。
- **知识点**：canonical store；typed message；ownership；version；reducer。
- **复习巩固**：画两个 Worker 更新同一任务的冲突流程。
- **参考回答（设计题口径，90 秒）**：共享状态放在单一持久存储，消息包含 task、assignment、attempt、schema version 和产物引用。每块状态有明确 owner，更新通过 reducer、事务或 CAS 校验，旧版本和越权 patch 拒绝。冲突能合并的按确定性规则合并，语义冲突转 reviewer 或人工，不能用最后写入覆盖。

### Q107 模型反复调用同一工具但没有进展，如何检测、停止并给出可行动错误？
- **考察点**：循环治理。
- **知识点**：action fingerprint；state delta；预算；重复阈值；诊断。
- **复习巩固**：设计相同参数和近似参数两种检测。
- **参考回答（90 秒）**：记录工具名、规范化参数、结果摘要和关键状态变化。连续相同 fingerprint、错误类别不变或目标状态无变化达到阈值就停止，写明已尝试动作、最后错误和建议补充。允许模型基于新证据有限重试，但次数、时间和成本都有硬预算。

### Q108 哪些节点需要人工审批？审批结果如何绑定请求、版本和有效期？
- **考察点**：人机协作与防重放。
- **知识点**：风险分级；写操作；敏感数据；approval token；expiry。
- **复习巩固**：为 SQL 导出和任务发布设计审批对象。
- **参考回答（60 秒）**：高风险写操作、敏感数据导出、超预算任务和低置信不可逆动作需审批。审批绑定租户、用户、具体操作、参数 hash、资源版本和有效期，只能消费一次；任何参数或版本变化都重新审批。审批人、决定和执行结果进入审计。

### Q109 DAG 和状态机的区别，动态任务拆分时为什么纯 DAG 不够？
- **考察点**：编排模型理解。
- **知识点**：静态依赖；状态转换；循环；动态节点；事件。
- **复习巩固**：把固定 ETL 与开放研究做对比图。
- **参考回答（45 秒）**：DAG 擅长预先已知且无环的依赖，状态机表达事件驱动的状态、循环、暂停与恢复。动态拆分会在运行中新增任务、重试和人工分支，纯静态 DAG 难表示。可以用 DAG 调度固定计算，用状态机管理 Agent 运行生命周期。

### Q110 一次用户请求的 trace/span 应覆盖哪些 Agent 与工具事件？
- **考察点**：可观测设计。
- **知识点**：request；model；retrieval；tool；queue；state transition；cost。
- **复习巩固**：为一次问数请求画 trace 树。
- **参考回答（60 秒）**：根 span 关联 request、tenant、session 和版本；子 span 覆盖排队、上下文构建、模型调用、检索、每次工具、状态转换、审批等待和流式发送。记录耗时、错误类别、重试、token 与成本，但敏感 prompt、SQL 和结果需脱敏或只存 hash 与安全引用。

### Q111 Prompt、tool schema、模型、知识库和 workflow 如何版本化并可回放？
- **考察点**：多资产版本一致性。
- **知识点**：immutable version；manifest；snapshot；session pin；replay。
- **复习巩固**：写一次运行 manifest 的字段。
- **参考回答（设计题口径，90 秒）**：每类资产用不可变版本或内容 hash，发布生成运行 manifest。session 创建时固定模型、Prompt、tool schema、workflow 和知识库 snapshot，运行事件保存 manifest ID。回放使用同版本与原始输入，外部副作用改为 mock 或只读验证。资产下线保留可审计元数据，迁移需显式兼容。

### Q112 规划模型不可用时如何降级，哪些请求直接失败更安全？
- **考察点**：降级边界。
- **知识点**：fallback model；固定流程；只读；高风险；诚实失败。
- **复习巩固**：将请求按只读低风险和写入高风险分类。
- **参考回答（60 秒）**：低风险、意图明确的请求可切备用模型或固定 Workflow，并降低能力、标记降级；已有计划的只读步骤可继续。需要复杂规划、敏感权限判断或不可逆写操作的请求直接失败或转人工更安全。降级要记录模型与策略版本，不能静默让质量变化。

### Q113 为什么框架不是生产能力本身？换框架时哪些业务 contract 必须不变？
- **考察点**：是否避免框架崇拜。
- **知识点**：运行契约；工具；状态；事件；权限；评测。
- **复习巩固**：列出与 LangGraph 无关的五个业务不变量。
- **参考回答（45 秒）**：框架提供图或循环原语，生产能力还依赖权限、状态、恢复、观测、评测和运维。换框架时工具 schema 与错误语义、业务状态机、幂等键、审计事件、资产版本和评测基线应保持不变。否则迁移无法判断行为是否等价。

### Q114 如何为状态机写最小测试，覆盖非法转移、恢复和重复消息？
- **考察点**：状态机测试方法。
- **知识点**：transition table；invariant；property；replay；duplicate。
- **复习巩固**：为一个任务状态写表驱动测试。
- **参考回答（60 秒）**：用表驱动覆盖每个合法转换和关键非法转换，断言版本、owner 和终态不变量；在每个 checkpoint 恢复后继续执行；把同一消息重复、乱序和旧 attempt 注入，结果应幂等或拒绝。再加一个从事件重放到最终状态的端到端用例。

### Q115 Agent 运行状态写 DB、发 MQ、写对象存储时，如何避免分布式事务幻觉？
- **考察点**：跨系统一致性认知。
- **知识点**：local transaction；outbox；idempotent consumer；saga；reconciliation。
- **复习巩固**：画 DB 状态和 MQ 事件的 outbox 流程。
- **参考回答（设计题口径，90 秒）**：不假设三个系统能原子提交。DB 事务内更新状态并写 outbox，后台可靠发布 MQ；消费者按 event ID 幂等，写对象存储后记录引用。跨步骤用 saga 和补偿，定期对账修复悬挂状态。对外只有在可验证提交点后才显示成功。

### Q116 at-most-once、at-least-once、exactly-once 在 Agent 工具调用中各自能承诺到什么层？
- **考察点**：交付语义是否准确。
- **知识点**：delivery；effect；dedup；idempotency；scope。
- **复习巩固**：分别用搜索和扣费举例。
- **参考回答（60 秒）**：at-most-once 可能丢但不重发；at-least-once 允许重复，需幂等或去重；所谓 exactly-once 通常只在某个受控存储或事务边界内成立。Agent 能保证消息和状态处理协议，不能替外部 API 保证业务副作用 exactly-once，除非对方提供幂等键或可查询事务。

### Q117 如何判断一个业务该做 Chat Agent、表单 Workflow 还是 API 自动化？
- **考察点**：产品形态选择。
- **知识点**：意图开放度；输入结构；风险；频率；可解释。
- **复习巩固**：对报销、查数、批量同步三场景选择。
- **参考回答（45 秒）**：需求开放、需多轮澄清时用 Chat Agent；字段明确、步骤固定且需审批时用表单 Workflow；高频稳定、机器间调用用 API 自动化。风险越高越偏结构化和确定性。也可让 Chat 只负责收集意图，再进入 Workflow。

### Q118 设计故障注入演练，验证取消、重试、恢复和人工接管。
- **考察点**：可靠性验证能否落地。
- **知识点**：kill worker；timeout；duplicate；network partition；invariant。
- **复习巩固**：写四个故障点和预期状态。
- **参考回答（设计题口径，90 秒）**：在模型前后、工具执行中、状态提交前后和 SSE 断线处注入超时、进程 kill、重复消息与网络失败。验收不只看恢复成功，还看无伪成功、无重复副作用、资源释放、审计完整和可人工接管。每次演练固定版本和种子，检查任务最终状态与外部系统对账。

## G. Tool Calling、MCP、Skill、Prompt 与上下文

### Q119 一个高质量 tool schema 应包含哪些字段？
- **考察点**：工具接口设计基础。
- **知识点**：name；description；type；required；enum；constraint；result；error。
- **复习巩固**：为元数据查询工具写一份 schema。
- **参考回答（45 秒）**：名称和描述要明确单一职责，输入写类型、必填、枚举、范围、格式和字段关系，并说明前置条件、副作用与权限。输出和错误也要结构化。描述过宽会让模型误选工具，真正的安全边界仍由程序校验。

### Q120 工具入参如何在 schema 边界校验，为什么 prompt 约束不能替代程序校验？
- **考察点**：信任边界意识。
- **知识点**：parse；validate；normalize；reject；policy；error recovery。
- **复习巩固**：构造类型正确但业务危险的参数。
- **参考回答（45 秒）**：先解析并做类型、范围、枚举和格式校验，再做权限、资源存在性和业务 policy 检查，只对无歧义输入窄化归一。Prompt 是概率性建议，模型升级或注入都可能绕过，不能保护数据库和副作用。拒绝时返回字段级原因与安全修复路径。

### Q121 模型生成“看似合法、实际危险”的参数，如何在 policy 层拒绝并给出恢复路径？
- **考察点**：schema 与语义安全的区别。
- **知识点**：semantic policy；risk score；dry-run；approval；least privilege。
- **复习巩固**：用全表导出和跨租户查询举例。
- **参考回答（设计题口径，90 秒）**：schema 通过后，policy 结合用户、租户、资源、动作、数据级别和预计影响判断。跨租户、超范围扫描或高风险写入直接拒绝；可收窄的返回允许范围或 dry-run，需授权的生成绑定参数 hash 的审批请求。不能让模型修改 policy 或换工具绕过。

### Q122 MCP 的 Host、Client、Server 各承担什么，Host 为什么是安全策略的关键位置？
- **考察点**：MCP 架构理解。
- **知识点**：Host；Client；Server；capability；consent；aggregation。
- **复习巩固**：按官方架构画一 Host 多 Client/Server。
- **参考回答（45 秒）**：Host 承载用户体验和 Agent，管理多个 MCP Client；Client 与一个 Server 建会话并协商能力；Server 暴露 tools、resources、prompts。Host 掌握用户身份、上下文注入、权限与确认，也决定哪些 Server 能互通，所以安全策略不能下放给任意 Server。

### Q123 MCP 的 prompts、resources、tools 的控制权有何差异？
- **考察点**：MCP primitive 边界。
- **知识点**：user-controlled；application-controlled；model-controlled；read；execute。
- **复习巩固**：查当前官方规范版本并准备例子。
- **参考回答（45 秒）**：prompts 通常由用户显式选择，resources 由应用决定如何纳入上下文，tools 可由模型请求调用但最终仍受 Host 策略与确认控制。resource 偏读取上下文，tool 会执行动作，风险更高。规范会演进，面试时说明依据版本。

### Q124 把内部 REST API 包装成 MCP tool，如何处理认证、分页、错误码和版本演进？
- **考察点**：协议适配工程能力。
- **知识点**：identity propagation；cursor；typed error；schema version；compatibility。
- **复习巩固**：为列表查询 API 设计 tool 输入输出。
- **参考回答（设计题口径，60 秒）**：Host 到 Server 传递可验证用户或服务身份，Server 再换取最小权限凭据，不把密钥给模型。分页暴露 cursor 与 limit，限制最大页数；REST 错误映射为可重试、权限、参数和业务错误。schema 采用向后兼容新增，破坏性变更并行新版本并给下线期。

### Q125 如何防 tool poisoning、提示注入经 tool result 传播、跨工具数据外泄？
- **考察点**：工具供应链安全。
- **知识点**：registry trust；untrusted data；capability；egress；taint；approval。
- **复习巩固**：画恶意文档到导出工具的攻击链。
- **参考回答（设计题口径，90 秒）**：工具接入前审查来源、schema、权限和版本，运行时按能力 allowlist。所有 tool result 默认是不可信数据，和系统指令隔离，敏感数据标记不能流入未授权工具；跨工具调用由 policy 检查数据级别、目的和目标域。高风险动作审批，网络出口与凭据最小化，审计完整链路。

### Q126 一个 remote MCP server 如何做 OAuth/身份映射、最小权限与审计？
- **考察点**：企业远程工具认证设计。
- **知识点**：OAuth；delegation；audience；scope；short-lived token；audit。
- **复习巩固**：画用户、Host、授权服务器、MCP Server 流程。
- **参考回答（设计题口径，90 秒）**：Host 发起 OAuth 授权并获得面向特定 Server、audience 和 scope 的短期 token，Server 校验后映射为内部用户与租户。每个工具再做资源级授权，服务账号不能替代用户权限。审计记录 actor、client、tool、参数摘要、资源、授权决策和结果，token 不进模型上下文或普通日志。

### Q127 Skill、Tool、Prompt template、Workflow node 的适用边界？
- **考察点**：常见复用单元能否区分。
- **知识点**：能力；方法；模板；编排节点；执行。
- **复习巩固**：把“查询天气并生成报告”拆成四类资产。
- **参考回答（45 秒）**：Tool 是原子可执行能力；Skill 是完成某类任务的说明、约束和资源组合；Prompt template 是一次模型输入的可复用结构；Workflow node 是状态机中的执行步骤。Skill 可指导使用多个 tool，node 可调用模型或 tool，四者不应互相冒充安全边界。

### Q128 如何让 Skill 可发现但不让模型每轮背上数百个工具描述？
- **考察点**：渐进式发现和上下文成本。
- **知识点**：catalog；metadata；router；progressive disclosure；cache。
- **复习巩固**：设计两级目录和加载协议。
- **参考回答（60 秒）**：常驻只放精简的 Skill 目录与触发元数据，先按意图、权限和场景筛出候选，再按需加载完整说明和工具 schema。稳定目录可缓存，动态权限在加载时复查。还要评测召回错 Skill 和漏 Skill，不能只省 token。

### Q129 工具很多且相似时，如何做分层发现、路由与工具选择评测？
- **考察点**：大规模工具生态治理。
- **知识点**：taxonomy；coarse router；fine selection；negative examples；top-k。
- **复习巩固**：为十个数据工具构建层级和混淆集。
- **参考回答（设计题口径，90 秒）**：先按领域、风险和资源类型建立目录，粗路由选工具组，再在授权后的少量 schema 中细选。描述明确排除项和相似工具差异，必要时用规则处理高风险选择。评测包含正确工具、无需工具、相似负例、参数正确率和误调用成本，逐层定位漏召回或误选择。

### Q130 system prompt、developer instruction、user input、tool result 的优先级和信任等级？
- **考察点**：指令层级与数据边界。
- **知识点**：instruction hierarchy；trusted policy；user goal；untrusted result；conflict。
- **复习巩固**：构造 tool result 注入并口述处理。
- **参考回答（45 秒）**：系统和开发指令承载更高优先级的产品规则，用户输入给目标但不能越权，tool result 默认是外部数据而非新指令。冲突时遵循更高层规则，同时程序 policy 仍是最终硬边界。不要把层级当安全隔离，敏感动作还要鉴权和审批。

### Q131 如何用 JSON schema、repair、重试和 fallback 处理结构化输出？
- **考察点**：结构化生成可靠性。
- **知识点**：native schema；validate；bounded retry；repair；fallback。
- **复习巩固**：写一个三分支失败策略。
- **参考回答（60 秒）**：优先使用模型原生结构化输出并在服务端校验。轻微可确定的格式错误可做窄 repair；语义缺字段时带校验错误有限重试；重复失败则回退到更简单 schema、规则解析或人工确认。原始输出和修复步骤留审计，不能把猜测修成合法数据。

### Q132 结构化输出反复不合法，何时重试，何时降级为人工确认？
- **考察点**：重试停止条件。
- **知识点**：transient；deterministic error；retry budget；risk；human fallback。
- **复习巩固**：为低风险分类和高风险发布分别定策略。
- **参考回答（90 秒）**：若错误可明确反馈、模型有机会修正且动作无副作用，可在固定次数内重试；同类错误重复、输入本身含糊或预算接近上限就停止。低风险可降级 unknown 或规则路径，高风险参数和审批请求转人工，不能为得到合法 JSON 无限调用。

### Q133 上下文工程与“把所有资料塞 prompt”有什么区别？
- **考察点**：上下文治理理解。
- **知识点**：selection；ordering；trust；compression；budget；freshness。
- **复习巩固**：对一次问数请求排上下文优先级。
- **参考回答（45 秒）**：上下文工程会按目标、权限、相关性、时效和 token 预算选择、排序与标注信息，并保留未完成动作和关键约束。全部塞入会放大噪声、冲突、注入和成本，长窗口也不会自动解决这些问题。每段上下文还要能追溯来源。

### Q134 短期会话、摘要、长期记忆、用户画像各应存什么，不应存什么？
- **考察点**：多层 memory 设计。
- **知识点**：turn state；summary；durable fact；profile；consent；expiry。
- **复习巩固**：将十类信息分层并标删除策略。
- **参考回答（60 秒）**：短期会话存当前任务细节，摘要保留目标、约束、决定和未完成项；长期记忆只存经确认且跨任务稳定的信息；画像存获授权的偏好或业务属性。临时猜测、敏感原文、半成品和可从权威源实时查询的事实不应长期保存。所有层都要有来源、过期、删除和审计。

### Q135 用户纠正历史偏好后，如何做记忆冲突、过期、删除和审计？
- **考察点**：记忆生命周期治理。
- **知识点**：version；source；supersede；tombstone；audit；consent。
- **复习巩固**：设计一次“旧偏好被新偏好替换”的事件。
- **参考回答（设计题口径，90 秒）**：新记忆不直接覆盖旧值，而是带来源、时间和版本，将旧项标 superseded；读取选择当前有效且置信更高的记录。用户删除时写 tombstone 并清理索引、缓存和派生画像，审计只保留合规允许的最小元数据。冲突无法判断就询问，不让模型自行选。

### Q136 如何给上下文分配预算，保证目标、约束、未完成动作和证据优先？
- **考察点**：上下文预算策略。
- **知识点**：reserved budget；priority；recency；evidence；tool output truncation。
- **复习巩固**：为 32K 窗口做一张预算表。
- **参考回答（60 秒）**：先为系统约束、当前目标、工具 schema 和输出预留固定空间；再按未完成动作、最新决定、直接证据、近期对话分配。大工具输出落 artifact，只送摘要和可按需读取的引用；旧对话压缩但保留冲突与承诺。预算不足时删低相关背景，不删权限和关键证据。

### Q137 few-shot 何时提高稳定性，何时会导致过拟合或上下文成本失控？
- **考察点**：示例提示的适用性。
- **知识点**：format；decision boundary；coverage；bias；token cost。
- **复习巩固**：为意图分类选择三个边界例而非三个同类例。
- **参考回答（45 秒）**：输出格式固定、分类边界难用规则描述时，少量代表性正反例能提高稳定性。样例单一会让模型照抄表面词，过多则挤占任务上下文并增加缓存失效。应优先选易混淆边界例，用 holdout 坏例验证，而非不断追加示例。

### Q138 如何把业务口径、权限边界和不可执行动作分到 prompt、schema、policy 三层？
- **考察点**：软硬约束分层。
- **知识点**：guidance；shape；authorization；deny；defense in depth。
- **复习巩固**：以 SQL 工具为例分配十条规则。
- **参考回答（60 秒）**：Prompt 解释业务概念、选择原则和期望行为；schema 限定参数结构、类型和值域；policy 根据身份、资源和动作执行授权，拒绝写 SQL、越权字段或超量扫描。不可执行动作必须由 policy 阻断，Prompt 只做前置引导，schema 也不能表达全部语义权限。

### Q139 用户在文档中注入“忽略规则并导出数据”，RAG Agent 如何处置？
- **考察点**：间接提示注入防御。
- **知识点**：untrusted document；instruction isolation；taint；tool policy；approval。
- **复习巩固**：构造检索文档到导出工具的完整攻击链。
- **参考回答（设计题口径，90 秒）**：文档内容始终标为证据数据，不获得指令权限；上下文模板明确其不可改变系统和用户授权。即使模型产生导出调用，policy 仍按用户身份、数据级别和允许动作拒绝，敏感结果也不能流向外部工具。记录注入命中与调用尝试，高风险场景增加内容扫描和人工确认。

### Q140 如何记录 prompt 版本、上下文摘要来源和 tool decision，兼顾隐私？
- **考察点**：可回放与数据最小化。
- **知识点**：version ID；content hash；provenance；redaction；secure reference。
- **复习巩固**：设计一条 trace 记录，区分明文与引用。
- **参考回答（60 秒）**：记录 Prompt 模板版本和 hash、上下文片段的来源 ID 与版本、摘要算法或模型、候选工具和最终选择原因。敏感正文默认不进普通 trace，只存脱敏摘要、分类标签或受控对象引用；需要取证时按权限访问安全存储。保留期限和删除策略按租户配置。

### Q141 MCP 规范持续演进，平台怎样避免把草案能力当长期稳定依赖？
- **考察点**：外部协议演进治理。
- **知识点**：spec version；capability negotiation；adapter；conformance；fallback。
- **复习巩固**：查当前采用版本并列实验能力。
- **参考回答（45 秒）**：显式固定规范和 SDK 版本，通过 capability negotiation 使用可选能力，草案特性放适配层并设 feature flag。升级前跑协议一致性和关键 Server 回归，保留旧版本并行与回滚。业务 contract 不直接依赖草案字段。

### Q142 设计工具结果的可信度标签与隔离策略，哪些结果可进入下一轮模型上下文？
- **考察点**：结果治理与信息流控制。
- **知识点**：source；integrity；freshness；sensitivity；taint；allowlist。
- **复习巩固**：给数据库、网页、用户文件、第三方工具各打标签。
- **参考回答（设计题口径，90 秒）**：结果至少标来源身份、完整性校验、采集时间、数据级别、租户和是否含外部指令。只有当前请求授权、格式校验通过且经预算裁剪的内容进入上下文；敏感原文、未知二进制和高风险注入留在隔离 artifact。模型看到的是带标签的数据片段，跨工具流转仍由 policy 再校验。

## H. RAG、知识库与检索

### Q143 RAG 全链路有哪些环节，哪个环节最容易被“回答看起来对”掩盖？
- **考察点**：能否分层理解 RAG 质量。
- **知识点**：ingestion；chunk；index；retrieve；rerank；pack；generate；cite。
- **复习巩固**：画全链路并为每层写一个指标。
- **参考回答（45 秒）**：链路包含解析、切分、索引、查询理解、召回、融合、重排、上下文打包、生成和引用。最容易被流畅答案掩盖的是证据支持与口径正确性，模型可能靠常识答对或引用无关段落。评测要分别看召回、回答和引用，不只看成文质量。

### Q144 embedding 模型、向量索引、向量数据库分别是什么？
- **考察点**：向量检索基础概念。
- **知识点**：representation；ANN；storage；metadata；filter；lifecycle。
- **复习巩固**：用 Agentic RAG 的 embedding、FAISS、Node Store 映射概念。
- **参考回答（45 秒）**：embedding 模型把文本映射到向量空间；向量索引组织向量以近似搜索，如 HNSW 或 IVF；向量数据库把索引、持久化、metadata filter、更新和服务能力组合起来。FAISS 更偏索引库，不等同完整数据库。三者版本必须一致，否则距离不可比。

### Q145 ANN 召回中的 HNSW/IVF 取舍如何影响延迟、内存和 recall？
- **考察点**：近似索引调参理解。
- **知识点**：graph；nprobe；efSearch；training；memory；recall。
- **复习巩固**：查官方文档，画参数对 recall/latency 的方向。
- **参考回答（知识题口径，60 秒）**：HNSW 用多层图搜索，通常 recall 和低延迟较好，但建索引与内存开销大；IVF 先聚类到倒排桶，索引更紧凑，查询用 `nprobe` 控制扫描范围，但需要训练且分布变化会影响效果。HNSW 的 `efSearch`、IVF 的 `nprobe` 都是在延迟和 recall 间换取，需用自身数据压测。

### Q146 语义相似但业务口径错误的文档排在前面，怎样引入 metadata filter 和规则？
- **考察点**：语义检索与业务约束融合。
- **知识点**：tenant；domain；version；metric；time；pre-filter；rerank。
- **复习巩固**：为同名指标设计 metadata schema。
- **参考回答（设计题口径，90 秒）**：把租户、业务域、指标 ID、版本、有效期和数据级别做成 metadata，在召回前按权限与硬口径过滤，不能检索后再删敏感结果。语义排序只在合法候选内进行，重排时加入指标和时间匹配特征。无法确定口径时先澄清，不让相似度替业务治理做决定。

### Q147 BM25 的 TF、IDF、长度归一化直觉是什么，中文分词有什么坑？
- **考察点**：稀疏检索原理。
- **知识点**：term frequency；inverse document frequency；saturation；length norm；tokenization。
- **复习巩固**：手算两篇短文的词频趋势，并比较两种中文分词。
- **参考回答（45 秒）**：TF 表示词在文档中出现强度但会饱和，IDF 提高稀有词权重，长度归一化避免长文因词多占优。中文没有天然空格，分词错误会拆坏专有名词、指标和缩写。应加入领域词典、字符或混合 token，并用真实查询验证。

### Q148 cross-encoder rerank 为什么更准也更慢，如何做候选数和缓存设计？
- **考察点**：重排性能取舍。
- **知识点**：joint encoding；pair inference；top-N；batch；cache key。
- **复习巩固**：画召回 K、重排 N、最终 M 三个参数。
- **参考回答（60 秒）**：cross-encoder 联合编码 query 与每个候选，能看细粒度交互，因此通常比独立向量更准，但每对都需推理。先用便宜召回缩到合理 N，批量重排并限制文本长度。缓存键要含规范化 query、chunk/version、模型与配置版本，知识库变化时失效。

### Q149 引用正确但回答错误、回答正确但引用错，各如何定位？
- **考察点**：答案与证据评测分离。
- **知识点**：generation faithfulness；citation mapping；support；ground truth。
- **复习巩固**：各造一个坏例并走分层诊断。
- **参考回答（90 秒）**：引用正确但回答错，先查 Prompt、上下文理解和生成是否曲解证据；回答正确但引用错，查 evidence ID、chunk 到原文映射和展示层，也要警惕模型靠常识答对。两种情况分别用 answer correctness 与 citation precision/recall 评估。

### Q150 文档入库如何做解析、OCR、切分、去重、metadata 和质量门禁？
- **考察点**：知识库摄取链路设计。
- **知识点**：parser；OCR confidence；structure；dedup；provenance；quarantine。
- **复习巩固**：画入库状态机及失败隔离区。
- **参考回答（设计题口径，90 秒）**：文件先做类型、安全和权限检查，再解析正文、版面、表格与页码；扫描件走 OCR 并保留置信度。按结构切分，文档 hash 与近重复去重，metadata 记录来源、版本、租户、权限和有效期。空文本、乱码、低 OCR、页码缺失或解析异常进入隔离区，校验通过后才构建索引并原子发布。

### Q151 知识库增量更新、删除、回滚如何防止索引中残留已撤销内容？
- **考察点**：多索引一致性与删除语义。
- **知识点**：manifest；tombstone；generation；atomic switch；garbage collection。
- **复习巩固**：画 dense、sparse、metadata 三通道版本切换。
- **参考回答（设计题口径，90 秒）**：每次构建生成同一 generation 的文档、chunk、dense、sparse 和权限 manifest。删除先写 tombstone，使查询立即排除，再异步清理各索引；更新在新 generation 完整校验后原子切换。回滚切回旧 snapshot，但合规删除不能复活。定期对账文档目录与各索引 ID。

### Q152 实时业务数据为什么不该完全依赖离线文档 RAG？
- **考察点**：数据类型与访问链路匹配。
- **知识点**：freshness；structured query；transaction；snapshot；provenance。
- **复习巩固**：把规则文档和实时订单分别选链路。
- **参考回答（30 秒）**：离线文档有更新和索引延迟，且难保证事务时点和聚合口径。实时指标应走受控 SQL、指标服务或业务 API，RAG 用于解释口径、规则和背景。最终回答同时标数据时间和文档版本。

### Q153 图表、表格、代码块和扫描 PDF 如何保证检索与引用可追溯？
- **考察点**：复杂文档处理。
- **知识点**：layout；table structure；OCR；modality；coordinates；source anchor。
- **复习巩固**：为表格单元和图注设计引用锚点。
- **参考回答（60 秒）**：解析时保留内容类型、页码、版面坐标、表头层级、图注和代码边界。检索文本可增加结构化描述，但展示引用必须能回到原页区域或单元格。OCR 与图表理解保存模型、置信度和原始截图；低置信结果不用于高风险结论。

### Q154 文档级、段落级权限如何参与召回，为什么不能检索后再过滤？
- **考察点**：检索权限前置。
- **知识点**：ACL；pre-filter；index partition；side channel；cache key。
- **复习巩固**：构造未授权文档进入 top-k 的泄漏场景。
- **参考回答（60 秒）**：权限条件必须随用户和租户在召回前进入索引过滤或物理分区，段落继承或覆盖文档 ACL。检索后过滤已经让未授权内容进入候选、日志或模型，也会通过结果数量和缓存形成侧信道。缓存键同样包含权限上下文，默认拒绝漏传 filter。

### Q155 同一向量库承载多租户时，如何保证 filter 不被漏传？
- **考察点**：多租户数据隔离设计。
- **知识点**：tenant-bound client；mandatory filter；DB policy；test；defense in depth。
- **复习巩固**：设计一个无法构造无租户查询的接口。
- **参考回答（设计题口径，90 秒）**：不让业务代码直接传可选 tenant filter，而由认证后的 tenant-bound repository 自动注入并在服务端强制校验；存储支持时再加 namespace 或行级策略。缓存、rerank 和日志保持租户标签。用缺 filter、伪造 tenant 和跨租户缓存命中的负向测试验证，关键客户可用物理隔离。

### Q156 Recall@K、MRR、nDCG、context recall 分别回答什么问题？
- **考察点**：检索指标理解。
- **知识点**：coverage；first rank；graded ranking；evidence coverage。
- **复习巩固**：对一个排序列表手算四项直觉。
- **参考回答（45 秒）**：Recall@K 看前 K 是否覆盖相关项；MRR 看第一个相关项排多前；nDCG 支持多级相关性并评价整体排序；context recall 看回答所需证据是否进入最终上下文。前三级好不代表 packing 后仍保留完整证据。

### Q157 如何切分 dev、holdout、线上 badcase，避免调参污染 holdout？
- **考察点**：评测治理。
- **知识点**：development；sealed holdout；temporal split；badcase；version。
- **复习巩固**：为 100 题设计数据用途和访问规则。
- **参考回答（60 秒）**：dev 用于日常诊断和调参；holdout 封存，仅在里程碑评估并记录访问；线上 badcase 先去敏、去重和归因，再分配到下一版 dev 或新的未来 holdout。按时间或来源切分防近重复泄漏，任何查看答案后的改动都不能再把该题当独立 holdout。

### Q158 检索指标上升但用户满意度下降，有哪些合理原因？
- **考察点**：能否跨层分析指标背离。
- **知识点**：noise；packing；latency；answer；citation；distribution。
- **复习巩固**：列五条可验证假设及对应观测。
- **参考回答（90 秒）**：可能召回更多相关项同时引入噪声，重排或 packing 丢了关键条件；上下文变长导致延迟上升；生成被冲突证据干扰；离线 query 与线上分布不同；引用展示变差。要按层查看候选、最终上下文、回答、延迟和用户任务，不用 Recall 单指标解释体验。

### Q159 query cache、embedding cache、检索 cache 分别怎样失效？
- **考察点**：缓存键与版本治理。
- **知识点**：normalized query；model version；index version；ACL；TTL。
- **复习巩固**：写三种 cache key。
- **参考回答（60 秒）**：query cache 绑定规范化请求、用户或权限、Prompt 和业务版本；embedding cache 绑定文本 hash、预处理和 embedding 模型版本；检索 cache 还绑定 index snapshot、filter、top-k 与 Pipeline。知识库、权限或模型变化必须失效，实时数据用短 TTL 或不缓存。

### Q160 为什么必须保留 page、section、chunk version，而不只保存文本？
- **考察点**：证据可追溯性。
- **知识点**：provenance；duplicate text；location；version；audit。
- **复习巩固**：用同句在两个版本重复出现举例。
- **参考回答（30 秒）**：纯文本不能区分来源、位置和版本，也无法在文档更新后复核。page、section 和 chunk version 能定位原文、解释引用变化并支持删除与回滚。文本相同也可能属于不同权限或时间版本。

### Q161 query rewrite 什么时候会伤害精确实体或指标名称？
- **考察点**：查询改写风险。
- **知识点**：entity preservation；identifier；acronym；dual query；fallback。
- **复习巩固**：构造表名、指标名和错误拼写三个例子。
- **参考回答（45 秒）**：模型可能把表名、指标 ID、版本号、缩写或否定条件改成更常见表达，导致精确词丢失。可抽取并锁定实体，原 query 与 rewrite 并行召回，记录差异；高风险指标名不确定时先澄清。改写必须用 holdout 证明净收益。

### Q162 给一个不适合 RAG 的问题，并说明应走哪条数据或工具链路。
- **考察点**：是否会选择正确数据源。
- **知识点**：real-time；transaction；calculation；tool；RAG boundary。
- **复习巩固**：准备一个实时指标例子。
- **参考回答（90 秒）**：“今天截至十点某业务 GMV 是多少”不适合靠文档 RAG。它应解析指标口径和权限后调用指标服务或只读 SQL，返回数据时间、口径和查询版本；RAG 只补充指标定义和解释。

## I. 评测、坏例归因、可靠性与可观测

### Q163 离线评测、线上监控、人工评审各自不能替代什么？
- **考察点**：评测体系是否完整。
- **知识点**：repeatability；real traffic；semantic judgment；drift；judge bias。
- **复习巩固**：为三者各列优势和盲区。
- **参考回答（45 秒）**：离线评测可复现但覆盖不了真实分布和系统运行；线上监控看流量、SLO 和行为，却缺少可靠 gold；人工评审能判断复杂语义但慢且有分歧。LLM judge 也会偏好风格或被答案诱导，需用人工样本校准。三者相互补充。

### Q164 如何为 Agent 定义任务成功、工具成功、事实正确、格式正确和用户满意？
- **考察点**：指标分层能力。
- **知识点**：outcome；tool execution；groundedness；schema；feedback。
- **复习巩固**：为数据问答写五层指标与失败例。
- **参考回答（60 秒）**：任务成功看用户目标是否完成；工具成功只看调用和业务结果；事实正确检查结论与权威数据；格式正确用 schema 验证；满意度来自用户行为或反馈。五层分别记录，工具 200 不等于任务成功，用户点赞也不能证明事实正确。

### Q165 如何构建可复现 eval manifest，包含模型、prompt、知识库、tool 和预算版本？
- **考察点**：评测可追溯设计。
- **知识点**：commit；dirty；dataset hash；asset version；seed；environment。
- **复习巩固**：参考 KITE provenance 写 manifest。
- **参考回答（设计题口径，90 秒）**：manifest 固定代码提交与 dirty 状态、数据集和 gold hash、模型/provider、Prompt、知识库 snapshot、tool schema、workflow、预算、评测器、随机参数和环境。逐例结果引用 manifest，并保存错误、证据、延迟与用量。外部非确定服务无法完全复现时要记录请求与时间，并明确边界。

### Q166 坏例归因为什么要先分输入、检索、规划、工具、生成、展示六层？
- **考察点**：诊断方法是否结构化。
- **知识点**：failure layer；intermediate artifact；ownership；minimal fix。
- **复习巩固**：拿一个坏例逐层排除。
- **参考回答（45 秒）**：同一个错误答案可能来自问题含糊、漏召回、计划错、工具失败、生成曲解或引用展示错。先分层能找到最早偏离的位置，选择最小修复并分配 owner。直接归因“模型不聪明”会掩盖可确定修复的工程问题。

### Q167 如何设计 failure taxonomy，避免“模型不聪明”成为万能归因？
- **考察点**：错误分类的可操作性。
- **知识点**：mutually useful；observable；root cause；action owner；unknown。
- **复习巩固**：从真实坏例归纳 8 至 12 类并定义证据。
- **参考回答（60 秒）**：分类以可观测证据和修复动作区分，如输入不可答、权限、召回、重排、上下文、工具参数、依赖失败、生成事实、格式和展示。每类有判定信号、owner 和下一步，允许 unknown 并定期复盘拆分。标签不能只按表面症状，也不要细到样本稀疏。

### Q168 某版本 judge 分升了但人工发现更会讨好评分器，怎么发现并修正？
- **考察点**：评测器投机识别。
- **知识点**：holdout；human calibration；style bias；counterfactual；multi-judge。
- **复习巩固**：构造内容相同、表达风格不同的对照答案。
- **参考回答（90 秒）**：保留人工标注 holdout，检查 judge 与人工分歧和版本间异常跃升；对答案做去风格、顺序交换和隐藏系统名的对照，识别长度、措辞偏好。修订 rubric，加入事实和证据确定性检查，必要时多评测器与人工复核。被用来调参的 judge 集不再充当最终 holdout。

### Q169 A/B 实验中模型随机性和用户 query 分布变化怎样处理？
- **考察点**：线上实验基本功。
- **知识点**：randomization；sticky assignment；stratification；variance；guardrail。
- **复习巩固**：设计用户级分流和查询分层。
- **参考回答（知识题口径，60 秒）**：按用户或会话稳定随机分流，避免一次请求跨组；记录模型版本、采样参数和重试。对 query 类型、租户和时段分层，检查 SRM 与分布漂移，主指标配护栏指标。随机性通过足够样本、重复观测或较低温度控制，结论需报告置信区间。

### Q170 p50、p95、p99 各反映什么，为什么 Agent 不能只报平均延迟？
- **考察点**：延迟分位数理解。
- **知识点**：median；tail；outlier；multi-step amplification。
- **复习巩固**：用十个样本手算分位直觉。
- **参考回答（30 秒）**：p50 是典型体验，p95/p99 反映尾部慢请求和容量问题。Agent 一次请求包含多次模型、检索和工具调用，少数超时会被链路放大，平均值会掩盖。还应拆首事件、总完成和各阶段分位。

### Q171 为数据问答 Agent 定义 SLI/SLO/错误预算，哪些指标需要按租户分桶？
- **考察点**：服务目标设计。
- **知识点**：availability；correct response；latency；freshness；error budget；tenant。
- **复习巩固**：写一套不虚构数值的 SLI 公式。
- **参考回答（设计题口径，90 秒）**：SLI 可含授权请求成功率、可复核正确率、首事件与总延迟、数据新鲜度和取消收口率；SLO 数值需基于业务和基线确定。错误预算驱动发布与降级。可用性、p95、限流、成本、正确率和数据源失败都按租户及场景分桶，避免大租户或简单 query 掩盖问题。

### Q172 依赖模型限流、检索服务超时、工具 5xx 同时发生，如何降级并保留诊断？
- **考察点**：级联故障处理。
- **知识点**：deadline；bulkhead；circuit breaker；fallback；correlation ID。
- **复习巩固**：画依赖优先级与降级矩阵。
- **参考回答（设计题口径，90 秒）**：请求设置总 deadline，各依赖独立超时、并发隔离和熔断，避免同步重试放大。模型限流可切受控备用，检索超时可用缓存或明确无证据降级，关键工具 5xx 则停止高风险任务。trace 保留 correlation ID、每次尝试、错误类别和降级版本，用户看到不完整而非伪成功。

### Q173 按错误类别定义 retry policy，说明退避、抖动、上限和熔断。
- **考察点**：重试策略设计。
- **知识点**：transient；permanent；exponential backoff；jitter；budget；circuit breaker。
- **复习巩固**：为 429、400、timeout、写操作分别定策略。
- **参考回答（60 秒）**：429、部分 5xx 和网络瞬断可在总 deadline 内指数退避加随机抖动，设置次数与耗时上限；参数、权限和业务拒绝不重试。写操作仅在有幂等键时自动重试。连续失败触发熔断，半开探测恢复，所有重试计入请求和租户预算。

### Q174 为什么重试可读查询和重试扣费/写操作的策略不同？
- **考察点**：副作用意识。
- **知识点**：idempotent read；side effect；duplicate；confirmation；compensation。
- **复习巩固**：对超时响应分别推演。
- **参考回答（30 秒）**：可读查询通常无副作用，有限重试只增加成本；扣费和写操作可能已成功但响应丢失，重试会重复执行。后者必须有业务幂等键或先查询确认，无法确认就进入 unknown 和人工处理。

### Q175 如何设计 outbox、任务表或 saga，让 Agent 侧副作用可审计可补偿？
- **考察点**：可靠副作用编排。
- **知识点**：transactional outbox；operation state；idempotent consumer；saga；compensation。
- **复习巩固**：以“创建报告并通知”画事务边界。
- **参考回答（设计题口径，90 秒）**：本地事务同时写任务状态和 outbox，发布器重试发送，消费者按 event ID 幂等。每个副作用记录 operation ID、参数 hash、外部结果和状态；多步骤用 saga 定义正向与补偿动作。不可补偿步骤放最后并审批，定期对账 pending/unknown，只有确认提交后对用户显示成功。

### Q176 SSE 断线重连如何做 event id、replay window 和最终一致性？
- **考察点**：流式服务恢复。
- **知识点**：monotonic ID；Last-Event-ID；buffer；snapshot；terminal event。
- **复习巩固**：写客户端重连序列。
- **参考回答（60 秒）**：每个 session 的事件 ID 单调递增并持久化或保留窗口，客户端用 Last-Event-ID 重连，服务端补发缺失事件。若 ID 超出窗口，返回当前任务 snapshot 后继续订阅。事件可重复，客户端按 ID 去重；终态由任务存储决定，SSE 只是投影。

### Q177 用户取消与系统超时同时发生，最终状态由谁写，如何避免竞态？
- **考察点**：终态竞争处理。
- **知识点**：single writer；CAS；precedence；timestamp；idempotent transition。
- **复习巩固**：设计 cancelled 与 timed_out 的优先规则。
- **参考回答（60 秒）**：由任务状态服务作为单一写者，通过版本 CAS 接收取消和超时事件。先定义优先规则，例如用户取消先被持久化则终态 cancelled，否则 deadline 触发 timed_out；后到事件只作审计，不覆盖终态。工具清理幂等，终态转换只能成功一次。

### Q178 日志、metrics、trace、audit log 分别适合查什么？
- **考察点**：观测四件套边界。
- **知识点**：event detail；aggregate；causal path；compliance；immutability。
- **复习巩固**：为一次越权失败选择四种记录。
- **参考回答（45 秒）**：日志查具体事件和错误上下文；metrics 看聚合趋势、SLO 和告警；trace 串联一次请求跨服务耗时与因果；audit log 记录谁在何时对什么资源做了什么以及授权结果，需防篡改。它们可关联但不能混成一份敏感明文日志。

### Q179 trace 中如何脱敏 prompt、SQL、文档片段和用户标识，又保留排障能力？
- **考察点**：隐私与可观测平衡。
- **知识点**：classification；redaction；tokenization；hash；secure vault；RBAC。
- **复习巩固**：设计普通观测层和受控取证层。
- **参考回答（设计题口径，60 秒）**：默认 trace 只存模板版本、长度、类别、hash、表与字段的安全标识和脱敏错误。必要原文进入加密受控存储，以引用 ID 关联，访问需单独权限和审计。用户 ID 做租户内伪匿名化，敏感参数按 schema 字段级清洗，保留期限最小化。

### Q180 如何把 token、模型调用、工具调用、检索上下文成本归因到用户、租户和工作流节点？
- **考察点**：成本计量设计。
- **知识点**：run/span IDs；usage；price version；unknown；allocation。
- **复习巩固**：画一条 cost event schema。
- **参考回答（设计题口径，90 秒）**：每个模型、工具和检索 span 带 run、session、用户、租户、workflow node 和用途，记录输入输出 token、调用数、时长及资源量。费用按当时 price version 计算，缓存命中和共享批处理有明确分摊规则。provider 未返回 usage 时记 unknown，不记零；聚合用于配额、账单和优化。

### Q181 Prompt 或模型升级如何灰度、回滚并避免会话中途行为变化？
- **考察点**：资产发布治理。
- **知识点**：session pinning；canary；shadow；eval gate；rollback。
- **复习巩固**：设计版本选择与回滚键。
- **参考回答（60 秒）**：新会话按稳定哈希进入灰度，已有会话固定原 manifest，避免中途切换。发布前离线回归，灰度看质量、延迟、成本和安全指标，可做 shadow 对比。版本与会话、trace 绑定，异常时停止新流量并快速切回，迁移旧会话需显式策略。

### Q182 超时、取消、失败、blocked、incomplete 这些状态如何避免混为“完成”？
- **考察点**：终态语义设计。
- **知识点**：state enum；reason code；terminal；user message；metrics。
- **复习巩固**：为五种状态定义触发和展示。
- **参考回答（45 秒）**：状态使用明确枚举和 reason code，成功必须满足产物与门禁。超时是 deadline，取消来自用户或上游，failed 是不可恢复错误，blocked 等外部输入，incomplete 是有部分结果但未达交付条件。UI、指标和重试策略按状态处理，不能统一映射成“已结束”。

### Q183 生产 badcase 如何脱敏回放，避免用线上敏感数据直接训练或泄露？
- **考察点**：坏例闭环与合规。
- **知识点**：redaction；synthetic substitute；access control；consent；retention。
- **复习巩固**：写 badcase 入库门禁。
- **参考回答（设计题口径，60 秒）**：采集前按字段和内容分类，去用户标识、密钥、PII 和业务机密，能合成的实体用等价占位替换；保留结构和失败机制。回放环境使用 mock 或只读数据，数据集有用途、权限、期限和删除。未经授权的线上原文不直接进训练或普通评测。

### Q184 定义一次“报告已生成但不可交付”的判定，并设计防线。
- **考察点**：完成与可交付的区别。
- **知识点**：evidence gate；coverage；freshness；PII；format；blocked delivery。
- **复习巩固**：给报告写一份交付门禁。
- **参考回答（设计题口径，90 秒）**：报告文件存在但核心 claim 无证据、引用失效、数据未就绪、含敏感信息、口径不明或格式契约失败，都应判不可交付。生成后运行结构、证据、权限和数据新鲜度门禁，高风险样本人工抽查。状态记 incomplete/blocked，保留草稿供修复，但不发下载链接或成功通知。

### Q185 主库或队列故障后，Agent 平台如何保证用户不会看到伪成功？
- **考察点**：系统事实与用户呈现一致性。
- **知识点**：commit point；durable state；outbox；read-after-write；degraded mode。
- **复习巩固**：画成功事件的提交顺序。
- **参考回答（设计题口径，90 秒）**：成功只在 canonical 状态和产物引用持久提交后产生，通知通过 outbox 发布。主库不可确认写入时返回处理中或失败，不靠内存状态显示完成；队列故障时已提交任务保持 queued，入口做背压。恢复后对账状态、消息和产物，重复通知按 event ID 去重。

## J. Python、并发、网络、存储与部署

### Q187 线程、进程、协程的调度和适用场景？Python GIL 影响什么、不影响什么？

### Q188 用 `asyncio` 并发调用三个 I/O 工具，如何设置 timeout、取消和异常聚合？

- **知识点**：TaskGroup；wait_for/timeout；cancellation；ExceptionGroup；finally。
- **复习巩固**：闭卷写一个 `TaskGroup` 最小示例。

### Q189 一个协程被取消时持有 DB 连接或 semaphore，如何确保 finally 清理？

- **知识点**：async context manager；try/finally；shield；rollback；release。

### Q190 HTTP keep-alive、连接池、超时（connect/read/write/total）分别解决什么？

### Q194 事务隔离、幻读、死锁在 Agent 任务状态更新中会怎样出现？

### Q195 Redis 常见数据结构与适用场景，为什么缓存不能成为任务真相？

### Q196 cache-aside 如何处理穿透、击穿、雪崩和一致性？

### Q197 用消息队列调度长任务，如何处理重复消费、顺序、DLQ 和积压？

### Q204 TCP 三次握手、四次挥手、TIME_WAIT 对高并发客户端有什么影响？

- **考察点**：数据不稳定时的产品语义。
- **知识点**：as-of time；readiness；provisional；revision；version。
- **复习巩固**：设计回答中的时间和状态字段。
- **参考回答（90 秒）**：回答携带数据截至时间、分区就绪状态、口径和版本。未到 SLA 时标临时结果并说明缺失范围；回补后生成新版本和变化说明，历史回答仍能追溯旧 snapshot。对关键决策可阻断未就绪数据，而不是让模型用旧值补齐。

### Q215 OLTP 与 OLAP 的存储、查询和索引取舍？
- **考察点**：数据库工作负载区别。
- **知识点**：transactions；row/column；point query；scan；aggregation；concurrency。
- **复习巩固**：将订单写入和 GMV 分析分配系统。
- **参考回答（45 秒）**：OLTP 面向高并发短事务和点查，常用行存与 B+ 树；OLAP 面向大扫描与聚合，常用列存、分区、排序和向量化执行。数据 Agent 的分析查询应走治理后的 OLAP 或指标服务，避免直接压交易库。

### Q216 为什么 Text-to-SQL 需要 schema linking、语义层和权限过滤？
- **考察点**：Text-to-SQL 核心难点。
- **知识点**：entity-table mapping；metric semantics；join path；ACL；search space。
- **复习巩固**：用“活跃用户”映射表、字段、指标。
- **参考回答（60 秒）**：schema linking 把用户实体和条件映射到候选表字段，语义层提供指标公式、合法维度和 join path，权限过滤先移除不可见资源。三者共同缩小生成空间并防口径错和越权。只给全库 DDL，模型即使语法正确也很容易选错表或扫描敏感数据。

### Q217 从自然语言到 SQL 的完整链路如何设计：意图澄清、指标解析、SQL 生成、校验、执行、解释、审计？
- **考察点**：数据 Agent 主链路设计。
- **知识点**：clarify；semantic parse；generate；static check；explain；execute；audit。
- **复习巩固**：闭卷画端到端链路。
- **参考回答（设计题口径，90 秒）**：先认证并澄清指标、时间、粒度和维度；从语义层、目录和权限生成最小 schema 上下文；模型产 SQL 后做 AST 解析、只读与字段权限、口径、join、扫描量和 Explain 校验，再在隔离只读身份下限时执行。结果做合理性与数据质量检查，回答带 SQL、口径、数据时间和证据，整链路审计。

### Q218 模型生成语法正确但口径错误 SQL，如何在执行前发现？
- **考察点**：语义校验能力。
- **知识点**：metric contract；AST；join validation；grain；gold query；dry-run。
- **复习巩固**：构造重复计数和错误时间字段两个样例。
- **参考回答（60 秒）**：把 SQL AST 与指标 contract 对照，检查事实表、时间字段、聚合、默认过滤、粒度和允许 join path；检测 many-to-many 放大、漏去重和单位错误。用 Explain 和小样本 dry-run 检查扫描与结果形态，高风险或口径歧义先澄清。执行成功不等于语义正确。

### Q219 如何防 SQL 注入、越权扫描、大查询拖垮集群和敏感字段泄露？
- **考察点**：Text-to-SQL 安全设计。
- **知识点**：AST allowlist；read-only identity；row/column policy；cost estimate；quota；masking。
- **复习巩固**：写执行前六道门禁。
- **参考回答（设计题口径，90 秒）**：不拼接用户字符串，解析 AST 并仅允许受控 SELECT 和函数；执行身份只读，行列权限由引擎或 policy 强制。执行前做 Explain、扫描量、分区、超时和并发配额，结果集限制与敏感字段脱敏。导出需审批，SQL、授权决策和数据版本审计。

### Q220 分区、分桶、排序键如何影响大表查询与成本？
- **考察点**：大数据存储布局基础。
- **知识点**：partition pruning；bucket；shuffle；sort skip；small files。
- **复习巩固**：为按天和用户查询设计布局。
- **参考回答（45 秒）**：分区按常用粗粒度条件裁剪文件，分桶按 hash 分布数据，利于 join 或采样，排序键让范围过滤和压缩更有效。选择不当会产生海量小分区、倾斜或无法裁剪。Agent 生成 SQL 时应强制分区条件并用成本估算。

### Q221 语义层如何把 metric definition、join path、可用维度暴露给 Agent？
- **考察点**：语义层接口设计。
- **知识点**：typed catalog；metric ID；dimension compatibility；join graph；version。
- **复习巩固**：设计 `get_metric` 和 `plan_query` 工具结果。
- **参考回答（设计题口径，60 秒）**：通过结构化 API 返回指标 ID、公式、事实表、时间粒度、允许维度、默认过滤、合法 join path、权限和版本，而不是长段自然语言。Agent 先检索候选指标，再调用 planner 生成受约束查询计划。语义层负责治理，模型不能新增口径。

### Q222 多个业务线对 GMV 口径不一致，平台应如何治理，而不是让模型选一个？
- **考察点**：数据治理与歧义处理。
- **知识点**：namespace；owner；definition；version；approval；clarification。
- **复习巩固**：为两个 GMV 建独立 ID 和展示名。
- **参考回答（90 秒）**：按业务域建立不同稳定指标 ID，明确公式、币种、退款处理、时间口径、owner 和有效期；平台提供术语映射但不强行合并。用户只说 GMV 时，根据权限和上下文给候选并澄清。跨业务比较需显式转换规则和治理审批。

### Q223 数据目录搜索如何结合关键词、向量、权限和热度？
- **考察点**：企业搜索设计。
- **知识点**：hybrid recall；ACL prefilter；quality；freshness；popularity；rerank。
- **复习巩固**：设计目录 ranking 特征。
- **参考回答（60 秒）**：先按租户与 ACL 过滤，关键词召回精确表名和字段，向量召回业务同义表达；重排加入所有者认证、质量、新鲜度和受控热度。热度只能辅助，不能让旧或低质量表压过权威资产。结果展示口径、owner、SLA 和权限原因。

### Q224 数据分级分类、脱敏、行列权限分别应落在哪层？
- **考察点**：数据安全分层。
- **知识点**：catalog tag；policy engine；storage enforcement；query；presentation。
- **复习巩固**：画目录、查询引擎、服务和 UI 四层。
- **参考回答（60 秒）**：分级分类在数据目录形成统一标签；行列权限尽量由查询引擎或数据服务强制；脱敏可在引擎、服务和展示层按场景执行。Agent 只消费授权后的 schema 和结果，不能成为唯一防线。日志、缓存和评测集也继承数据级别。

### Q225 离线任务调度如何处理依赖、补数、优先级和 SLA？
- **考察点**：数据开发调度基础。
- **知识点**：DAG；data dependency；backfill；resource pool；deadline；alert。
- **复习巩固**：画日报 DAG 与补数旁路。
- **参考回答（60 秒）**：依赖既看任务完成也看数据分区就绪，调度记录 run 和数据版本。补数单独标范围、资源池和下游影响，避免挤占在线 SLA；优先级结合截止时间、业务等级和资源配额。监控关键路径、延迟和数据质量，失败支持从安全节点重跑。

### Q226 上游 schema 变更后下游任务静默产出空表，如何监测并止损？
- **考察点**：schema drift 与数据质量防线。
- **知识点**：contract；compatibility；row count；freshness；lineage；circuit breaker。
- **复习巩固**：设计发布前和运行后两层检查。
- **参考回答（90 秒）**：上游发布前做 schema contract 兼容检查并通过血缘通知下游；运行时监控字段缺失、类型、分区行数、空值与历史基线。发现空表立即阻断向下游发布和 Agent 查询，标数据未就绪，保留上一稳定版本但注明时间。定位影响面后修复并补数，再逐层放开。

### Q227 如何把数据质量告警、血缘和 Agent 的回答置信度关联起来？
- **考察点**：数据状态进入回答链路。
- **知识点**：asset health；lineage propagation；severity；freshness；confidence label。
- **复习巩固**：为一个受上游延迟影响的指标写规则。
- **参考回答（设计题口径，60 秒）**：查询计划解析到具体表、分区和指标版本，沿血缘获取相关质量告警与新鲜度，按严重度决定阻断、降级或提示。回答置信标签来自证据覆盖和数据健康等可解释因素，不伪装成概率。关键告警未解除时不输出确定结论。

### Q228 数据智能体和传统 BI 问答相比，新增了哪些风险和能力？
- **考察点**：产品差异理解。
- **知识点**：multi-step；tool action；open-ended；trace；hallucination；side effect。
- **复习巩固**：列能力和风险各三项。
- **参考回答（45 秒）**：数据智能体能多轮澄清、跨元数据和血缘工具、执行诊断并生成解释，超出传统固定问答。新增风险是动态规划不可预测、跨工具权限扩大、口径幻觉和副作用。需要更强的状态、审计、评测和人工门禁。

### Q229 客户要求把私有数据库接入平台，网络、凭据、权限和审计怎么设计？
- **考察点**：To B 数据接入安全。
- **知识点**：private link；connector；secret manager；read-only；egress；audit。
- **复习巩固**：画控制面与客户数据面的连接。
- **参考回答（设计题口径，90 秒）**：优先让 connector 部署在客户网络，通过私网或受控出站与平台通信；凭据进 secret manager，短期下发给 worker，不进模型。使用专用只读账号和库表字段权限，查询有配额、超时和审批。审计记录用户、SQL 摘要、资源和结果规模，客户可查看与撤销。

### Q230 设计一个“问数与归因” Agent，要求结果可复核、可追溯、可治理。
- **考察点**：岗位核心系统设计。
- **知识点**：semantic layer；SQL；anomaly；lineage；evidence；governance。
- **复习巩固**：按系统设计模板完整讲一次。
- **参考回答（设计题口径，90 秒）**：入口做身份与意图澄清，语义层解析指标、维度和时间；SQL planner 生成受权限和成本约束的只读查询，结果经过数据质量检查。异常归因只提出候选：结合维度下钻、变更事件、实验和血缘证据，区分相关与因果。回答携带 SQL、口径、数据时间、来源和限制；全链路有版本、trace、审计和离线回归。

## L. 安全、权限、审计与多租户 To B

### Q231 认证、授权、审计三者的区别？
- **考察点**：安全基础概念。
- **知识点**：identity；permission；evidence；authentication；authorization；audit。
- **复习巩固**：用数据导出请求串起三者。
- **参考回答（30 秒）**：认证确认“你是谁”，授权判断“你能对什么做什么”，审计记录“谁何时做了什么、依据和结果”。三者顺序相关但职责不同，登录成功不代表有数据权限，日志存在也不能替代执行前授权。

### Q232 RBAC 与 ABAC 怎样组合支持数据表、字段、操作和环境权限？
- **考察点**：企业授权模型设计。
- **知识点**：role；attribute；resource tag；action；environment；deny override。
- **复习巩固**：为分析师角色和敏感字段写一条策略。
- **参考回答（60 秒）**：RBAC 给职位分配基础权限，如分析师可查询；ABAC 再结合租户、数据等级、字段标签、环境、时间和请求目的细化。策略输入是主体、资源、动作和上下文，显式 deny 优先。模型只提交意图，policy engine 做最终判定并返回可审计理由。

### Q233 共享库共享表、共享库分 schema、独立库三种隔离模型如何取舍？
- **考察点**：多租户存储隔离。
- **知识点**：cost；blast radius；operations；compliance；migration。
- **复习巩固**：按中小客户和强监管客户做选择。
- **参考回答（90 秒）**：共享表成本最低、扩展方便，但每个查询都依赖 tenant key，爆炸半径最大；分 schema 提高逻辑隔离，迁移和运维更复杂；独立库隔离、密钥和恢复最强，成本最高。按数据级别、合规、规模和定制需求分层选择，并保留从共享到独立迁移路径。

### Q234 Agent 身份、用户身份、服务身份怎样委托与收敛？
- **考察点**：身份传递和最小权限。
- **知识点**：on-behalf-of；service account；scope；audience；short-lived credential。
- **复习巩固**：画用户到工具的身份链。
- **参考回答（60 秒）**：用户身份决定资源权限，Agent 是受控执行主体，服务身份只用于平台自身能力。调用工具时用 on-behalf-of 或短期委托 token，同时受用户权限与 Agent 能力交集约束，token 限 audience、scope 和有效期。不能用高权服务账号替所有用户访问。

### Q235 API key、OAuth token、数据库密码如何存储、轮换、短期授权和脱敏？
- **考察点**：秘密管理能力。
- **知识点**：secret manager；encryption；rotation；ephemeral token；redaction。
- **复习巩固**：列秘密从创建到撤销的生命周期。
- **参考回答（60 秒）**：长期秘密放专用 secret manager 加密存储，运行时按身份短期注入，不写配置、Prompt、trace 或 artifact。优先 OAuth 短期 token 和最小 scope，数据库用专用低权账号；定期与事件触发轮换，支持双密钥过渡和快速撤销。日志按字段脱敏。

### Q236 Prompt injection 到 tool invocation 的攻击链如何建 threat model？
- **考察点**：Agent 特有威胁建模。
- **知识点**：source；instruction confusion；privilege；data flow；sink；mitigation。
- **复习巩固**：从恶意网页到外发工具画 source-to-sink。
- **参考回答（设计题口径，90 秒）**：列攻击源如用户、网页和工具结果，分析它如何进入上下文、影响模型选择、调用高权工具并把数据送到外部。对每条链检查信任标签、权限提升、敏感数据流和不可逆 sink。防线包括指令隔离、最小工具集、policy、出站限制、审批和审计，并用对抗样例验证。

### Q237 一次高风险数据导出要记录哪些审计字段，如何保证不可抵赖？
- **考察点**：高风险审计设计。
- **知识点**：actor；approver；resource；purpose；policy；hash；immutable log。
- **复习巩固**：写审计事件 schema。
- **参考回答（60 秒）**：记录租户、用户与服务身份、审批人、请求时间、目的、资源和字段、过滤条件、结果规模、policy 版本、审批与执行结果、文件 hash 和去向。日志追加写、受限修改并做完整性校验，时间和事件 ID 可验证。敏感内容不必全明文，但要能受控取证。

### Q238 PII、敏感数据、业务机密在 prompt、日志、eval 集中分别如何处理？
- **考察点**：全生命周期隐私治理。
- **知识点**：classification；minimization；redaction；consent；retention；access。
- **复习巩固**：做三类存储的允许矩阵。
- **参考回答（60 秒）**：Prompt 只放任务所需最小内容并按模型目的授权；日志默认脱敏、结构化记录；eval 集在入库前去标识和替换敏感实体，无法安全脱敏就不收。三处都需访问控制、加密、期限、删除和供应商边界，线上原文不能顺手变训练数据。

### Q239 代码执行 sandbox 的网络、文件、进程、资源配额怎样限制？
- **考察点**：不可信代码隔离设计。
- **知识点**：namespace；seccomp；read-only fs；egress deny；cgroup；timeout。
- **复习巩固**：列容器外还需补的防线。
- **参考回答（设计题口径，90 秒）**：每任务独立容器或微虚机，根文件系统只读，只挂临时工作目录；网络默认拒绝，仅白名单出站；限制系统调用、子进程、用户权限、CPU、内存、磁盘、PID 和时间。秘密按任务短期注入并回收。容器本身不是全部边界，还需镜像供应链、宿主加固和审计。

### Q240 缓存或向量检索发生跨租户命中，立即止损、排查、修复和告知如何做？
- **考察点**：严重安全事故处理。
- **知识点**：containment；revoke；scope；forensics；notification；regression。
- **复习巩固**：写前一小时处置清单。
- **参考回答（90 秒）**：立即关闭相关缓存或检索路径、切安全降级，撤销可能泄露的链接和凭据并保全日志；按 tenant、时间、query 和对象版本界定影响。根因常查漏 filter、错误 cache key 或索引混写，修复后清缓存、重建索引并加入负向隔离测试。按合规和合同及时通知受影响客户，不能先改日志掩盖。

### Q241 如何做租户级 QPS、并发、token、工具调用和存储配额？
- **考察点**：多维配额设计。
- **知识点**：token bucket；semaphore；budget ledger；quota hierarchy；priority。
- **复习巩固**：画组织、租户、用户三级配额。
- **参考回答（60 秒）**：QPS 用令牌桶，并发用租户 semaphore 或队列，token 和工具调用在 run budget ledger 预留与结算，存储做硬上限和预警。配额按组织、租户、用户分层，父级约束子级，高优请求仍受安全上限。超额返回明确等待或降级，不让重试绕过。

### Q242 为什么“模型供应商承诺不训练数据”仍不足以完成企业安全设计？
- **考察点**：供应商承诺与端到端安全区别。
- **知识点**：retention；access；region；logging；subprocessor；egress；authorization。
- **复习巩固**：列供应商之外的五个泄漏点。
- **参考回答（45 秒）**：不训练只覆盖一种用途，仍要确认留存、人工访问、地域、子处理方、传输和删除。企业自身还可能在 Prompt、日志、缓存、工具和权限处泄漏。安全设计需数据最小化、合同与技术控制、访问审计和替代路线。

### Q243 Prompt、工具与知识库发布如何审批、灰度和回滚？
- **考察点**：Agent 资产治理。
- **知识点**：manifest；risk tier；eval gate；canary；session pin；rollback。
- **复习巩固**：设计一次版本发布记录。
- **参考回答（60 秒）**：变更生成不可变版本和 manifest，按风险经过自动回归与人工审批；小流量或指定租户灰度，已有 session 固定旧版本。监控质量、安全、延迟和成本，异常停止新流量并切回旧 manifest。知识库回滚还要尊重合规删除。

### Q244 第三方 MCP server 或 plugin 如何做接入准入、版本锁定和持续审查？
- **考察点**：Agent 供应链安全。
- **知识点**：publisher；code review；permission manifest；pin；SBOM；revocation。
- **复习巩固**：写准入 checklist。
- **参考回答（设计题口径，90 秒）**：核验发布者、源码或制品签名、依赖与漏洞、工具 schema、权限、网络和数据用途；在隔离环境跑对抗与兼容测试。生产锁定版本和 hash，权限变更需重新审批，持续监测行为与漏洞。支持快速禁用、凭据撤销和受影响调用追溯。

### Q245 如何让错误日志可排查又不把原始敏感 SQL 与结果扩散？
- **考察点**：日志最小化。
- **知识点**：query fingerprint；AST summary；redaction；secure reference；RBAC。
- **复习巩固**：把一条 SQL 变成安全诊断字段。
- **参考回答（60 秒）**：普通日志记录 query fingerprint、涉及的安全表标识、操作类型、扫描量、错误位置、request_id 和版本，不存完整 SQL 与结果。原始材料若必须取证，放加密受控存储并用引用关联，访问单独审批和审计。schema 驱动脱敏比正则更可靠。

### Q246 客户要求“全自动执行”，你会坚持的三条边界是什么？
- **考察点**：产品压力下的安全判断。
- **知识点**：least privilege；reversible action；approval；observability；kill switch。
- **复习巩固**：准备三条可谈判和不可谈判边界。
- **参考回答（45 秒）**：一是权限与数据范围由程序强制，模型不能扩大；二是不可逆、高成本和敏感操作需审批或稳定幂等补偿；三是每次执行可追踪、可停止并有 kill switch。可在低风险、可回滚、评测充分的动作上逐步提高自动化。

### Q247 跨地域部署时，数据驻留、模型调用和备份恢复如何处理？
- **考察点**：全球 To B 架构考虑。
- **知识点**：region affinity；data residency；routing；encryption；RPO/RTO。
- **复习巩固**：画区域内数据面和全局控制面。
- **参考回答（设计题口径，90 秒）**：数据、索引、日志和备份按租户驻留策略固定区域，控制面只保存允许的元数据；模型请求路由到合规区域，禁止跨区时提供区域模型或关闭能力。密钥分区管理，备份同样遵守驻留。定义 RPO/RTO 并演练区域故障，跨区恢复需客户和合规授权。

### Q248 设计一个多租户 Agent 平台的控制面和数据面边界。
- **考察点**：To B 平台总体设计。
- **知识点**：control plane；data plane；tenant config；runtime；secrets；audit。
- **复习巩固**：画两平面和信任边界。
- **参考回答（设计题口径，90 秒）**：控制面管理租户、用户、策略、工具与 Prompt 版本、配额、发布和评测；数据面执行 run、模型、检索和工具，处理客户数据。数据面按租户隔离并只拿短期配置与凭据，控制面不收不必要的原始结果。两者通过版本化签名配置和审计事件通信，故障与扩缩容独立。

## M. 系统设计、产品业务与前沿判断

### Q249 设计一个最小企业 Agent 平台，第一版明确不做什么？
- **考察点**：MVP 边界和优先级。
- **知识点**：runtime；tool registry；state；trace；eval；YAGNI。
- **复习巩固**：写五个必做和五个不做。
- **参考回答（设计题口径，90 秒）**：第一版支持单 Agent、少量受控工具、版本化 Prompt、任务状态、SSE、权限审计和最小评测，外层用确定性 Workflow。暂不做通用多 Agent、自动长期记忆、自研 planner、任意代码执行和复杂可视化 DSL。先在一个高价值只读场景验证任务成功、稳定性和复用边界。

### Q250 设计 Agent runtime：请求生命周期、状态存储、工具执行、流式输出、取消、审计。
- **考察点**：运行时核心链路。
- **知识点**：gateway；orchestrator；checkpoint；tool worker；event stream；policy。
- **复习巩固**：按七层模板完整画图。
- **参考回答（设计题口径，90 秒）**：网关认证、限流并创建 run；runtime 固定版本 manifest，构建上下文并驱动模型与工具。canonical 状态和 checkpoint 存数据库，工具经 registry、policy 和隔离 worker 执行。事件持久化后由 SSE 投影；取消写状态并传播，终态 CAS 收口。模型、工具、授权、成本与副作用进入 trace 和审计。

### Q251 设计支持百万日请求的多租户 Agent 平台，先澄清哪些容量与一致性约束？
- **考察点**：大规模设计的需求澄清。
- **知识点**：QPS；burst；concurrency；duration；tokens；SLO；state；tenant skew。
- **复习巩固**：列十个澄清问题，不直接报架构。
- **参考回答（90 秒）**：先问日请求分布与峰值、会话时长、模型和工具次数、流式连接数、长任务比例、租户倾斜、延迟与可用性 SLO、状态和事件保留、跨区与一致性要求、可接受降级及成本。百万日请求本身信息不足。容量分别估模型 token、工具 I/O、worker 并发、队列和存储，再决定分片与隔离。

### Q252 设计企业知识库服务，如何支持解析、检索、权限、版本和评测？
- **考察点**：知识库平台化设计。
- **知识点**：ingestion pipeline；snapshot；hybrid retrieval；ACL；provenance；eval。
- **复习巩固**：画控制面、构建面和查询面。
- **参考回答（设计题口径，90 秒）**：入库面做安全检查、解析/OCR、结构切分、去重、质量门禁并生成 snapshot；查询面先权限过滤，再混合召回、重排和 packing。文档、chunk、索引与 embedding 全部版本化，删除和回滚有 manifest。评测覆盖解析、Recall、引用、权限负例、延迟和成本，发布走灰度。

### Q253 设计数据分析 Agent，如何把 SQL 执行引擎、语义层、元数据和审计接起来？
- **考察点**：岗位核心架构整合。
- **知识点**：semantic parse；catalog；planner；policy；query gateway；audit。
- **复习巩固**：复用 Q217 链路并补服务边界。
- **参考回答（设计题口径，90 秒）**：Agent 先从语义层解析指标和维度，再用元数据目录收窄表、字段和 join；生成查询计划后由 policy 做租户、行列权限和成本检查，SQL gateway 负责 AST、Explain、只读身份、超时与结果限制。结果绑定数据 snapshot、口径和质量状态，审计记录用户、SQL 摘要、授权与导出。

### Q254 平台面向算法、数据开发、业务运营三类用户，各自需要怎样的配置体验？
- **考察点**：平台易用性分层。
- **知识点**：SDK；DSL；visual builder；guardrail；progressive disclosure。
- **复习巩固**：为三类用户各写最常见任务。
- **参考回答（60 秒）**：算法同学需要 SDK、评测和模型参数；数据开发需要工具、元数据、Workflow 与版本控制；业务运营需要受约束模板、表单和可解释结果。底层运行 contract 相同，界面按角色渐进暴露能力。高风险配置不因可视化而绕过审批。

### Q255 客服、数据问答、运维排障、测试自动化四类 Agent 哪个优先平台化，为什么？
- **考察点**：场景价值与风险判断。
- **知识点**：frequency；repeatability；tool reuse；risk；data readiness。
- **复习巩固**：建立价值、复用、风险、数据四维评分。
- **参考回答（60 秒）**：没有绝对答案。我会优先选择高频、工具与数据已标准化、结果可验收且副作用低的场景。若数据平台已有指标、元数据和只读查询能力，数据问答适合作为第一场景；运维和测试自动化价值高但副作用更大，先做建议与 dry-run，再逐步执行。

### Q256 如何识别可复用的能力和只该留在垂类业务的规则？
- **考察点**：平台抽象能力。
- **知识点**：change frequency；cross-domain invariants；extension point；policy；ownership。
- **复习巩固**：把十项能力分平台和业务。
- **参考回答（45 秒）**：多个场景重复、语义稳定且由平台统一治理的能力可复用，如状态、工具协议、权限、观测和评测。变化快、依赖业务口径或风险责任的规则留在垂类，如指标定义和审批条件。平台提供扩展点，不把所有差异做成核心 if/else。

### Q257 如何定义 Agent 产品从“能演示”到“值得长期用”的门槛？
- **考察点**：产品成熟度判断。
- **知识点**：task success；retention；reliability；trust；cost；operations。
- **复习巩固**：为数据问答列主指标和护栏。
- **参考回答（90 秒）**：演示看单次效果，长期使用需代表任务完成率稳定、错误可发现、引用和权限可信、p95 与成本可接受、坏例能闭环，用户会重复使用且人工节省真实。还要有发布、回滚和运维。指标阈值应从基线与业务风险确定，不凭感觉。

### Q258 模型路由、小模型预筛、缓存、批处理如何降低成本，各有什么质量风险？
- **考察点**：成本优化取舍。
- **知识点**：routing error；false reject；staleness；latency；batch queue。
- **复习巩固**：为每项写收益、风险和护栏。
- **参考回答（60 秒）**：路由可把简单任务给便宜模型，但错路由会降质；小模型预筛可能误拒复杂请求；缓存有过期和权限风险；批处理提高吞吐却增加排队。所有优化都要版本化，用高风险直达、置信阈值、缓存版本和延迟上限保护，并做逐场景回归。

### Q259 你如何看待 agentic coding、computer use、MCP、A2A 等协议的长期价值？
- **考察点**：前沿判断是否克制。
- **知识点**：capability；standardization；interoperability；security；evaluation。
- **复习巩固**：每项准备“价值、限制、落地条件”。
- **参考回答（60 秒）**：agentic coding 和 computer use 扩大可执行任务，MCP 降低工具接入差异，A2A 类协议尝试标准化 Agent 间协作。长期价值取决于身份、权限、状态、错误语义和评测能否一起成熟。协议只解决互操作的一部分，不自动带来任务质量或安全。

### Q260 长上下文变强后，RAG、memory、workflow 是否还必要？
- **考察点**：是否理解窗口与治理的区别。
- **知识点**：freshness；selection；permission；provenance；state；cost。
- **复习巩固**：分别列长窗口无法解决的问题。
- **参考回答（45 秒）**：仍必要。RAG 负责新鲜、授权和可追溯检索，memory 管跨任务稳定信息与生命周期，workflow 管状态、副作用和恢复。长窗口能减少部分切分和压缩压力，但全部塞入仍有噪声、注入、成本和版本问题。

### Q261 如果模型能力每季度变化，怎样保证评测集和安全策略不过时？
- **考察点**：持续评测治理。
- **知识点**：rolling badcase；sealed anchor；adversarial；drift；policy independent。
- **复习巩固**：设计季度评测更新流程。
- **参考回答（90 秒）**：保留稳定 anchor 集用于纵向比较，同时从线上坏例、业务变化和新攻击更新 rolling 集；新增题经去重、可回答性和人工校准。安全硬策略尽量独立于模型，通过 policy 和权限实现，再用新模型做对抗回归。版本升级先 shadow 和灰度，不因总分升高跳过旧坏例。

### Q262 客户成功团队反馈 Agent 经常“答得很自信但不解决问题”，优先看哪些数据？
- **考察点**：模糊反馈转诊断。
- **知识点**：task intent；resolution；abandonment；evidence；follow-up；segment。
- **复习巩固**：把“没用”拆成五类标签。
- **参考回答（60 秒）**：先抽样对话标真实任务、是否需澄清、最终动作和用户后续；看答案是否有证据、是否命中业务口径、是否只复述、用户是否改问或转人工。按场景、租户和版本分桶，与检索、工具和延迟 trace 对齐。自信语气是表象，先找任务未完成发生在哪层。

### Q263 模型能力、结构化数据和领域规则三者谁最决定数据 Agent 质量？请给反例。
- **考察点**：多因素取舍。
- **知识点**：model reasoning；data quality；semantic contract；bottleneck；counterexample。
- **复习巩固**：准备三个不同短板场景。
- **参考回答（60 秒）**：没有固定单一决定项。口径混乱时再强模型也会答错；数据正确但复杂意图解析差时模型成为限制；两者都好但权限和业务规则缺失仍不能上线。数据 Agent 通常先保证结构化数据、语义和规则可用，再用模型处理语言和开放推理，按坏例找当前限制。

### Q264 设计“每次回答为什么这样做”的可解释视图，哪些内容不应直接暴露给用户？
- **考察点**：可解释与安全边界。
- **知识点**：sources；tool summary；decision；version；chain-of-thought privacy。
- **复习巩固**：画用户视图和内部 trace 两层。
- **参考回答（设计题口径，90 秒）**：用户看到使用的指标口径、数据时间、来源、关键工具动作、SQL 或其安全摘要、限制和可复核步骤；内部保留完整 trace、版本和授权决策。不要直接暴露模型私有推理、系统提示、秘密、内部安全规则或其他租户信息。解释应基于可验证事件，不伪造思维过程。

### Q265 将单体 Agent 迁到平台时，如何迁移状态、工具、知识库和观测而不中断业务？
- **考察点**：渐进迁移设计。
- **知识点**：contract inventory；adapter；dual run；shadow；session drain；rollback。
- **复习巩固**：写四阶段迁移计划。
- **参考回答（90 秒）**：先盘点现有状态、工具 schema、知识库版本和 SLO，抽出稳定 contract；平台侧做适配并 shadow 回放。新会话小流量切换，旧会话固定旧 runtime 直至 drain，状态需要迁移时做版本转换与校验。双写只用于可对账数据，任何阶段可按 manifest 回滚。

### Q266 说一个你不会采用的 Agent 架构潮流，并给出工程理由。
- **考察点**：独立技术判断。
- **知识点**：multi-agent by default；complexity；latency；state；eval evidence。
- **复习巩固**：用项目中一次未晋级实验支撑观点。
- **参考回答（60 秒）**：我不会默认把所有任务拆成多 Agent。它会增加模型调用、状态同步、上下文损失和故障面，若角色没有独立输入输出和验证标准，通常只是更慢。我的选择是先用 Workflow 或单 Agent 建基线，只有并行、隔离或专长带来可测收益才拆分。

## N. 行为面、沟通、现场编码与开放题

### Q267 和持不同技术意见的同学如何决策？请用证据、试验或用户影响说清。
- **考察点**：协作中能否形成可验证决策。
- **知识点**：shared goal；hypothesis；experiment；decision record；revisit。
- **复习巩固**：准备 Agentic RAG Pipeline 取舍案例。
- **参考回答（60 秒）**：先统一业务目标和硬约束，把争议写成可验证假设，再用最小实验或历史坏例比较，提前约定指标和停止条件。结果与取舍写进决策记录，不能验证的部分明确 owner 和复查时间。比如候选 Pipeline 均分略升但逐题回退超门槛，我会保留原默认而非按复杂度投票。

### Q268 讲一次线上或测试失败复盘，如何避免把责任推给模型或外部依赖？
- **考察点**：责任心和系统思维。
- **知识点**：trigger；control gap；detection；containment；action item。
- **复习巩固**：用 Deep Research 外部额度失败讲事实边界，再补系统改进。
- **参考回答（60 秒）**：我会区分触发因素和系统缺口。外部服务 403 是触发，但系统还要正确分类 environment failure、停止无效重试、保留诊断并明确未完成。复盘写影响、时间线、为何监控和降级未提前发现，以及可验收修复，不用“模型幻觉”或“外部问题”结束分析。

### Q269 需求模糊时如何把“做个 Agent”拆成可验收的任务？
- **考察点**：需求澄清与交付拆解。
- **知识点**：user job；input/output；allowed action；risk；baseline；acceptance。
- **复习巩固**：把数据分析 Agent 写成一页任务定义。
- **参考回答（60 秒）**：先问谁在什么场景要完成什么任务，现有流程卡在哪里；明确输入、期望输出、数据源、允许动作、人工节点和错误代价。选一组代表任务和现有基线，定义成功、质量、延迟和安全护栏。第一版收缩到一个可闭环场景，不先讨论多 Agent 框架。

### Q270 产品坚持全自动化但你认为风险过高，如何提出替代方案？
- **考察点**：能否在分歧中推进而非只说不。
- **知识点**：risk tier；dry-run；approval；progressive automation；evidence。
- **复习巩固**：为补数工具设计三阶段自动化。
- **参考回答（60 秒）**：把风险量化为越权、错误影响面和不可恢复成本，提出分级路线：先只给建议与 dry-run，再对白名单低风险动作自动执行，高风险保留审批。用实际成功率和坏例决定扩大范围，并保留 kill switch。这样满足效率目标，又让自动化范围由证据增长。

### Q271 面试官追问一个你未亲自运行的项目指标，如何回答并继续展示能力？

### Q272 手写 LRU Cache，说明哈希表和双向链表的不变量与边界测试。
- **考察点**：经典数据结构与代码质量。
- **知识点**：O(1)；sentinel；move-to-head；evict-tail；capacity zero。
- **复习巩固**：闭卷实现并测试更新、淘汰和零容量。
- **参考回答（编码题口径，60 秒）**：哈希表从 key 定位节点，双向链表从头到尾表示新到旧，get 命中和 put 更新都移到头，超容量删尾并同步哈希表。用哨兵节点减少边界。测试空缓存、容量一、更新已有 key、访问改变淘汰顺序和重复淘汰，平均复杂度 O(1)。

### Q273 实现 top-k 高频元素或滑动窗口限流，复杂度与并发边界？
- **考察点**：算法选择与工程意识。
- **知识点**：hash count；heap/bucket；deque；timestamp；lock/distributed state。
- **复习巩固**：两题各写一个最小实现和复杂度。
- **参考回答（编码题口径，60 秒）**：top-k 用哈希计数加大小 k 的堆，复杂度 O(n log k)，或频率桶做到 O(n) 但占更多空间。滑动窗口用双端队列清理过期时间戳，单 key 均摊 O(1)。并发下复合更新需锁或原子存储，多实例应使用 Redis 脚本等共享原子状态，并说明时钟误差。

### Q274 实现一个工具调用的重试包装器，按异常类别决定是否重试。
- **考察点**：工程编码与错误语义。
- **知识点**：retryable；backoff；jitter；deadline；idempotency；cancel。
- **复习巩固**：闭卷写可注入 sleep 的小函数并测试 429、400、取消。
- **参考回答（编码题口径，60 秒）**：包装器接收最大次数、总 deadline 和错误分类器。仅对明确临时错误重试，指数退避加抖动；参数、权限、业务拒绝和取消直接抛出。带副作用工具要求幂等键，记录每次 attempt，耗尽后返回最后错误链。测试用假时钟避免真实等待。

### Q275 实现任务状态机的 compare-and-set 更新，如何测试重复消息与乱序消息？
- **考察点**：并发状态更新编码。
- **知识点**：expected version；legal transition；atomic update；idempotency；stale event。
- **复习巩固**：写 SQL `UPDATE ... WHERE version=? AND status=?`。
- **参考回答（编码题口径，90 秒）**：更新请求带 task_id、expected_version、from/to 和 event_id，事务内校验合法转换并用条件更新把 version 加一；影响行数为零时读取当前状态，已应用 event 返回幂等成功，否则报冲突。测试同一消息两次、旧版本晚到、两个并发终态和非法转换，断言只有一个写者成功。

## O. 数据集成、实时计算与湖仓链路

### Q281 全量同步、增量同步和 CDC 分别适合什么场景？如何定义同步完成？
- **考察点**：数据集成基础。
- **知识点**：snapshot；watermark；log-based CDC；cutover；reconciliation。
- **复习巩固**：画初始全量加 CDC 衔接。
- **参考回答（60 秒）**：全量适合初始化或小表，增量依赖可靠更新时间或递增键，CDC 从日志捕获插入、更新和删除。同步完成不能只看任务退出，要定义源端截止位点、目标已应用、延迟、行数或校验和对账。没有更新时间可用数据库日志、触发器或快照差异，但各有权限和成本。

### Q282 Kafka 的 partition、consumer group 和 offset 如何共同决定并行度、顺序与重复消费？
- **考察点**：消息队列核心语义。
- **知识点**：partition order；group assignment；offset commit；rebalance；at-least-once。
- **复习巩固**：画三分区两消费者和故障重平衡。
- **参考回答（60 秒）**：分区内有序，消费组内一个分区同一时刻由一个消费者处理，并行度上限受分区数限制。offset 记录组的消费位置。先处理后提交可能重复但不易丢，先提交后处理可能丢；常用前者配幂等。rebalance 也会引入重复窗口。

### Q283 解释 event time、watermark、window 和 allowed lateness。迟到数据超过窗口后如何修正下游结果？
- **考察点**：流处理时间与迟到数据。
- **知识点**：event time；watermark；window；late event；upsert；retraction。
- **复习巩固**：画一条超 watermark 事件的处理。
- **参考回答（90 秒）**：event time 按业务发生时间计算，window 聚合时间范围，watermark 表示系统认为事件时间已推进的位置，allowed lateness 在窗口关闭后再等一段。超过后可进 side output，离线回补或发修正流，通过可 upsert 的结果表更新旧值。下游需支持版本或撤回，报告标修订时间。

### Q284 Spark 批处理、Structured Streaming 与 Flink 应如何选择？不要只回答吞吐和延迟。
- **考察点**：计算引擎选型维度。
- **知识点**：ecosystem；state；event time；exactly-once scope；operations；skills。
- **复习巩固**：按已有栈、状态复杂度、运维能力比较。
- **参考回答（60 秒）**：除吞吐延迟，还看团队生态、SQL/ML 集成、状态与事件时间复杂度、故障恢复、连接器、升级和运维。已有 Spark 数仓且流需求简单，Structured Streaming 迁移成本低；复杂事件时间和长状态场景常更适合 Flink。最终用真实作业压测和运维成本决定。

### Q285 数据湖表格式为什么需要 snapshot、schema evolution、compaction 和 time travel？

### Q286 设计一个从业务库 CDC 到湖仓、实时数仓和指标服务的链路，说明一致性、回放、血缘和监控。

### Q289 上游字段改名、类型变化或新增枚举值时，如何发现 schema drift 并保护下游？

## P. 实验评估、画像标签与增强分析

### Q295 A/B 实验中的随机化单位、分流、曝光和指标窗口分别是什么？为什么“进入实验组”不等于“真实曝光”？

- **知识点**：primary；guardrail；diagnostic；pre-registration；multiple testing；FDR。
- **复习巩固**：为推荐实验设计三层指标。
- **参考回答（60 秒）**：主指标直接对应目标且数量少，护栏保护体验、风险和长期价值，诊断指标解释机制。实验前固定定义、方向、窗口和分析方法；多指标使用多重检验校正或明确探索性标签，完整报告所有预注册指标，避免只挑显著项。

### Q298 CUPED 等方差缩减方法解决什么问题？使用前需要哪些假设和历史数据检查？
- **考察点**：实验统计进阶理解。
- **知识点**：pre-period covariate；correlation；unaffected covariate；variance reduction；missingness。
- **复习巩固**：写 CUPED 直觉公式并说明假设。
- **参考回答（知识题口径，90 秒）**：CUPED 用实验前与目标指标相关的协变量减去可预测波动，提高统计功效，不改变随机化。需确认协变量在处理前、不会被实验影响、与指标稳定相关，缺失和异常处理一致，并检查两组预实验分布。弱相关时收益有限，不能修复 SRM 或偏差。

### Q299 实验指标依赖次日数仓数据，但上游延迟或回补，报告如何标记未就绪、重算和版本变化？
- **考察点**：实验报告的数据版本治理。
- **知识点**：readiness；watermark；provisional；recompute；snapshot；notification。
- **复习巩固**：设计报告状态和版本字段。
- **参考回答（90 秒）**：报告绑定分区 readiness、数据截至时间、指标版本和计算 snapshot。上游未就绪时标 provisional 或阻断，不给最终胜负；回补后重算生成新版本，展示变化原因并通知订阅者。旧版本保留可追溯，不静默覆盖。

### Q300 设计一个实验分析 Agent。它可以解释报告、找相似实验和生成排查建议，但为什么不能替代随机化与统计检验？
- **考察点**：Agent 在实验平台中的合理边界。
- **知识点**：report explanation；similar experiment；diagnosis；causal design；statistical engine。
- **复习巩固**：列 Agent 能做与不能做各四项。
- **参考回答（设计题口径，90 秒）**：Agent 可解释报告、检索口径与相似实验、调用统计服务、检查 SRM 并生成排查建议；随机分流、曝光、指标计算和显著性由实验平台的确定性服务完成。模型不能把观察相关性变因果，也不能临时改指标。回答引用实验版本、样本、方法和限制。

### Q301 实验胜出后如何固化为 Feature、灰度发布、长期反转观察并支持回滚？
- **考察点**：从实验到发布闭环。
- **知识点**：feature flag；ramp-up；holdout；guardrail；rollback；ownership。
- **复习巩固**：画实验组到全量的阶段。
- **参考回答（60 秒）**：将处理固化为版本化 Feature 和配置，先小流量灰度并保持护栏和告警；逐步扩大时看分群和系统指标。保留长期 holdout 或反转观察，识别新奇效应和漂移。回滚开关、owner 和触发阈值在发布前确定。

### Q302 历史实验如何按业务背景、人群、指标和结论检索？怎样避免 Agent 把相关性案例当成因果证据？
- **考察点**：实验知识库与证据等级。
- **知识点**：structured metadata；hybrid search；experiment design；causal scope；disclaimer。
- **复习巩固**：为实验记录设计 metadata。
- **参考回答（90 秒）**：实验以业务域、假设、随机化单位、人群、Feature、指标、时间和结论结构化入库，文本做混合检索。结果明确区分随机实验、观察分析和经验记录，只把通过设计与质量检查的实验结论作为因果证据，且限定适用人群和版本；相似案例用于提出假设，不直接外推。

### Q303 事实属性、统计标签、规则标签和模型标签有什么区别？各自如何更新和解释？
- **考察点**：画像标签基础。
- **知识点**：source fact；aggregation；rule；prediction；freshness；explainability。
- **复习巩固**：各举一个脱敏例子。
- **参考回答（45 秒）**：事实属性来自权威源直接记录；统计标签由时间窗口聚合；规则标签按显式条件计算；模型标签是预测结果并带模型版本和分数。更新分别随源变更、调度窗口、规则发布和模型推理。解释时必须显示类型、口径、时间和版本。

### Q304 标签的口径、值域、计算周期、版本、负责人和下游依赖怎样治理？
- **考察点**：标签平台治理。
- **知识点**：tag contract；domain；schedule；owner；lineage；deprecation。
- **复习巩固**：写一份标签 contract。
- **参考回答（60 秒）**：每个标签有稳定 ID、业务定义、类型和值域、来源、计算逻辑、周期、SLA、版本、owner、权限和质量规则；血缘记录下游人群与应用。变更做兼容和影响分析，破坏性版本并行迁移，旧版按下游确认后下线。模型不能凭名称猜标签含义。

### Q305 自然语言圈选人群时，如何处理标签歧义、人数预估、敏感属性、最小人群阈值和导出审批？
- **考察点**：画像 Agent 的安全设计。
- **知识点**：semantic parse；clarification；count preview；sensitive tag；k-anonymity；approval。
- **复习巩固**：画 query plan 到导出的审批链。
- **参考回答（设计题口径，90 秒）**：先把自然语言解析为标签 ID、条件和时间，歧义时让用户确认；dry-run 只返回受权限保护的人数区间和影响面。敏感属性按用途和角色限制，低于最小人群阈值拒绝或扩大分组。导出绑定计划 hash、字段、目的和有效期审批，结果水印、限时并审计。

### Q306 设计一个指标异常归因 Agent，如何结合维度下钻、变更事件、血缘和实验信息，避免输出伪因果？
- **考察点**：增强分析核心设计。
- **知识点**：anomaly；dimension drill-down；change event；lineage；experiment；hypothesis。
- **复习巩固**：把事实、候选原因、验证结果分层输出。
- **参考回答（设计题口径，90 秒）**：先确认指标口径、数据质量和异常统计成立，再做维度贡献下钻，关联发布、实验、上游变更和血缘告警。Agent 生成候选假设并调用工具找支持与反证，输出“观察到的变化、证据、仍未知”，不把同时发生写成因果。因果结论需实验或明确机制验证。

## Q. Agent 平台工程、模型服务与开发者体验

### Q307 Agent 平台应提供代码 SDK、配置 DSL、可视化 Workflow 还是三者并存？分别服务哪些用户？
- **考察点**：开发体验分层设计。
- **知识点**：SDK flexibility；DSL governance；visual builder；single IR；round-trip。
- **复习巩固**：为算法、数据开发、运营分配入口。
- **参考回答（60 秒）**：可以三者并存，但底层应编译到同一版本化 IR 和运行 contract。SDK 服务复杂扩展，DSL 服务可审查配置，可视化面向标准流程和业务用户。要避免三套语义分叉，明确哪些高级能力不能在 UI 编辑，并提供导入导出和 diff。

### Q308 工具注册中心如何管理 schema、负责人、权限、版本、健康状态和下线影响？
- **考察点**：Tool Registry 平台设计。
- **知识点**：immutable version；owner；policy；health；dependency graph；deprecation。
- **复习巩固**：设计工具元数据结构。
- **参考回答（设计题口径，90 秒）**：每个工具版本保存 schema、语义、owner、风险、认证方式、权限、SLO、依赖和兼容范围；发布做 contract 与安全测试。运行时监测成功率和延迟，异常可熔断。通过 workflow/session 依赖图评估下线，先弃用提示和迁移，再阻止新引用，最后下线。

### Q309 tool schema、事件协议或 SDK 升级时，怎样做兼容性检查、双版本运行和迁移？
- **考察点**：平台协议演进。
- **知识点**：semantic diff；additive change；version negotiation；adapter；telemetry。
- **复习巩固**：为字段重命名设计迁移。
- **参考回答（90 秒）**：发布前做 schema semantic diff，新增可选字段通常兼容，删除、改类型和语义需新主版本。runtime 按 manifest 路由双版本，适配层转换旧请求，遥测旧版本使用者和失败。提供迁移工具与截止期，旧会话固定原版本，确认流量归零后下线。

### Q310 Agent 模板、Skill 和 Workflow 如何发布、继承、覆盖和回滚，避免复制后永久分叉？
- **考察点**：复用资产治理。
- **知识点**：package；base version；overlay；lockfile；diff；rollback。
- **复习巩固**：设计 base 加 tenant overlay 模型。
- **参考回答（60 秒）**：资产作为不可变包发布，实例引用明确 base version，只允许在声明的扩展点做 overlay；依赖写 lockfile。升级展示 base 变更与本地覆盖冲突，自动化兼容检查后再迁移。回滚切回旧 manifest，禁止复制一份后失去上游关系。

### Q311 Prompt 或工具配置支持热更新时，如何保证同一 session 行为稳定、变更可审计且能快速回滚？
- **考察点**：动态配置一致性。
- **知识点**：snapshot；session pin；atomic publish；audit；rollback。
- **复习巩固**：画配置从草稿到生效流程。
- **参考回答（90 秒）**：配置编辑生成新不可变版本，经校验后原子发布；新 session 读取当前版本，已有 session 固定启动时 snapshot，除非显式迁移。每次运行记录版本与发布者，灰度异常时指针切回旧版。紧急安全禁用可覆盖 session，但要明确为 policy 事件并审计。

### Q312 模型网关应统一鉴权、限流、重试、路由、计量和日志中的哪些能力？哪些 provider 差异不该抹平？
- **考察点**：模型接入平台抽象。
- **知识点**：auth；quota；error taxonomy；usage；capability；native feature。
- **复习巩固**：做公共 contract 与扩展能力表。
- **参考回答（60 秒）**：统一租户鉴权、配额、请求 ID、错误大类、有限重试、usage 和安全日志；路由基于能力、SLO 和成本。结构化输出、思考控制、缓存、上下文窗口、工具语义和原生错误需显式 capability，不能强抹成最低公分母。缺失数据保持 unknown。

### Q313 Prompt cache 的命中条件、收益和失效因素是什么？动态用户数据放在哪里更合理？
- **考察点**：Prompt 缓存原理与工程使用。
- **知识点**：stable prefix；exact tokens；model；TTL；prefix order；dynamic suffix。
- **复习巩固**：把系统提示和用户上下文重新排序。
- **参考回答（45 秒）**：Prompt cache 通常要求同模型下稳定前缀 token 匹配，收益是减少重复前缀计算、延迟和费用；模型、前缀内容、顺序、TTL 或 provider 策略变化会失效。稳定系统规则和工具定义放前面，动态用户数据、时间和请求放后面，同时不为命中牺牲权限隔离。

### Q314 continuous batching、KV cache、量化和 speculative decoding 各优化什么，可能牺牲什么？应用后端需要理解到什么程度？
- **考察点**：推理性能基础与岗位边界。
- **知识点**：throughput；memory；precision；draft model；latency；quality。
- **复习巩固**：为四项各写优化对象和代价。
- **参考回答（知识题口径，90 秒）**：continuous batching 提高 GPU 吞吐但调度影响尾延迟；KV cache 复用历史注意力，消耗显存；量化降内存和算力，可能损失精度或受硬件限制；投机解码用草稿模型减少大模型步数，收益依接受率。应用后端应理解容量、延迟、成本和质量影响，不把这些说成自己的训练或推理内核经验。

### Q315 模型调用和工具调用的瓶颈不同，怎样分别做容量估算、排队、准入控制和负载保护？
- **考察点**：异构依赖容量设计。
- **知识点**：tokens/sec；GPU concurrency；I/O QPS；queue；bulkhead；deadline。
- **复习巩固**：分别写模型和数据库工具的容量公式。
- **参考回答（设计题口径，90 秒）**：模型侧按输入输出 token、并发、批处理和 tokens/sec 估算，队列关注首 token 与总时延；工具侧按各依赖 QPS、连接池、耗时和副作用分别建池。入口按 run 预算预留，模型与工具 bulkhead 隔离，队列过长就降级或拒绝。不能用一套全局 semaphore 掩盖不同瓶颈。

### Q316 如何给一次 Agent 运行设置 token、时间、工具次数和金额预算，并在耗尽前降级？
- **考察点**：运行预算控制。
- **知识点**：budget ledger；reserve；remaining；finalization；fallback；unknown cost。
- **复习巩固**：设计预算状态和每步检查点。
- **参考回答（60 秒）**：run 创建时按租户和场景设置总 token、wall time、模型/工具次数和金额上限，每步先估算并预留，完成后结算。接近阈值进入 finalizing，停止宽泛探索、缩小候选、用便宜模型或返回部分结果与缺口。成本未知按保守估计，绝不记零继续无限执行。

### Q317 设计一个共享评测服务，如何管理数据集、评测器、版本、基线、回归门禁和人工复核？
- **考察点**：Eval 平台系统设计。
- **知识点**：dataset registry；manifest；runner；evaluator；baseline；gate；review queue。
- **复习巩固**：按控制面、执行面、结果面画图。
- **参考回答（设计题口径，90 秒）**：控制面管理不可变数据集、样本权限、评测器和基线；runner 根据 manifest 固定代码、模型、Prompt、工具与预算，逐例写结果；比较器按场景计算均值和逐例回退，触发发布门禁。低置信 judge、关键损失和争议样本进入人工复核，结论与版本可追溯，敏感集隔离。

### Q318 一个大客户的长任务占满 worker 和模型配额，如何防 noisy neighbor 又保留高优先级通道？
- **考察点**：多租户资源隔离。
- **知识点**：per-tenant quota；weighted fair queue；reservation；preemption；priority abuse。
- **复习巩固**：设计租户并发和全局预留。
- **参考回答（90 秒）**：租户有独立并发、队列、token 和模型额度，全局用加权公平调度；worker 和模型资源按池隔离，为系统和高优请求保留容量。长任务分步释放资源，可在安全 checkpoint 暂停而非任意杀死。优先级需授权且有上限，持续监控等待时间和饥饿。

### Q319 流量突增时，哪些请求该排队、降级、拒绝或中断？如何防止重试风暴？
- **考察点**：过载保护策略。
- **知识点**：admission；deadline；priority；fallback；Retry-After；jitter；load shedding。
- **复习巩固**：做请求风险与价值矩阵。
- **参考回答（90 秒）**：短时可恢复且 deadline 足够的请求排队；低风险查询可用缓存、便宜模型或部分结果降级；无容量且即将超时的请求尽早拒绝；已运行任务只在有安全 checkpoint 时中断。返回 Retry-After，客户端指数退避加抖动，服务端限每请求与每租户重试，熔断故障依赖。

### Q320 设计本地调试、trace 回放、mock tool、Prompt 对比和一键复现能力，怎样降低 Agent 问题定位成本？
- **考察点**：Agent 开发者体验与可复现性。
- **知识点**：run manifest；event viewer；mock fixture；side-by-side diff；redaction；replay boundary。
- **复习巩固**：以一个坏例走完整调试流程。
- **参考回答（90 秒）**：每次 run 导出脱敏 manifest、事件、版本、工具输入输出引用和错误。调试器按时间线展示模型、工具、状态和预算；mock tool 用固定 fixture 重放，Prompt/模型对比在同输入与 mock 下生成逐层 diff。一键复现默认禁真实副作用，外部非确定调用明确标不可完全复现。这样能定位最早偏离层，而非只看最终答案。

## R. 工具、上下文与知识版本治理

### Q321 如何解释“模型负责内容，代码负责边界”？哪些判断可以交给模型，哪些必须由确定性代码执行？
- **考察点**：能否划清概率推理和确定性控制的责任。
- **知识点**：语义理解；规划；schema；权限；状态机；门禁。
- **复习巩固**：从自己的三个项目各找一个模型判断和一个代码约束。
- **参考回答（60 秒）**：模型适合做意图理解、候选规划、摘要和自然语言生成；代码负责参数校验、权限、副作用确认、状态转移、预算和验收门禁。比如模型可以建议调用哪个工具，但 policy 决定是否允许；Worker 可以声称完成，服务端仍要校验 assignment 和产物。边界会随风险调整，但安全与一致性不能只靠提示词。

### Q322 工具返回结果过大时，怎样做摘要、分页、引用和按需再取，避免信息丢失与上下文爆炸？
- **考察点**：大工具结果的上下文治理能力。
- **知识点**：artifact；cursor；摘要；引用；lazy fetch；token budget。
- **复习巩固**：为日志查询工具设计元数据、分页和二次读取接口。
- **参考回答（90 秒）**：完整结果存为 artifact，只向模型返回摘要、大小、schema、关键片段、引用 ID 和下一页 cursor。模型需要细节时按引用或范围再取，不能反复返回全量。摘要要保留错误、限定条件和反证，并能回到原文验证；每次读取受 token、权限和时间预算约束。

### Q323 有副作用工具在执行前需要用户确认时，确认记录应绑定哪些不可变字段，如何防止确认后参数被替换？
- **考察点**：是否理解确认与执行之间的 TOCTOU 风险。
- **知识点**：canonical request；hash；version；identity；expiry；idempotency key。
- **复习巩固**：画“生成提案、确认、执行、审计”四步链路。

### Q324 为什么缓存 `tools/list` 不能代替调用时权限校验？工具描述、可见性和用户权限发生变化时如何处理？

### Q325 embedding 模型升级时，如何完成双写、回填、索引切换和回滚，并避免新旧向量混检？

### Q326 如何识别同一文档的不同版本、重复 URL、镜像内容和正文漂移？去重后如何保留来源关系？

### Q327 用户查询历史时点的数据或制度，怎样让检索使用当时有效的知识版本，而不是被最新版本覆盖？

### Q328 会话摘要压缩错了，Agent 如何发现并回退到原始消息或证据，而不是在错误摘要上继续推理？

### Q329 如何评测上下文压缩质量？除了 token 降幅，还应检查哪些任务信息与错误类型？

### Q330 用户要求“忘记我”时，需要删除或失效哪些会话、记忆、索引、缓存、日志与评测副本？

## S. Python 后端、部署与性能诊断

### Q331 `asyncio.gather`、`TaskGroup` 和异步队列在失败传播、取消和背压方面有什么区别？
- **考察点**：Python 结构化并发基础。
- **知识点**：gather；TaskGroup；exception group；queue；backpressure；cancellation。
- **复习巩固**：写三个最小示例观察一个子任务失败后的行为。
- **参考回答（60 秒）**：`gather` 适合收集一组已知任务，但失败和兄弟任务处理要显式设计；`TaskGroup` 提供结构化生命周期，一个任务失败会取消其余任务并聚合异常；异步队列适合持续生产消费并用容量形成背压，但需要 worker 退出和 drain 协议。选择取决于任务是否固定、是否要联动取消和是否持续流入。

### Q332 在 event loop 中直接做阻塞文件 I/O 或 CPU 密集计算会发生什么，如何定位和改造？
- **考察点**：异步服务卡顿的根因理解。
- **知识点**：event loop lag；blocking I/O；to_thread；process pool；profiling。
- **复习巩固**：用定时 heartbeat 验证阻塞前后的 loop lag。
- **参考回答（60 秒）**：阻塞操作占住 event loop，会让所有协程的流式输出、超时和取消一起延迟。通过 loop lag、慢回调日志和 profiler 定位；阻塞文件 I/O 放到线程，CPU 密集任务放进程池或独立服务，调用侧保留超时和取消语义。只迁移阻塞部分，状态变更仍留在事件循环中。

### Q333 生产者持续快于消费者时，如何通过有界队列、并发限制、丢弃或降级建立背压？
- **考察点**：过载时能否保护系统而非无限堆积。
- **知识点**：bounded queue；admission；flow control；drop policy；deadline；load shedding。
- **复习巩固**：为 SSE 事件和长任务队列分别设计背压策略。
- **参考回答（设计题口径，90 秒）**：入口先做准入和租户限流，内部使用有界队列，生产者在队列满时等待、降级或拒绝。状态事件可合并中间进度但不能丢最终状态；高价值长任务按 deadline 和优先级排队，过期任务提前失败。监控队列长度、等待时间和消费速率，避免靠增加内存隐藏容量问题。

### Q334 如何发现和治理 async task 泄漏、未回收连接和悬挂子进程？
- **考察点**：异步资源生命周期管理。
- **知识点**：task registry；structured concurrency；finally；context manager；child process；shutdown。
- **复习巩固**：设计一次请求结束后的资源不变量检查。
- **参考回答（60 秒）**：所有后台任务进入可追踪 registry 或 TaskGroup，连接和锁用异步 context manager，取消路径在 `finally` 释放；子进程保存 handle，超时后先优雅终止再强杀并等待回收。监控活跃 task、连接池占用和孤儿进程，测试结束断言资源回到基线，禁止无所有者的 `create_task`。

### Q335 如何为 reservation、compare-and-set 或取消竞态编写可重复的回归测试，而不是依赖偶现？
- **考察点**：并发正确性的可测性。
- **知识点**：barrier；event；controlled scheduler；CAS；invariant；repeat。
- **复习巩固**：用两个事件精确控制两个任务读写顺序。
- **参考回答（90 秒）**：把关键步骤暴露为可注入同步点，用 barrier 或 event 让两个任务先读同一版本，再按指定顺序提交；断言只有一个 reservation/CAS 成功，旧 attempt 被拒绝，取消后资源释放且终态唯一。测试覆盖两种顺序并重复运行，失败时输出事件序列。靠随机 sleep 只能增加概率，不能证明竞态被覆盖。

### Q336 TLS、Cookie、Session、JWT 各解决什么问题？服务端收到 JWT 后至少验证哪些字段？
- **考察点**：后端认证与传输安全基础。
- **知识点**：transport encryption；cookie carrier；server session；signed token；iss；aud；exp；alg。
- **复习巩固**：画浏览器登录到 API 鉴权链路。
- **参考回答（60 秒）**：TLS 保护传输并验证服务端身份；Cookie 是浏览器携带数据的机制；Session 把登录状态保存在服务端；JWT 是签名声明载体，不等于加密。服务端至少校验签名算法与密钥、issuer、audience、过期时间、not-before 和必要权限，还要处理撤销与密钥轮换，不能只解码 payload。

### Q337 索引失效和慢 SQL 的常见原因是什么？从执行计划到锁等待应按什么顺序排查？
- **考察点**：MySQL 性能诊断基本功。
- **知识点**：EXPLAIN；selectivity；leftmost prefix；function/cast；filesort；lock wait；statistics。
- **复习巩固**：准备两个联合索引失效和一个锁等待案例。

### Q338 如何缓存检索或查询结果，同时保证租户、用户权限或数据版本变化后不会泄露旧结果？
- **考察点**：缓存性能与安全一致性的权衡。
- **知识点**：tenant key；permission fingerprint；data version；TTL；revocation；negative cache。
- **复习巩固**：设计一个包含身份、权限和知识版本的 cache key。

### Q339 为什么 provider 限流导致的排队不能简单靠 HPA 扩容解决？应观察什么指标并如何降级？
- **考察点**：能否区分本地容量和外部依赖瓶颈。
- **知识点**：429；external quota；queue age；concurrency；circuit breaker；fallback。
- **复习巩固**：画 CPU 低但队列增长的故障图。
- **参考回答（90 秒）**：瓶颈是 provider 配额时，扩 worker 只会制造更多并发和 429，放大重试风暴。应同时看本地 CPU、队列年龄、外部成功率、429、provider 并发和 token 配额。入口限制新请求，按 Retry-After 退避，熔断故障模型并路由到已验证备选或返回排队状态；HPA 只针对本地资源饱和信号。

### Q340 如何把一次 Agent 请求拆成排队、TTFT、模型、检索、重排、工具、数据库和序列化耗时，并定位 p99？
- **考察点**：端到端响应效率诊断。
- **知识点**：critical path；span；TTFT；queue time；parallel branch；tail latency。
- **复习巩固**：为一次含两次模型调用的请求画 trace 瀑布图。
- **参考回答（90 秒）**：统一 request/run ID，为网关排队、每次模型调用的 TTFT 与生成、检索、重排、工具、数据库和序列化建 span，并标记并行关系和重试。按场景、租户、模型与工具分桶看 p95/p99，定位关键路径而不是把所有耗时相加。再关联队列深度、错误和资源指标，用慢样本 trace 验证根因。

## T. 数据治理、租户安全与产品闭环

### Q341 从客户端埋点到指标看板，完整描述采集、传输、清洗、存储、建模、计算、服务和消费链路。

### Q345 查询结果为空时，怎样区分确实无数据、SQL 错误、数据未就绪和权限过滤？

### Q346 SQL AST 校验相比字符串黑名单有什么优势和局限？哪些风险仍需查询引擎和权限系统兜底？

### Q347 如何分别评测 SQL 语法正确、执行正确和业务口径正确？等价 SQL 如何处理？

- **知识点**：parse rate；execution accuracy；result equivalence；semantic judge；gold variants；holdout。
- **复习巩固**：为同一结果的两条等价 SQL 设计判分。
- **参考回答（90 秒）**：语法层只检查能否解析；执行层在隔离快照上比较结果、错误与资源；业务层校验指标、时间、粒度、过滤和 join 语义。不能只做字符串匹配，等价 SQL 用规范化 AST、结果集合和允许的 gold variants 判断。涉及非确定顺序、浮点和时间要定义容差，危险 SQL 即使结果对也不能通过安全门禁。

### Q348 多租户 Agent 从用户登录到模型规划、工具调用和数据查询，身份与授权上下文如何端到端传递？
- **考察点**：多租户身份链与防止 confused deputy。
- **知识点**：user identity；tenant；service identity；delegation；scoped token；audit context。
- **复习巩固**：画用户、Agent 服务、MCP 工具和数据库四跳身份链。
- **参考回答（设计题口径，90 秒）**：网关认证用户并确定租户，运行时保存不可由模型修改的身份上下文；模型只提出动作。工具调用使用短期、最小范围的 delegated token，服务身份不能扩大用户权限；数据库按用户或受控代理执行行列权限。每一跳传 request/run、用户、租户、授权范围和审计 ID，禁止把身份放进可被 Prompt 覆盖的普通参数。

### Q349 租户级数据导出、删除、保留期和备份副本如何治理，怎样证明删除已经覆盖各层？
- **考察点**：To B 数据生命周期治理。
- **知识点**：inventory；export approval；retention；tombstone；backup expiry；deletion evidence。
- **复习巩固**：列在线库、对象存储、索引、缓存、日志和备份六层。
- **参考回答（设计题口径，90 秒）**：资产目录记录每类租户数据的位置、owner、用途和保留期；导出需权限、目的、范围与审批。删除任务先阻止新访问，再清理在线数据、索引、缓存和派生副本，备份按不可变保留策略到期淘汰。每层产生可核验状态并汇总删除证明，失败可重试；不承诺无法验证的即时全介质抹除。

### Q350 如何把专家反馈转成规则、数据、工具校验和评测集，而不是持续往 Prompt 里打补丁？
- **考察点**：Agent 迭代是否形成可维护闭环。
- **知识点**：failure taxonomy；policy；tool validation；gold case；regression；prompt scope。
- **复习巩固**：把一个“回答口径错”坏例分别映射到四种修复层。
- **参考回答（60 秒）**：先归因反馈：稳定业务规则进入语义层或 policy，参数与权限错误进入工具校验，知识缺口进入数据和元数据，表达偏好才考虑 Prompt。每个真实坏例脱敏后加入回归集，记录修复层、版本和预期。Prompt 只保留模型需要的指导，避免把确定性规则堆成不可测试文本。

## U. 工程编码与综合设计

### Q351 手写嵌套 JSON 的递归合并，并说明数组、空值和类型冲突策略。
- **考察点**：递归、边界定义与代码表达。
- **知识点**：mapping；deep copy；list policy；null semantics；type conflict；complexity。
- **复习巩固**：闭卷实现并测试空对象、嵌套冲突和数组策略。
- **参考回答（60 秒）**：先澄清策略：两个值都是对象时递归合并；数组默认整体替换或按业务指定拼接；右侧空值是覆盖还是忽略必须明确；类型冲突通常右侧覆盖，也可严格报错。实现避免原地修改输入，时间复杂度与访问节点数线性。面试中先说 contract，再写代码和边界测试。

### Q352 给定 ToolCall 事件流，校验每个 call 都有匹配 result、顺序合法且取消后没有悬空调用。
- **考察点**：状态机与事件一致性编码能力。
- **知识点**：call_id；finite state machine；duplicate；orphan result；cancel；terminal state。
- **复习巩固**：实现 `pending/running/completed/failed/cancelled` 转移表。
- **参考回答（90 秒）**：按 `call_id` 保存状态，收到 call 只能从不存在进入 pending/running，result 只能结束已存在且未终止的 call；重复同结果可幂等，冲突结果报错，孤儿 result 拒绝。流结束或取消时扫描未终止调用，要求补 cancelled/error ToolMessage 后才能封存 session。测试乱序、重复、缺失和取消竞态。

### Q353 从乱序日志中合并同一 request 的事件，计算延迟分位数并统计失败类别。
- **考察点**：数据处理与可观测性基础。
- **知识点**：group by request；timestamp；event state；quantile；missing event；failure taxonomy。
- **复习巩固**：用小样本手算 p95，并处理缺开始或缺结束事件。
- **参考回答（60 秒）**：按 request ID 分组并按时间与序号排序，从 start 到 terminal 计算延迟，缺失或冲突事件单独标记 incomplete，不能当成功。分位数需先说明样本定义和插值方法，失败按标准 taxonomy 统计。大数据量用流式聚合或近似分位数，但保留慢请求 ID 供 trace 下钻。

### Q354 给定任务依赖边，检测环并输出可执行顺序；出现环时返回可解释路径。
- **考察点**：拓扑排序和错误解释能力。
- **知识点**：indegree；Kahn；DFS color；cycle path；O(V+E)。
- **复习巩固**：分别用 Kahn 和 DFS 写一遍并比较输出。
- **参考回答（60 秒）**：用邻接表和入度做 Kahn 拓扑排序，持续弹出入度为零的任务；输出数量小于节点数说明有环。为了返回具体环路，再对剩余子图做带颜色和 parent 的 DFS，遇到灰色节点回溯路径。复杂度是 `O(V+E)`，重复边和缺失节点要先规范化。

### Q355 设计 SQL AST allowlist 的最小接口和测试用例，覆盖只读、函数、表字段权限和扫描限制。
- **考察点**：安全校验接口设计与测试意识。
- **知识点**：parse；visitor；policy context；decision；reason；dialect；explain。
- **复习巩固**：写 `validate(sql, context) -> decision` 的最小数据结构。
- **参考回答（设计题口径，90 秒）**：接口输入 SQL、方言、用户/租户和 policy，解析 AST 后只允许 SELECT，遍历表、字段、函数、子查询和 limit，返回 allow/deny、原因与规范化摘要。扫描量通过 Explain 或引擎 dry-run 再判断。测试正常查询、注释绕过、未授权列、危险函数、笛卡尔积、超大分区和解析失败；默认拒绝未知节点。

### Q356 设计 tenant、user、run 三层 token bucket，说明键、时钟、原子更新和公平性。
- **考察点**：分层限流与并发数据结构设计。
- **知识点**：token bucket；hierarchical key；monotonic clock；atomic script；weighted fair；rollback。
- **复习巩固**：手算一次三层桶扣减和补充过程。
- **参考回答（90 秒）**：每层用稳定 ID 建桶，记录容量、速率、剩余 token 和最后更新时间，以单调时钟补充。一次请求必须原子检查并扣减租户、用户、run 三层，任一不足则全部不扣；分布式可用事务或 Redis Lua。租户层防总量超限，用户层防独占，run 层限制失控任务；高优先级用受控权重，不能绕开租户总额度。

### Q357 如何测试一个 retry 包装器不会重试不可重试错误，也不会突破 deadline 与 retry budget？
- **考察点**：重试策略的确定性验证。
- **知识点**：error classifier；fake clock；attempt count；backoff；deadline；idempotency。
- **复习巩固**：用 fake function 依次返回 429、成功和权限错误。
- **参考回答（60 秒）**：注入 fake clock、sleep 和调用函数，逐类断言：临时错误按上限退避后成功，权限/参数错误只调用一次，剩余 deadline 不足时不再 sleep 或发起请求，budget 用尽返回最后分类。检查 jitter 范围和累计等待，并验证有副作用调用未声明幂等时禁止自动重试。

### Q358 设计多区域 Agent API，明确状态归属、流量切换、RPO、RTO 和外部副作用语义。
- **考察点**：高可用设计能否落到状态和业务语义。
- **知识点**：active-active；home region；replication；failover；RPO/RTO；idempotency；fencing。
- **复习巩固**：先分别回答无状态请求和长任务的容灾策略。
- **参考回答（设计题口径，90 秒）**：先按业务确定 RPO/RTO。入口和无状态 API 可多活，长任务选择 home region，canonical state 跨区复制并带版本；故障切换用 fencing 防双主。外部工具副作用用全局幂等键和审计，无法确认结果时标 unknown 并人工对账，不能假装 exactly-once。会话和索引版本随 run 固定，演练区域失联与恢复回切。

### Q359 设计 SSE 网关，支持重连、回放、取消、背压、敏感字段过滤和最终状态查询。
- **考察点**：流式 Agent 服务综合设计。
- **知识点**：event id；append log；replay window；cancel API；bounded buffer；redaction；status endpoint。
- **复习巩固**：画 run 事件日志、SSE 连接和状态查询三者关系。
- **参考回答（设计题口径，90 秒）**：后端把状态事件写入有序 append log，SSE 只是投影；客户端用 Last-Event-ID 在保留窗口内回放，超窗后从 snapshot 续接。取消走独立幂等 API 并传播 token，最终状态由任务状态机写。每连接使用有界缓冲，合并中间进度但不丢终态；发送前按字段策略脱敏，断线时可通过状态接口查询结果。

### Q360 模型能力提升后，怎样判断一个复杂 Workflow 应简化或删除？如何证明删减没有破坏质量和安全？
- **考察点**：是否具备主动删除复杂度的工程判断。
- **知识点**：baseline；ablation；failure coverage；latency；cost；safety invariant；rollback。
- **复习巩固**：选一个 planner 或多 Agent 节点做消融实验设计。
- **参考回答（60 秒）**：先明确该 Workflow 每个节点防什么失败，再做消融：新模型加简化链路对同一冻结集和线上影子流量，比较任务成功、逐例回退、安全门禁、延迟和成本。若节点没有独立收益且规则可由更小 contract 保留，就删除；权限、审计和副作用校验不能随模型变强一起删。灰度发布并保留快速回滚。
