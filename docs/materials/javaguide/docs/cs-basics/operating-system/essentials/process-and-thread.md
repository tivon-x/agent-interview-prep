# 进程与线程

> 根据 [JavaGuide 原文](https://github.com/Snailclimb/JavaGuide/blob/992dae31eade2a34ba8dbbbcf5ed9de5511325ec/docs/cs-basics/operating-system/process-and-thread.md) 整理；快照版本：`992dae31eade2a34ba8dbbbcf5ed9de5511325ec`。

## 程序、进程与线程

程序是存放在文件中的指令和数据；进程是程序的一次运行，拥有虚拟地址空间、文件描述符和权限等资源。同一程序可以启动多个相互隔离的进程。线程是进程内的执行流，现代操作系统通常以线程作为 CPU 调度单位。

| 维度 | 进程 | 同一进程内的线程 |
| --- | --- | --- |
| 定位 | 资源与隔离边界 | 执行和调度单位 |
| 地址空间 | 默认相互独立 | 共享代码、数据、堆和映射区域 |
| 私有信息 | 进程 ID、地址空间、资源表等 | 线程 ID、栈、寄存器、程序计数器、线程本地存储 |
| 通信 | 管道、共享内存、Socket 等进程间通信 | 可访问共享内存，但读写共享可变数据需要同步 |
| 创建和切换 | 通常更重 | 同进程线程通常更轻 |
| 故障隔离 | 一个进程崩溃通常不直接破坏另一进程 | 线程非法访问等可能导致整个进程退出 |

线程还共享进程打开的文件、Socket、工作目录等。Java 堆和方法区/元空间属于 JVM 运行时概念，不应直接当作通用操作系统内存分区。共享内存不等于无需同步：例如两个线程并发执行非原子 `count++`，可能发生更新丢失。

并发与并行描述任务的执行关系，不是进程和线程各自独有的属性。单核上多个进程或线程可以交替并发，多核上两者都可能并行。进程默认隔离，但可以通过共享内存映射同一块物理内存，仍需处理同步和生命周期。

## 状态和控制块

五状态模型包括创建、就绪、运行、阻塞和终止：

- 就绪的进程或线程获得 CPU 后进入运行态；时间片用完或被抢占后回到就绪态。
- 运行中等待 I/O、锁或其他事件时进入阻塞态；事件完成后先回到就绪态，重新等待调度。
- 挂起表示被暂停或换出，阻塞表示等待事件，两者可以同时发生。

PCB（进程控制块）记录进程标识、状态、调度信息、内存映射、资源等；TCB（线程控制块）记录线程标识、栈、寄存器、状态等执行现场。Linux 用 `task_struct` 表示任务，通过指针关联地址空间、文件表等资源；线程是否共享这些资源由创建方式决定，不必把教材中的 PCB、TCB 名称直接等同某个内核结构。

## fork、exec 和 wait

| 调用 | 作用和结果 |
| --- | --- |
| `fork()` | 创建子进程。成功后父进程返回子进程 PID，子进程返回 0；两者地址空间独立，初始内容相同，通常使用写时复制。 |
| `exec()` | 用新程序替换当前进程的用户态映像，不新建进程。成功后代码、数据、堆、栈等被替换。 |
| `wait()` / `waitpid()` | 等待子进程状态变化，并回收退出状态；子进程退出后尚未被父进程回收时是僵尸进程。 |

`fork()` 后文件描述符表分别存在，但对应描述符通常指向同一个打开文件描述，因此共享文件偏移量和打开状态标志。可用 `FD_CLOEXEC` 或 `O_CLOEXEC` 防止不需要的文件描述符跨 `exec()` 继承。

多线程进程 `fork()` 后，子进程只保留调用 `fork()` 的线程，但可能继承其他线程持有的锁状态；在 `exec()` 前，子进程只应调用异步信号安全函数。Shell 启动外部命令的常见链路是子进程 `fork()` 后 `exec()`，父进程用 `wait()` 回收。

## 用户线程、内核线程与切换

| 映射 | 说明 | 影响 |
| --- | --- | --- |
| 多对一 | 多个用户线程映射一个内核线程 | 用户态切换开销低；一个阻塞调用可能拖住其他用户线程，无法在多个核心并行 |
| 一对一 | 每个用户线程对应一个内核线程 | 可并行、单线程阻塞不必拖住同进程其他线程；数量受内存和系统资源限制 |
| 多对多 | 多个用户线程映射多个内核线程 | 兼顾用户态调度和多核并行，运行时实现更复杂 |

Linux 的 POSIX 线程通常采用一对一模型，底层创建使用 `clone()`，共享内容取决于 `CLONE_VM`、`CLONE_FILES` 等标志。进程内增加线程可在一个线程等待 I/O 时执行其他工作，但线程栈、调度和上下文切换都有成本；线程数并非越多越快。

上下文切换保存当前执行实体的寄存器、程序计数器和栈指针，再恢复下一个实体。同进程线程共享地址空间，通常不必切换整套内存映射；跨进程切换可能涉及页表切换以及 TLB、缓存局部性开销。跨核迁移、锁竞争和过多线程也会增加线程切换成本。

## 协程、纤程与 Java 虚拟线程

协程和纤程由用户态运行时调度，操作系统调度承载它们的内核线程。若阻塞操作没有被运行时处理为可挂起操作，仍可能阻塞承载线程。

Java 21 虚拟线程仍是 `Thread`，运行时将其挂载到平台线程；遇到 JDK 支持的可挂起阻塞 I/O 时可卸载，让平台线程执行其他任务。它适合大量等待 I/O 的任务，提升并发承载能力，不会加快单段 CPU 密集计算。

在 Java 21 中，虚拟线程在 `synchronized`、native 或 foreign 调用中阻塞可能发生 pinning，导致承载线程也被占用；后续 JDK 对 `synchronized` pinning 的处理有改进，需按实际 JDK 版本判断。
