# 内存管理与文件系统

来源：JavaGuide [内存管理](https://github.com/Snailclimb/JavaGuide/blob/992dae31eade2a34ba8dbbbcf5ed9de5511325ec/docs/cs-basics/operating-system/memory-management.md)、[文件系统](https://github.com/Snailclimb/JavaGuide/blob/992dae31eade2a34ba8dbbbcf5ed9de5511325ec/docs/cs-basics/operating-system/file-system.md)。以下按笔试重点整理，版权归原作者。

## 内存分配与碎片

进程看到的是虚拟地址空间，页表负责把虚拟页映射到物理页；地址空间隔离不意味着每一页都已经分配物理内存。

- **内部碎片**：分配单位内部未用完的空间，比如固定大小页的最后一页剩余空间。
- **外部碎片**：可用空间总量足够，但分散成不连续的小块，无法满足连续分配。
- **分页**按固定大小划分虚拟页和物理页框，便于非连续分配；可能产生内部碎片。**分段**按代码、数据等逻辑单位划分变长段，容易产生外部碎片。段页式结合二者。
- Linux 伙伴系统按 2 的幂管理连续物理页块；释放后可合并相邻空闲伙伴，仍可能出现高阶连续块不足。小对象常由 slab 类分配器管理。

多级页表按需分配下级页表，节省稀疏地址空间所需的页表内存，但 TLB 未命中时可能增加页表遍历次数。分页地址计算：页面大小为 `2^n` 字节时，低 `n` 位是页内偏移，其余高位是虚拟页号；物理地址由查得的页框号与相同页内偏移组成。缺页与页面置换算法见[虚拟内存](./virtual-memory.md)。

## 内存指标、回收与 OOM

| 指标 | 含义 | 注意 |
| --- | --- | --- |
| VSZ | 进程虚拟地址空间大小 | 不等于实际占用的物理内存 |
| RSS | 当前驻留在内存的页面 | 共享页会在各进程的 RSS 中重复计算 |
| PSS | 共享页按映射进程数分摊后的驻留内存 | 汇总进程占用时比直接相加 RSS 更能反映共享页 |

内存紧张时，内核可回收干净的文件页、回写脏页；在配置了 swap 且页面可换出的条件下，也可换出匿名页。swap 不是内存容量不足的免费补偿，频繁换入换出会明显增加延迟。Linux overcommit 允许在特定策略下承诺分配大于当前可用物理内存；`malloc` 成功不保证以后每次访问都能获得物理页。无法继续满足内存需求时，内核或容器的 OOM 机制可能终止进程。

`mmap` 将文件或匿名区域映射到进程地址空间；映射不代表所有页面立即驻留。写时复制（COW）允许进程先共享页面，某一方写入时再复制；共享映射和私有映射的写入可见性、回写行为不同。

## 文件系统对象与读写

- 文件名保存在目录项中，目录项关联 inode；inode 保存文件类型、权限、大小、数据位置等元数据，通常不保存文件名。
- 文件描述符是进程中指向已打开文件的句柄。`open` 涉及路径解析、权限检查和建立打开文件状态；`read` / `write` 通过描述符访问数据。
- VFS 提供统一接口，具体文件系统实现各自的 inode、目录、缓存和数据存储操作。
- 文件块可采用连续、链式或索引等分配方式：连续分配访问快但扩展困难；链式顺序访问方便、随机访问差；索引分配便于定位但需要维护索引。

**硬链接**是指向同一 inode 的另一个目录项；一般不能跨文件系统，也通常不允许给目录创建硬链接。**软链接**是独立文件，保存目标路径，可以跨文件系统，目标删除后会变成悬空链接。

## Page Cache 与持久化

普通文件读写通常经过 Page Cache：缓存命中可避免再次读取存储设备；写入可能先修改缓存并标记脏页，之后由内核回写。`write` 返回成功不必然代表数据已经持久落盘；需要持久化时使用 `fsync` 等接口，并考虑文件及目录元数据的持久化要求。

日志文件系统先记录相关变更，再应用到文件系统结构，帮助崩溃后恢复一致性；具体保护范围取决于文件系统和日志模式，不能推断所有应用数据都已持久化。空闲块可通过位图、空闲链表等方式管理。
