# 虚拟内存、地址转换与页面置换

根据 [JavaGuide 原文](https://github.com/Snailclimb/JavaGuide/blob/992dae31eade2a34ba8dbbbcf5ed9de5511325ec/docs/cs-basics/operating-system/virtual-memory.md)整理，快照版本 `992dae31eade2a34ba8dbbbcf5ed9de5511325ec`。

## 虚拟地址与物理地址

进程使用虚拟地址，MMU 根据当前进程的页表和权限将其转换为物理地址。不同进程相同的虚拟地址可以映射到不同物理页；共享内存则可有意将多个虚拟地址映射到同一物理页。

- 进程获得相互隔离、看似连续的地址空间，物理页可以不连续。
- 地址空间可以按需映射和加载；可用地址空间大于实际物理内存不代表所有页面都能同时驻留。可回收页面的去向受页面类型、swap 和系统配置影响。
- 建立虚拟映射不等于已经分配物理页，也不等于对应文件已经读盘。

## 分段、分页和段页式

| 方式 | 地址转换 | 特点和碎片 |
| --- | --- | --- |
| 分段 | 段号查段表，检查段界限和权限，再用段基址加段内偏移 | 按代码、数据等逻辑划分，段长不固定；易产生外部碎片，整理成本高 |
| 分页 | 页号查页表得到页帧号，再与页内偏移组合 | 页大小固定，通常避免连续分配带来的外部碎片，但末页可能有内部碎片 |
| 段页式 | 段号找到该段页表，再按页号查页帧 | 保留逻辑分段和固定页粒度；转换层次更多 |

分页计算：页大小为 4 KB，虚拟地址为 32 位时，页内偏移占 12 位，虚拟页号占 20 位。若每个页表项为 4 字节，覆盖整个虚拟空间的单级页表需要 `2^20 × 4 B = 4 MB`。4 KB 是常见配置，具体页大小由架构与系统决定。

分段与分页同时启用时，分段转换先得到线性地址，再由页表转换为物理地址。x86-64 长模式下大部分传统分段作用弱化，FS、GS 仍可用于线程局部存储等用途。

## 多级页表与 TLB

多级页表把页号拆成多级索引。上级项不存在时不必为该地址范围分配下级页表，因此对稀疏地址空间节省内存；代价是未命中缓存时可能需要多次访存。

32 位、4 KB 页、两级页表的例子：每级 1024 项，一级表占 4 KB，二级表按地址范围分配。假设只用到 20% 的一级项，则总开销约为 `4 KB + 20% × 4 MB ≈ 0.804 MB`；若所有范围都使用，多级结构也有额外开销。

TLB 是缓存近期地址转换结果的硬件缓存：

1. TLB 命中且权限允许时，直接得到页帧并组合页内偏移。
2. 未命中时进行页表遍历；合法映射可装入 TLB 后继续访问。
3. 若页表不能完成转换或权限检查，触发缺页异常。**TLB 未命中不等于缺页。**

## 缺页异常与按需调页

缺页异常由当前访存同步触发，常被称为缺页中断，但不是外设硬件中断。处理顺序：

1. 内核检查地址及访问权限。非法访问通常向进程发送 `SIGSEGV`。
2. 合法访问时，可能分配新页、建立共享页映射、处理写时复制，或从文件、swap 调入页面。
3. 内存不足时先回收页：干净文件页可丢弃后再从文件读回；脏文件页通常需写回；匿名页的回收依赖 swap 等条件。
4. 更新页表及相关转换缓存，再重试触发异常的指令。

**次缺页**不需要为本次处理从磁盘读取页面，例如已有缓存页映射或常见的 COW 复制；**主缺页**需要等待从文件或 swap 读取。非法访问不作为第三种正常缺页统计类别。频繁页面换入换出导致系统大部分时间忙于 I/O，称为抖动。

## 页面置换算法

| 算法 | 选择依据 | 要点 |
| --- | --- | --- |
| OPT | 未来最长时间不用 | 理论最优，需要预知未来，只作基准 |
| FIFO | 最早装入 | 实现简单，可能淘汰热点页，可能出现 Belady 异常 |
| LRU | 最久未访问 | 利用局部性；精确维护访问顺序有成本 |
| CLOCK | 环形扫描访问位 | 位为 1 时清零并给第二次机会，位为 0 时淘汰；近似 LRU |
| LFU | 访问次数最少 | 历史热点可能长期占位，常结合计数衰减 |

**Belady 异常**：页帧数增加时，缺页次数反而增加。对访问序列 `1,2,3,4,1,2,5,1,2,3,4,5`，FIFO 在 3 个页帧下缺页 9 次，4 个页帧下缺页 10 次。OPT、LRU 满足栈性质，不出现该异常；不能因 CLOCK 近似 LRU 就断言其一定不会出现。

真实 Linux 页回收使用活跃 / 非活跃等近似机制，并受工作集、回访、页类型、内存水位和系统配置影响，不能等同于某个教科书算法。

## 应用边界

- `mmap` 建立文件到虚拟地址的映射，首次访问未驻留页才可能缺页并读盘；映射与按需调页可减少用户缓冲区复制。
- `fork` 后父子进程通常先共享物理页，写入时通过 COW 为写入方分配副本；只读期间不必复制所有页面。
- JVM 大堆可使用大页减少页表项和 TLB 压力，但收益和分配限制取决于工作负载与配置。TLB miss 或缓存 miss 不必然是缺页。
