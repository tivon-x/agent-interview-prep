# 调度、进程通信与系统调用

来源：JavaGuide [CPU 调度与系统负载](https://github.com/Snailclimb/JavaGuide/blob/992dae31eade2a34ba8dbbbcf5ed9de5511325ec/docs/cs-basics/operating-system/cpu-scheduling-and-load.md)、[进程间通信](https://github.com/Snailclimb/JavaGuide/blob/992dae31eade2a34ba8dbbbcf5ed9de5511325ec/docs/cs-basics/operating-system/ipc.md)、[中断、异常与系统调用](https://github.com/Snailclimb/JavaGuide/blob/992dae31eade2a34ba8dbbbcf5ed9de5511325ec/docs/cs-basics/operating-system/interrupt-exception-syscall.md)。以下按笔试重点整理，版权归原作者。

## CPU 调度与计算

就绪队列中的任务竞争 CPU；任务阻塞、退出、时间片耗尽或被更高优先级任务抢占时，调度器可能选择其他任务。上下文切换需要保存和恢复执行状态，还可能影响缓存与 TLB。

| 算法 | 选择方式 | 典型取舍 |
| --- | --- | --- |
| FCFS 先来先服务 | 按到达就绪队列的先后执行 | 简单；长任务可能让后续短任务等待 |
| SJF 短作业优先 | 优先预计运行时间短的任务 | 已知运行时间时有利于降低平均等待时间；长任务可能饥饿 |
| 最短剩余时间优先 | 选择剩余时间最短的任务，可抢占 | 新短任务可抢占；需要估计剩余时间 |
| 时间片轮转 | 依次运行一个时间片 | 适合交互；时间片太短增加切换开销，太长接近 FCFS |
| 优先级调度 | 优先运行高优先级任务，可抢占或非抢占 | 低优先级可能饥饿，可通过老化逐步提高优先级 |
| 多级反馈队列 | 多个优先级队列，任务随行为调整队列 | 兼顾交互任务和长任务；规则因实现而异 |

计算题先画时间轴，标出到达、开始、抢占和完成时刻：**周转时间 = 完成时刻 − 到达时刻；带权周转时间 = 周转时间 / 服务时间；等待时间 = 周转时间 − 实际运行时间**。最后求各任务的平均值。若题目包含 I/O 阻塞，等待时间应按就绪队列等待计算，不能把阻塞时间也算作就绪等待。

Linux 普通任务调度常讨论 CFS 的虚拟运行时间和 EEVDF 的虚拟截止时间；实际调度策略取决于内核版本和调度类。`load average` 是一段时间内可运行及不可中断睡眠任务数量的平均值，不等于 CPU 使用率；负载高也可能是任务在等待 I/O。多核机器还要结合 CPU 数量、运行队列、`%wa` 等指标判断。

## 进程间通信（IPC）

进程有各自的虚拟地址空间，通信需要约定数据传递、同步、命名和权限。共享物理页的不同虚拟地址不必相同，因此共享内存中通常保存偏移量，而不是进程私有指针。

| 方式 | 数据与边界 | 适用和限制 |
| --- | --- | --- |
| 匿名管道 | 内核缓冲区中的单向字节流，无消息边界 | 常用于有亲缘关系的进程；双向通常建两条管道 |
| FIFO 命名管道 | 按路径打开的字节流，无消息边界 | 无亲缘关系的进程也能通信；路径是命名入口，不代表数据写到磁盘 |
| 消息队列 | 内核保存一条条消息，有消息边界 | 适合控制消息；大小和容量受限制，发送接收涉及数据复制 |
| 共享内存 | 多个进程映射同一物理页 | 本机大块数据交换；必须另配进程间锁、信号量等同步机制 |
| 信号量 | 计数与同步，不传业务数据 | 控制并发访问或通知资源可用 |
| 信号 | 异步事件通知 | 传递的信息有限，信号处理函数需遵守安全限制 |
| Socket | 字节流或数据报，边界取决于类型 | Unix Domain Socket 可用于本机；TCP/UDP 可跨机器 |

管道中单次不超过 `PIPE_BUF` 的写入有不与其他写者交错的原子性保证，但这不等于读写次数一一对应，也不赋予管道消息边界。共享内存避免每次传递数据都复制进出内核，但仍要处理互斥、可见性和唤醒。

## 中断、异常与系统调用

- **中断**来自外部设备或时钟，通常与当前指令异步；**异常**由当前指令触发，如缺页或除零；**系统调用**由用户程序主动请求内核服务。
- 用户态到内核态是权限模式切换，未必发生线程切换；阻塞、抢占或主动让出 CPU 后才可能切换到其他线程。内核态执行的系统调用也可能发生阻塞。
- `read()` 进入内核后，若数据可用则复制到用户缓冲区并返回；若不可用，阻塞或返回错误等行为取决于文件类型、是否非阻塞和具体状态。磁盘 I/O 完成后可通过中断通知内核，内核再唤醒等待任务。
- 缺页异常不等于一定从磁盘读页：合法映射可能按需分配、加载文件页或处理写时复制；访问不合法地址则可能导致进程收到 `SIGSEGV`。缺页处理后，通常重新执行引发异常的指令。
