## 操作系统与特权级

### 操作系统有哪些职责？

操作系统是管理硬件和软件资源的软件。内核负责进程和线程、内存、文件、设备、网络与权限等管理，对应用提供受控接口；CPU 是执行指令的硬件，内核是软件。常见系统包括 Windows、macOS、Unix 和 Linux；严格说 Linux 是内核，发行版还包括用户空间程序。

### 用户态和内核态有什么区别，为什么要区分？

二者描述 CPU 执行代码的特权级。用户态不能直接执行特权指令、访问内核地址或任意操纵硬件；内核态可以执行页表管理、中断控制等操作。权限隔离使单个应用故障或恶意操作不至于直接破坏整个系统。

进入内核态的三种主要途径：

- **系统调用**：程序通过 `syscall` 等指令主动请求内核服务，是同步事件。
- **异常**：由当前指令触发，如除零、非法指令、缺页；缺页也可能是合法的按需分配或写时复制。
- **硬件中断**：网卡、磁盘、定时器等设备引发，与当前指令异步。

内核处理的是当前线程进入内核的工作，并不意味着用户进程变成了内核进程。信号是内核通知进程或线程的软件机制；非法访问导致的缺页无法修复时，Linux 通常投递 `SIGSEGV`。

### 系统调用和普通库函数有什么区别？一定发生线程切换吗？

系统调用是用户程序请求内核提供文件、设备、进程、内存或网络服务的受控入口。库函数是用户空间接口，有些只在用户态运行，有些包装系统调用；两者不是同一层。

以 `read(fd, buf, count)` 为例：库函数按 ABI 准备参数并进入内核，内核检查描述符、权限和缓冲区，再经文件系统、网络栈或设备处理，最后返回字节数或错误。数据未就绪时线程可能阻塞，数据就绪后才被唤醒并再次等待调度。

进入内核态不等于线程上下文切换：如果内核处理完后继续运行原线程，只有特权级切换；阻塞或调度器选中别的线程时才发生线程切换。

## 进程与线程

### 进程和线程有什么区别？为什么还需要线程？

进程是资源分配和隔离的基本单位，通常有独立虚拟地址空间；线程是调度和执行的基本单位。同一进程的线程共享地址空间、打开的文件等资源，各自持有栈、寄存器、程序计数器、线程本地存储等执行状态。

| 方面 | 进程 | 同一进程中的线程 |
| --- | --- | --- |
| 隔离 | 地址空间通常独立 | 共享进程地址空间 |
| 通信 | 管道、消息队列、共享内存、Socket 等 IPC | 可直接访问共享内存，需要同步 |
| 创建和切换 | 通常更重，可能涉及地址空间和 TLB | 通常更轻，无须切换整套地址空间 |
| 故障影响 | 一个进程崩溃通常不影响其他进程 | 线程错误可能影响整个进程 |

线程让一个应用以较低协作开销并发执行。I/O 密集任务可在等待时让其他线程运行；可并行的 CPU 计算可利用多核。线程并非越多越好，过多会增加栈占用、调度、缓存失效及锁竞争，配置要结合 CPU 配额、阻塞比例和测试结果。

### 线程同步有哪些方式？

- **互斥锁**：同一时刻只允许一个持有者进入临界区。
- **读写锁**：可并发读，写入需要独占。
- **信号量**：以许可计数限制并发访问数量，也可用于协调执行。
- **屏障**：一组线程到达同一阶段后再继续。
- **条件变量**：条件不满足时等待，状态改变后通知；通常配合互斥锁，并在循环中重新检查条件。

### PCB 和 TCB 分别保存什么？

PCB（进程控制块）保存进程标识、状态和调度信息、地址空间、文件和权限等资源信息；TCB（线程控制块）保存线程标识、状态、寄存器、栈及调度信息。具体组织因系统而异：Linux 以 `task_struct` 描述调度实体，通过资源结构是否共享区分进程和线程。

### 进程有哪些状态？

创建、就绪、运行、阻塞和结束是常用五状态模型。就绪获得 CPU 后运行；运行时片用完可回到就绪；等待 I/O、锁或事件进入阻塞；事件满足后先转就绪，再等待调度。阻塞强调等待事件，挂起强调被暂停或换出，二者可以同时发生。

### 进程间通信有哪些方式？

| 方式 | 适用场景与边界 |
| --- | --- |
| 匿名管道 | 常用于父子进程传递字节流 |
| 命名管道 / Unix Domain Socket | 本机无亲缘关系的进程通信 |
| 消息队列 | 按消息边界交换结构化数据 |
| 共享内存 | 本机大块数据交换，需额外同步 |
| 信号 | 异步事件通知，传递的数据有限 |
| TCP/UDP Socket | 跨机器通信，也可用于本机 |

### `fork`、`exec`、`wait` 各做什么？

`fork()` 创建子进程，父子进程从调用后继续且返回值不同；`exec()` 用新程序替换当前进程的用户态程序映像，不创建进程；`wait()` / `waitpid()` 等待子进程状态变化并回收退出状态。Shell 启动外部命令常用 `fork → exec → wait`；已退出的子进程若长期未被回收会形成僵尸进程。

### 什么是上下文切换？

切换执行实体时，内核保存当前寄存器、程序计数器、栈指针等现场，恢复下一个执行实体的现场。进程间切换可能还要切换地址空间并影响 TLB 和缓存局部性；同进程线程通常共享地址空间。特权级切换与线程切换是不同概念。

### 进程调度算法有哪些？谁负责调度？

| 算法 | 规则 | 代价或问题 |
| --- | --- | --- |
| FCFS | 按到达顺序执行 | 长任务可拖慢后续短任务 |
| SJF | 优先预计运行时间短的作业 | 难准确预测，长任务可能饥饿 |
| RR | 就绪任务轮流运行时间片 | 过短切换频繁，过长接近 FCFS |
| 优先级调度 | 高优先级任务先执行 | 低优先级可能饥饿 |
| 多级反馈队列 | 按运行行为调整队列优先级 | 规则和防饥饿策略依实现而异 |

FCFS 和非抢占式 SJF 一旦开始运行通常直到结束或主动阻塞；RR 是抢占式。调度器选择下一个可运行任务，分派过程保存和恢复上下文并移交 CPU。Linux 普通任务长期使用 CFS 的权重与虚拟运行时间，Linux 6.6 起在 fair 调度类引入 EEVDF；实际行为应以运行内核及发行版实现为准。

### load average 和 CPU 使用率有什么区别？

Linux load average 反映一段时间内可运行任务和不可中断睡眠任务数量，常对应 R、D 状态；CPU 使用率说明 CPU 时间花在用户态、内核态、空闲、I/O wait 等位置。load 高可能是 CPU 竞争，也可能有大量 I/O 等待，需结合逻辑 CPU 数、`uptime`、`top`、`vmstat` 等指标判断。

## 死锁

### 什么是死锁？四个必要条件是什么？

一组线程或进程相互等待，形成无法自行解除的等待环。比如线程 1 持 A 等 B，线程 2 持 B 等 A。普通等待能在资源释放后继续，死锁需要打破等待关系。

四个必要条件必须同时成立：**互斥、占有并等待、不可抢占、循环等待**。破坏其中任一条件可从结构上预防死锁；满足条件本身不代表一定出现死锁。

### 如何复现、预防和处理死锁？

复现交叉持锁：让两个线程分别先取得 A、B，然后各自申请对方持有的锁；`sleep` 只扩大交错窗口，不保证每次复现。

- **预防**：固定加锁顺序等方式破坏必要条件；缩小锁范围、避免持锁慢操作也能降低风险，但本身不保证杜绝死锁。
- **避免**：分配前判断是否仍处于安全状态，如银行家算法。
- **检测**：分析等待图，Java 可用 `jcmd <pid> Thread.print -l`、`jstack -l <pid>` 或 `ThreadMXBean`。
- **恢复**：终止任务、回滚事务、释放或抢占资源并按需重试，打破等待环。
