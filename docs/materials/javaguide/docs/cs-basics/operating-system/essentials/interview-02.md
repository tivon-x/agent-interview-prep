# 操作系统常见面试题（下）

## 内存管理

### 内存管理做什么？VSZ、RSS、PSS 有何区别？

内核管理物理页与内存映射，完成分配、回收、地址转换、隔离、权限保护和共享。用户态分配器可通过 `brk`、`mmap` 等接口申请虚拟地址空间；分配虚拟地址不等于物理页立即就位。

- **VSZ**：进程映射的虚拟地址空间大小，包含未驻留、文件映射与共享库，不能直接代表物理占用。
- **RSS**：当前映射到进程且驻留在物理内存的页面之和；多个进程共享页会在各自 RSS 中重复计入。
- **PSS**：共享页按共享进程数分摊。多个进程合计占用通常比 RSS 直接相加更适合参考 PSS。

### 内部碎片、外部碎片和伙伴系统是什么？

内部碎片是已分配空间内未使用的部分，如申请 65 字节却分配 128 字节，浪费 63 字节；外部碎片是空闲总量足够、但没有足够大的连续空闲块。连续分配容易受外部碎片影响；分页可离散分配页框，消除普通页框分配的外部碎片，但末页可能产生内部碎片。

Linux 伙伴系统把物理页按 2 的幂次组织，分配时按需拆分，释放时可合并满足对齐及同阶条件的空闲伙伴。它缓解外部碎片但仍可能存在内外碎片；不是任意相邻块都能合并。SLAB / SLUB 进一步服务于内核小对象分配和复用。

### 虚拟内存有什么作用？虚拟地址如何变成物理地址？

程序使用虚拟地址，MMU 根据页表并借助 TLB 将其转换成物理地址。不同进程相同的虚拟地址可映射到不同物理页；页表权限和内核管理提供隔离，也可显式映射同一批物理页用于共享内存或共享库。虚拟内存还支持按需加载、离散物理页映射和页面回收，使可用地址空间不局限于当前驻留 RAM。

没有这样的映射和保护，程序更容易互相覆盖或破坏内核；虚拟地址空间和物理地址空间分别是对应地址的集合，不等于当前实际占用的 RAM。

### 分页、分段和段页式有什么区别？

| 维度 | 分页 | 分段 |
| --- | --- | --- |
| 单位 | 固定大小的页和页框 | 代码、数据等逻辑段，长度可变 |
| 地址 | 页号 + 页内偏移 | 段号 + 段内偏移 |
| 映射 | 页表查到页框，页框基址 + 偏移 | 段表查段基址，校验界限和权限后加偏移 |
| 碎片 | 最后一页可有内部碎片 | 连续变长段易产生外部碎片 |

段页式先以段表将段号和段内偏移转换为线性地址，再按页表转成物理地址。现代通用系统主要依赖分页；页大小取决于体系结构和配置，4 KiB 是常见值。纯分段模型中段界限异常与分页缺页不是同一问题。

**计算示例**：4 KiB 页大小下偏移占 12 位；虚拟地址除以 4096 得页号，余数为页内偏移。若页表把该页映射至页框 7，偏移为 100，则物理地址为 `7 × 4096 + 100 = 28772`。段基址 7000、合法段内偏移 500 时，物理地址为 7500。

### 多级页表和 TLB 为什么有用？

单级页表要覆盖整个虚拟地址空间；多级页表只为使用到的范围创建下级页表，以多次查表换取稀疏空间下的页表内存节省。32 位地址、4 KiB 页面、每项 4 字节时，单级页表有 `2^32 / 2^12 = 2^20` 项，占 4 MiB；若二级结构仅使用两张下级表，1 张 4 KiB 顶级表加 2 张 4 KiB 下级表共 12 KiB。

TLB 是 MMU 使用的地址转换缓存：命中时直接取得映射，未命中时查页表并可回填。页表修改后，操作系统须按体系结构要求使相关 TLB 项失效。TLB 未命中不等于缺页；页表映射有效时查表即可继续。

### 换页、缺页异常和页面置换有什么区别？

换页在内存紧张时将暂时不用的页面换出，需要时再调入。Page Fault 是当前访存无法直接完成地址翻译或权限检查时触发的同步异常，内核判断访问合法性后处理：

1. 合法且可修复：按需分配、建立已有页映射、从文件或 Swap 调页，或处理 COW；更新页表后重试指令。
2. 非法地址或不允许的访问：通常向当前线程投递 `SIGSEGV`。语言级越界若仍落在已映射且可访问的页中，不一定立刻触发异常。

**主缺页**通常需要实际存储 I/O；**次缺页**无需从存储设备读页，如部分映射建立、零页分配或 COW。回收没有空闲页时，页面置换算法决定淘汰对象：

| 算法 | 淘汰对象与限制 |
| --- | --- |
| OPT | 未来最久不访问的页，理论基准，无法预知未来 |
| FIFO | 最早进入的页，简单，可能出现页框增多而缺页反增的 Belady 异常 |
| LRU | 最近最久未使用的页，利用时间局部性，精确维护成本较高 |
| LFU | 一段时间内使用次数最少的页，可能需计数衰减避免旧热点长期驻留 |
| CLOCK | 环形扫描访问位，给近期访问的页第二次机会，近似 LRU |

真实系统通常使用结合多种机制的近似回收，而非照搬教材算法。

### Swap、工作集、抖动和 OOM 有什么关系？

工作集是进程一段时间内经常访问的页面。内存无法容纳主要工作集时，页面频繁换入换出称为抖动，I/O 和延迟可能剧增。内存紧张时，匿名页可写入 Swap，文件页则可能被回收并在之后从文件重新读取。

Overcommit 允许在一定策略下承诺超过当前可用物理资源的虚拟内存；`malloc` 或 `mmap` 成功不代表所有物理页都已分配。后续实际使用时若无法通过回收等手段获得内存，可能触发 OOM Killer。容器还受 cgroup 内存限制，宿主机有空闲也可能发生容器范围的 OOM。

### `mmap`、共享内存、COW 和局部性有什么关系？

`mmap` 建立文件或匿名内存映射，物理页可按需建立；多个进程可以映射同一物理页进行共享，但共享写入仍需同步。`fork` 后父子进程通常先共享 COW 页面；写入时发生缺页，内核按需复制或调整映射，维持进程间写入隔离。

**时间局部性**是近期访问的内容可能再次访问，支持缓存和页面保留；**空间局部性**是附近地址可能随后访问，支持按页加载和预读。

## I/O

### 阻塞 `read` 和 I/O 多路复用有什么区别？

`read` 进入内核并检查描述符、权限及缓冲区；数据就绪时复制到用户缓冲区并返回，数据未就绪时阻塞描述符可使当前线程等待，事件到来后线程被唤醒并等待调度。缓存命中时不一定等待设备，也不一定发生线程切换。

网络读可分为等待数据进入内核缓冲区和从内核复制到用户缓冲区两个阶段。I/O 多路复用让一个线程等待多个 fd 的就绪事件，适合大量空闲连接；就绪后应用仍需调用 `read` / `recv`，因此通常属于同步 I/O，且不消除内核到用户缓冲区的复制。

### `select`、`poll` 和 `epoll` 有什么区别？

| 机制 | 监听方式和限制 |
| --- | --- |
| `select` | 每次传入并扫描 `fd_set`；Linux glibc 通常受 `FD_SETSIZE` 限制，返回后需重新设置集合 |
| `poll` | 传入并扫描 `pollfd` 数组，避免 `fd_set` 固定大小限制 |
| `epoll` | `epoll_ctl` 维护内核监听集合，`epoll_wait` 获取就绪事件，适合大量连接但少量活跃 |

LT 在条件仍就绪时会再次通知；ET 强调状态变化，常用非阻塞 fd 循环读写直至 `EAGAIN`，避免遗漏尚未处理的数据。`epoll` 也有注册和事件维护成本，连接少或全部活跃时未必更快。

### 什么是零拷贝？`mmap`、`sendfile`、`splice` 如何选择？

零拷贝主要减少 CPU 在内核与用户缓冲区之间搬运数据，并可能减少系统调用；并非不发生任何 DMA 拷贝。传统文件发送 `read + write` 的典型路径是磁盘 DMA 到内核缓冲区、CPU 拷贝到用户缓冲区、CPU 拷贝到 Socket 缓冲区、DMA 送到网卡；缓存命中等条件会改变具体路径。

- `mmap + write`：映射文件页后可在用户态访问，避免一次内核到用户缓冲区的复制，写 Socket 通常仍需 CPU 复制。
- `sendfile`：适合文件到 Socket 原样发送；具备相应内核和网卡支持时，SG-DMA 可进一步避免 CPU 搬运 payload。
- `splice`：借助 pipe 在内核路径中转移数据，适合更一般的 fd 之间转发，使用和调用次数也要考虑。

加密、压缩、过滤等需要处理内容的场景，不能简单假设始终适用纯内核转发；实际路径取决于实现和系统能力。

## 文件系统与磁盘

### 文件系统负责什么？文件名、inode 和 dentry 有何关系？

文件系统负责命名、目录组织、数据块定位与空间管理、权限控制、缓存和恢复；VFS 为本地、内存和网络等文件系统提供统一接口。

目录项把文件名关联到 inode；inode 记录类型、权限、所有者、大小、时间、链接计数及数据块映射，通常不保存文件名；dentry 是内存中加速路径查找的目录项缓存，也可能缓存不存在的结果。多个目录项可指向同一个 inode。

### `open` 做了什么？文件在磁盘上如何分配？

`open()` 解析路径、查找目录项和 inode、检查权限与标志，创建打开文件对象，再在进程 fd 表中分配描述符；它不会默认把整个文件读入内存。`dup` 或 `fork` 得到的多个 fd 可指向同一个打开文件对象并共享偏移；分别 `open` 通常对应各自独立的打开文件对象。

文件块的常见分配方式：连续分配顺序和随机访问快但增长困难且易产生外部碎片；链式分配不要求连续但随机访问差；索引分配便于随机访问但需要索引空间。ext4 常用 extent tree 描述连续块区间。

### 硬链接和软链接有什么区别？

硬链接是指向同一个 inode 的新目录项，增加链接计数；删除原路径后，只要仍有硬链接，文件仍可通过它访问。inode 编号只在所属文件系统内有意义，因此硬链接不能跨文件系统；Linux 通常不允许普通用户给目录创建硬链接。

软链接本身有独立 inode，保存目标路径，可跨文件系统和指向目录；目标路径被删除或改名后可能悬空。

### `write` 成功等于已经落盘吗？日志文件系统保证什么？

普通 buffered I/O 的 `write` 成功通常表示内核接收了数据，常见情况是数据进入 Page Cache 并标脏，不等于已持久化；还必须处理部分写入。`fsync` 同步数据和关联元数据，`fdatasync` 同步数据及读取所必需的元数据。创建、重命名或删除后若要求目录项掉电持久化，通常还要同步父目录 fd；具体保证受文件系统及存储设备实现影响。

日志文件系统先记录事务相关变更，再更新正式位置；恢复时可重放完整提交的日志，以降低元数据不一致风险。ext4 的 `writeback`、`ordered`、`journal` 对数据和元数据的日志及写入顺序不同；日志维护文件系统结构一致性，不自动替代应用的业务持久化协议。

### 如何提高文件系统性能？

结合访问模式做顺序读写、预读和合并，利用 Page Cache；减少大量小文件和重复元数据操作；在持久性要求允许时调整刷盘频率；按场景选择文件系统、挂载参数和存储硬件。排查空间时可用 `df -h`、`df -i`，`df` 满但 `du` 未显示大文件时可检查仍被进程打开的已删除文件。

### 常见磁盘调度算法有哪些？

这些算法主要针对机械盘寻道；计算题要明确初始磁头位置、方向、请求序列与磁盘边界，再沿路径累加相邻磁道的绝对距离。

| 算法 | 选择规则 |
| --- | --- |
| FCFS | 按到达顺序处理，简单但寻道可能很长 |
| SSTF | 每次选最近请求，可能让远处请求饥饿 |
| SCAN | 沿当前方向处理，至磁盘边界后反向 |
| C-SCAN | 单方向处理，至边界后回到另一端再扫描 |
| LOOK | 沿方向处理至最远待处理请求后反向，不必走到边界 |
| C-LOOK | 单方向处理至最远请求后返回另一端的待处理请求 |

SSD/NVMe 没有机械寻道，不能直接套用上述物理模型；块层仍可按设备和调度策略处理请求合并、公平性及延迟。
