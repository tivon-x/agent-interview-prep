# MySQL 常见面试题

来源：[JavaGuide 原文](https://github.com/Snailclimb/JavaGuide/blob/992dae31eade2a34ba8dbbbcf5ed9de5511325ec/docs/database/mysql/mysql-questions-01.md)，快照 `992dae31eade2a34ba8dbbbcf5ed9de5511325ec`。相关专题在目录下有单独笔记。

## 基础和数据类型

### 什么是关系数据库、SQL 和 MySQL？

关系数据库以表、行、列和关系组织数据，支持约束与关联；SQL 是定义、查询、更新和管理关系数据的语言；MySQL 是实现 SQL 的关系数据库管理系统。其特点包括成熟生态、插件式存储引擎、事务与索引支持；功能、性能和可用性取决于版本、引擎及实际配置。

### 整数、字符串、金额和时间如何选择？

- `UNSIGNED` 取消负数表示，把可表示范围用于非负整数；边界与实际类型和版本相关，运算混合符号时注意转换。
- `CHAR(n)` 固定长度语义，短值可补空格；`VARCHAR(n)` 是变长字符串并记录长度。`n` 是字符数，行大小和字符集约束还按字节计算，`VARCHAR(100)` 比 `VARCHAR(10)` 容许更多字符，不意味着每行必占 100 字节。
- `DECIMAL` 精确表示定点数，适合精确金额；`FLOAT` / `DOUBLE` 是近似浮点，运算可能有舍入误差。`TEXT` / `BLOB` 适合较大内容，但索引长度、行存储、网络与 I/O 代价需评估；能力受版本约束，不应笼统说必然不能有默认值或只能用磁盘临时表。
- `DATETIME` 保存日历日期时间，不自动按会话时区转换；`TIMESTAMP` 与会话时区相关，范围、精度受版本约束。跨时区应明确 UTC 和展示规则。
- `NULL` 表示未知或缺失，`''` 是已知空字符串。普通 `= NULL` 得 UNKNOWN，使用 `IS NULL` 或 NULL 安全比较 `<=>`；`COUNT(*)` 统计行，`COUNT(col)` 只统计非 NULL，常见聚合忽略 NULL。
- `BOOLEAN` / `BOOL` 是 `TINYINT(1)` 的同义词，通常 0 为假、非 0 为真；`BIT(1)` 是位类型。手机号是标识符而非算术值，用字符串可保留前导零及国际前缀；若加密保存，列类型和长度按密文格式确定，查询方案也需相应设计。

## 架构和存储引擎

### SQL 如何执行？

连接器处理连接认证；Server 层解析 SQL、优化执行计划并通过执行器调用存储引擎，权限检查贯穿相关步骤。MySQL 旧版存在查询缓存，8.0 已移除；它不同于 InnoDB Buffer Pool。

### InnoDB 和 MyISAM 有什么区别？

通过 `SHOW ENGINES` 查看可用引擎。MySQL 5.5.5 后 InnoDB 为通常默认引擎，支持事务、行级锁、外键和崩溃恢复；MyISAM 不提供 InnoDB 同等事务和行锁支持，通常依靠表级锁。具体全文索引等功能依版本而异，不能把旧版本差异当成当前通则。涉及一致性和并发更新时通常选择 InnoDB；实际选择仍取决于功能和负载。

## 索引

### 索引为什么快，代价是什么？

索引维护有序数据结构以缩小定位或范围扫描，减少读取行数；但占空间并增加插入、删除、更新和页维护成本。InnoDB 常用 B+ 树：树高低、叶子有序，适合等值和范围查找。哈希通常适合等值但不天然支持范围和排序；普通 B 树与 B+ 树叶子布局不同，B+ 树更适于页访问和顺序扫描。自适应哈希属于引擎内部辅助机制。

### 聚簇索引、二级索引、回表和覆盖索引？

聚簇索引叶子保存行数据；二级索引叶子包含索引列与主键值。若查询列不能由二级索引提供，需要按主键取聚簇记录，称回表；查询所需列均可从索引提供时是覆盖索引，通常可减少回表。

### 联合索引及失效如何判断？

联合索引按列顺序组织，最左前缀常支持对应等值或范围定位；范围后列能否继续用于定位、过滤或排序取决于条件和版本，不能简单说完全无用。索引列转换、函数或计算、前置通配符、字符列与数字比较及不匹配索引顺序可能降低利用；`SELECT *` 可能增加回表成本，但不必然使索引失效。按过滤、关联、排序频率及选择性选择字段，兼顾写入成本；以 `EXPLAIN` 和实际数据验证。

## 日志与事务

### 三种日志各做什么？

redo log 支持崩溃恢复，undo log 支持回滚和历史版本，binlog 是 Server 层变更日志，支持复制和基于时间点恢复。开启 binlog 时协调 redo 与 binlog 的内部两阶段提交；能否在断电后保留最近提交还受刷盘、存储设备和配置影响。

### 事务和 ACID 是什么？

事务把一组操作组成逻辑单元：原子性表示全成或全不成，一致性是业务约束在正确事务前后成立，隔离性限制并发交互，持久性要求成功提交后按约定可恢复。`START TRANSACTION`、`COMMIT`、`ROLLBACK` 控制显式事务；隔离级别不能替代正确的约束和业务逻辑。

### 并发事务有哪些问题？

脏读读取未提交值；丢失更新指一个修改被另一修改覆盖；不可重复读指同一行重复读取结果变化；幻读指同一条件匹配的记录集合变化。锁、约束、原子更新、MVCC、隔离级别和乐观并发控制分别解决不同问题，不能只依赖某一个开关。

### 四种隔离级别和默认值？

读未提交允许脏读；读已提交避免脏读，但可能不可重复读、幻读；可重复读避免脏读与不可重复读，SQL 标准仍允许幻读；串行化要求结果等价于串行执行。InnoDB 通常默认 RR，通过 MVCC 对一致性读提供视图，并在适用的当前读范围使用 next-key 锁约束插入；锁范围受索引与计划影响，混用快照读和当前读仍可能观察到不同集合。

## 锁

### 表锁、行锁和行锁注意事项？

表锁粒度粗，可能降低并发；InnoDB 行锁实际针对索引记录及范围，锁定扫描范围受索引、条件、隔离级别和计划影响，不是只看最终返回行。无合适索引时可能扫描和锁住较多记录。多个事务访问资源顺序不同可能死锁，需诊断并按业务语义重试整个事务。

### 记录锁、间隙锁和 next-key 锁？

记录锁锁索引记录；间隙锁约束间隙内插入；next-key 锁是记录加相邻间隙的组合。具体范围依索引唯一性、查询谓词和隔离级别决定，不能把范围锁视为锁住整张表的所有新记录。

### 共享锁、排他锁、意向锁？

共享锁允许兼容的共享读取，排他锁与其他不兼容锁冲突；意向共享/意向排他锁在表层表示事务将持有或已持有行级共享/排他锁，使表级锁兼容性检查无需逐行扫描。意向锁不等于锁住所有数据行。

### 当前读、快照读和自增锁？

普通一致性 SELECT 使用快照，读取 Read View 可见版本；锁定读、UPDATE、DELETE 等按当前数据及隔离级别获取锁。自增值申请受 `innodb_autoinc_lock_mode` 与插入类型影响，失败、回滚、批量预分配等会产生空洞，不能保证无间隔或提交顺序。

## 性能与工程

### 大文件和 IP 如何存储？

数据库可存二进制对象，但大文件会影响备份、网络与 I/O；也可存对象存储引用，需处理权限和生命周期。IP 可用规范化字符串或二进制保存；IPv4 与 IPv6 长度及转换不同，选择类型要保留地址族和查询需求。

### 常见 SQL 优化和性能分析？

先测量慢查询、执行计划、扫描行数、回表、排序、锁等待和资源瓶颈；按条件和排序设计索引、取必要字段、避免无界结果和无效转换，结合真实数据复测。不能仅凭 `EXPLAIN` 中出现索引就认定快，也不应机械将所有子查询改成 JOIN。

### 读写分离、分库分表、深分页和冷热分离？

读写分离将部分读取分配到副本，但复制延迟可能导致读到旧数据；关键读可回主库或采用一致性策略。分库分表缓解单节点或单表瓶颈，同时引入路由、跨分片查询和运维成本。

大 `OFFSET` 往往需要跳过大量记录；可在稳定排序键上用游标/键集分页，如 `WHERE id > ? ORDER BY id LIMIT ?`，并正确处理相同排序键和并发更新。冷热分离把低频数据迁至更合适的存储层，需定义访问、归档、恢复和一致性边界。优化需覆盖数据库配置、SQL、索引、应用连接与容量，不凭固定单表行数判断。
