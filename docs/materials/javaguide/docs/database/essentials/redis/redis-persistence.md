# Redis 持久化：RDB、AOF 与恢复

根据 [JavaGuide 原文](https://github.com/Snailclimb/JavaGuide/blob/992dae31eade2a34ba8dbbbcf5ed9de5511325ec/docs/database/redis/redis-persistence.md)整理，快照版本 `992dae31eade2a34ba8dbbbcf5ed9de5511325ec`。

## RDB 快照

RDB 保存某一时刻的数据集，适合备份、复制和相对快速恢复；两次快照之间的写入在故障时可能丢失。

- `SAVE` 在主线程同步生成快照，期间阻塞服务。
- `BGSAVE` 先 `fork` 子进程，再由子进程生成快照；生成过程异步，但 `fork` 本身仍可能使主线程停顿。
- 父子进程初始共享页面。快照期间父进程修改已有数据会触发写时复制（COW），产生额外物理页；修改越多，内存峰值可能越高。
- `fork` 需要复制页表。数据量、写入速率、可用内存和透明大页（THP）都会影响停顿或 COW 开销，应监控快照耗时和内存峰值。

新快照生成成功后替换旧文件；生成失败时应检查日志和备份状态。

## AOF 追加日志

Redis 执行写命令后记录可用于重建状态的命令，按配置追加和同步到文件。先执行再记录避免记录未通过检查的命令，但执行与持久化之间仍有故障窗口，不提供无条件零丢失。

| `appendfsync` | 行为与代价 |
| --- | --- |
| `always` | 每次写入后同步，丢失窗口较小但 I/O 延迟较高 |
| `everysec` | 通常每秒异步同步一次，故障时可能丢失约一秒数据，实际窗口受系统状态影响 |
| `no` | 交由操作系统决定刷盘时间，吞吐较好但丢失窗口不可控 |

写入路径：执行命令 → 追加到 AOF 缓冲区 → 写入内核缓冲区 → 按策略调用 `fsync`。

`write` 成功不等于数据已落盘；`fsync` 的最终保证也依赖操作系统和存储设备。`everysec` 的约一秒是常见丢失窗口，并非任意环境下的固定上限；后台同步或磁盘繁忙也可能增加尾延迟。

### 重写过程与失败边界

AOF 重写根据当前数据库状态生成更紧凑的重建记录，不是逐条压缩旧 AOF。例如，同一计数器多次递增可由当前最终值重建。`BGREWRITEAOF` 手动触发；自动重写受 `auto-aof-rewrite-min-size` 和 `auto-aof-rewrite-percentage` 等配置控制。

| 版本 | 重写期间的增量与切换 |
| --- | --- |
| Redis 7 之前 | 子进程生成新文件，父进程继续服务并记录期间增量；完成后合并增量，再切换文件。 |
| Redis 7 的多文件 AOF | manifest 管理 base、incremental 等文件；重写期间增量写入独立文件，成功后切换文件集合。 |

两种方式都要保留重写期间的写入；具体流程依版本而定。原文将多文件设计的背景归于[阿里开发者对 Redis 7 的介绍](https://mp.weixin.qq.com/s/RnoPPL7jiFSKkx3G4p57Pg)。

重写依赖 fork、COW 和磁盘空间，fork 失败、磁盘或 inode 耗尽、重写异常中断都需要告警和恢复处理。结合 `INFO persistence` 中重写进度、成功状态、文件大小、`aof_delayed_fsync`，以及 `df -h`、`df -i` 和系统磁盘延迟排查；具体字段和含义以运行版本为准。

## 完整性与混合持久化

- 纯 AOF 是命令日志，不应认为每条命令都有校验和。`aof-load-truncated` 控制符合条件的尾部截断是否允许继续启动；文件中间损坏不能简单按尾部截断处理。
- `redis-check-aof` 修复可能截掉错误位置之后的数据。先备份原文件，确认版本和文件集合，再离线检查并验证恢复。
- Redis 4 起，AOF 重写可使用 RDB 格式前缀，恢复时先加载快照，再重放增量命令；`aof-use-rdb-preamble` 的默认值需核对版本。
- RDB 段的 CRC64 检查受 `rdbchecksum` 等配置影响，不代表增量 AOF 的每条命令都有校验和。Redis 7 多文件 AOF 需保留 manifest、base 与所需增量文件。

## 选择和验证

RDB 更适合周期性快照和备份，AOF 可按刷盘策略缩小丢失窗口；同时开启时恢复优先级和配置以具体版本为准。持久化不替代异地备份、复制或恢复演练；监控 fork 时长、COW 内存、AOF 大小、重写状态、磁盘空间与延迟，并定期在隔离环境验证恢复。
