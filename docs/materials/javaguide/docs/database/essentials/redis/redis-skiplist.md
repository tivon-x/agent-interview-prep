# Redis 跳表与有序集合

根据 [JavaGuide 原文](https://github.com/Snailclimb/JavaGuide/blob/992dae31eade2a34ba8dbbbcf5ed9de5511325ec/docs/database/redis/redis-skiplist.md)整理，快照版本 `992dae31eade2a34ba8dbbbcf5ed9de5511325ec`。

## 结构和查找

跳表是多层有序链表。底层包含全部节点，上层只保留部分节点作为索引；查询从最高层开始，沿当前层向前直到不能继续，再下降一层，最终在底层定位目标。节点高度按随机策略决定，期望查找、插入和删除为 `O(log n)`；极端情况下可能退化为线性。

插入时沿查询路径记录各层前驱，随机生成新节点高度，再逐层调整前后链接；删除时同样定位目标和各层前驱后解除链接。层越高节点越少，索引占额外空间；实现还需处理边界、重复值、层高增长及空层收缩。

例如底层为 `1 → 3 → 5 → 7 → 9`，上层为 `1 → 5 → 9`：查找 7 时在上层走到 5，因下一项 9 已超过目标而下降，再在底层走到 7。查找 6 时下降后停在 5，下一项为 7，说明不存在。上层跨度越大，越能跳过底层连续节点，但节点分布由随机高度决定。

```text
node = head
for level from highest down to 0:
    while node.next[level] exists and node.next[level].key < target:
        node = node.next[level]
candidate = node.next[0]
return candidate if candidate exists and candidate.key == target else not_found
```

插入要保留每层 `node` 作为前驱；如果按集合语义要求成员唯一，应先处理已存在成员，而不是插入多个相同成员。删除目标不存在时不应修改链表；最高层最后一个节点删除后可降低有效层高。随机化简化平衡维护，但不能承诺每次操作都有严格对数上界。

## Redis Sorted Set

有序集合按 score 排序，score 相同则比较成员；成员定位与按范围、排名遍历是不同需求。数据规模较大时，Redis 通常结合字典和跳表；字典辅助按成员获取分数，跳表提供有序遍历和区间查询，节点跨度等信息可支持排名计算。小集合可能采用紧凑编码，具体取决于版本、大小和配置。

范围查询先定位起点，再沿底层顺序输出匹配节点，开销与结果数量有关；按排名查找依赖记录跨越节点数的跨度，不能只依靠普通单向链表。更新已有成员分数时，需要维护排序位置与成员索引的一致性。相同分数并不表示成员相同，例如 `(100, alice)` 与 `(100, bob)` 可同时存在，顺序再按成员比较。

## 与树结构比较

平衡树和红黑树也可实现对数级有序操作；B+ 树擅长按页组织并支持范围访问，常用于磁盘索引。跳表的随机层级与顺序链表使插入和范围遍历相对直观，但需额外指针，也有随机性；不同实现和场景下性能不同，不能把它概括成普遍优于树结构。Redis 选择结合自身排序、范围查询、实现和维护等因素。
